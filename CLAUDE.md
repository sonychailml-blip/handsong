# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**The app ships as «Handsong»** (renamed from Air Synth 3; the repo folder is still `air-synth-3` and the old name survives only in doc titles). It is a gesture-controlled synthesizer and interactive scales/tunings tutorial that runs entirely in the browser. It uses the webcam + MediaPipe hand tracking to play notes/chords/bass/drums/effects with pinch gestures, synthesizing all sound with the Web Audio API. On top of live play it has a **linear multitrack recorder** (records intent as events in ABSOLUTE song beats onto tracks; a take either creates a track or merges into an armed one; undo removes the last take; an optional bar-quantised repeat brace brings looping back as a marked span — see "Time, tracks and the recorder"; it grew out of a looper, and many names still say `loop`), an **arrangement** system (harmony/rhythm/bass dropped in as frozen tracks), a **track editor** (a full-screen piano roll over the recorded song, with its own undo/redo and an automation lane for the effects), an **expression hand** (a hand that plays no notes and instead breathes into the sound), a **looper hand** (commands by finger), and a **six-lesson interactive tutorial** that runs inside the live app. **Code comments and the musical data names stay Russian; user-facing UI strings are English-first with Russian alongside** — see "Language" and "Localisation".

**The app is split into ES modules under `src/`, loaded via `<script type="module" src="src/main.js">`.** There is no build system, no package.json, no dependencies to install, and no tests — the modules load directly in the browser. `index.html` holds only markup; `style.css` holds all CSS; the only external dependency is `@mediapipe/tasks-vision`, loaded from a CDN via an ES module `import` in `vision.js`. At the repo root there are also **`manifest.json`** and **`sw.js`** — the PWA install pair (see "Publication & PWA").

**One control model (PC mode is gone).** The screen is a single vertical layout: **one role fills the whole screen** (`phoneInstr`, cycled by the role button). In **landscape** an optional **split** (`splitOn`) puts **two roles side by side** — the screen halves, each half is one instrument. **Role is decided by ZONE** (which half a hand pinches in — either hand plays whichever half it lands in), and **work inside a half is by POSITION** (the chord palette is position-only). **There is NO hand-keyed exception left anywhere**: `handRole` is deleted, and "effects on the left hand in the solo half" is now *derived* from the default `handFn.ld.L='fx'` (hard rule #18). There is no more `uiMode`, no `pc`/`phone` toggle, no `drawPC` — the old three-column PC layout and everything unique to it were deleted; the split covers PC's one real capability (two roles at once) and does strictly more.

The source of truth for pitch.
- `src/audio.js` — the Web Audio engine (see "Audio engine" — **three synthesis paths**: subtractive, FM `buildFMBank`, Karplus–Strong `buildKSBank`). Lead banks are built in `buildLeadBanks(preBus, ksOk)`; the KS tail (`KS_BANKS`, indices 16..22) needs the worklet, and if `addModule` failed `buildKSFallback` fills those slots with subtractive plucks so `banks[]` never desyncs from `LEAD_INSTR`. Drum kits (`DRUM_KITS`: Стандарт/Дарбука/Табла/Гамелан/Тайко) are per-hit synths (gamelan = inline FM `gmlFM`), same 6 rows/indices. `metroClick(t,level)` takes a 4-value accent level (2 bar-head / 1 group-head / 0 beat / −1 khali). The **chord pool voices carry TWO lowpass filters, not one** (`buildChordPool`: `o1/o2 → f → fb → g`): `f` bakes the ATTACK envelope (timbre, once at attack, never touched per-frame); `fb` carries the CONTINUOUS brightness (hand-depth expression, `setTargetAtTime` all note) via `briToHz(bri)` — see "Chord brightness". `chordOn(owner,freqs,vol,ins,bri,when)` / `chordGlide(owner,freqs,vol,bri,when)` / `chordOff(owner,when)` — `bri` before `when` (scheduler keeps `when` last); per-layer isolation is by owner key (`'latch'` live vs `'loop:'+layer`), each owning its own pool voices → its own `fb`. **Expression nodes** (`exprVibPitch`, `exprVibAmp`, `exprWah`, `exprSatSoftG`, `exprSatHardG`, `exprDlyWet`) + the sound-side numbers **`EXPR_A`** (channel→depth/range) and **`applyExpr(en,ten,spr,ori,eng,tc)`** — all four axes go in via `setTargetAtTime`, never direct assignment, and every node is **identity at neutral** (gain 0/1, the wah peaking filter at 0 dB is flat) so with no expression hand the solo chain is bit-for-bit as before. `EXPR_A` lives in audio and `EXPR_CFG` in gestures because **gestures imports audio — the reverse import would be a cycle**. **Reverb** = **`buildFDN`** + **`REV_A`** + `setRevDecay`/`setRevTone` (a 4-line feedback delay network with 3 input allpass diffusers, an in-loop damping lowpass at **Butterworth Q**, Householder mixing and stereo taps — it replaced `makeIR`+`ConvolverNode`, which are gone; see "Audio engine" for the topology and the Q-in-dB trap), wrapped by **`makeReverbFx`**. Effects are **modules registered in `FX_FACTORY` — four today:** `reverb` (`kind:'bus'`), `bright` (chord brightness, `kind:'voice'` — no nodes at all, the voice reads the value at attack), `dly` (`kind:'bus'`) and `trmMix` (the bus tremolo, `kind:'insert'`). Instances belong to a **chain-owner key**, not to a role name, are built lazily and never torn down (`FX_INST[key][fxId]` via `fxInstance`). **The chain is SERIAL** (slice O-1): `fxChainIO(key, head)` registers the two ends of ONE segment for each of the four owners (`leadOut`, `chordBus`, `bassBus`, `drumBus`), and `fxResplice`/`fxRespliceSmooth` rebuild the whole path `head → fx₁ → fx₂ → … → tail → master` in CHAIN ORDER, touching only connections (hard rule #3 holds — nothing is torn down). ⛔ **`fxAttach`, `fxRoleBus`, `fxRoleOut` and the three attachment kinds are GONE** — a signal module now carries its own dry/wet inside (`fxIn → dry(×1) → fxOut` plus `fxIn → send(mix) → gate → network → fxOut`), which is what makes order audible and `mix=0` identity sample-for-sample. `kind` survives only to answer "does it have ends at all" (`voice` = no nodes) and for the insert's own on/off. Capture, playback and aim live here too — `fxCaptureChain`/`fxCaptureWalk`, `fxPlayPath`/`fxPlaySet`/`fxGate`/`fxRestoreAim`, `FX_AIM`+`fxAimSet`/`fxAimGet`, `fxParamKeysOf`/`fxParamMetaOf`/`fxDefaultsOf`/`fxAddableIds`, and `EXPR_FX`/`EXPR_CH`/`exprCur` (the expression hand's five output scalars, snapshotted by `applyExpr` for capture) — see "Effect ownership, capture and playback". `verb`/`verbOut`/`revLead`/`revCh` are DELETED (tombstone comments only). What remains in `state.fx` — drive, vibrato, per-voice tremolo — is solo-only, per-voice and NOT a module (the planned "second floor"). Also **`createRecordingTap()`** — a parallel `MediaStreamDestination` off `limiter` (records exactly what's heard, live output untouched; `dispose()` removes the edge), consumed by `clip.js`.
- `src/ks-worklet.js` — the Karplus–Strong `AudioWorkletProcessor` (`registerProcessor('ks-string')`), loaded by `initAudio` via `addModule` **inside** the start click. A worklet is **mandatory, not a choice** (see "Audio engine"): a native `DelayNode` feedback loop is floored at one render quantum (128 samples ≈ 344 Hz) so higher notes are unreachable, and sample-quantised delay detunes the rest — disqualifying for a microtonal instrument. The delay line is a `Float32Array` read with a **first-order allpass fractional delay** plus loop-filter phase compensation → tuning error under 1 cent across the whole range. `freq`/`pluck` are a-rate params (continuous glissando, sample-accurate pluck edge).
- `src/arrange.js` — arrangement data + pure generation (`PROGRESSIONS`, `HARMONIES`, `RHYTHMS`, `BASS_MODES`, `buildArrangement`). No side effects. **Beat subdivision:** each `RHYTHMS` entry declares `beats` **and optionally `sub`** (cells per beat — 4 = sixteenths, the default; **3 = triplets**); `subOf(r)=r.sub||4`, `stepBeat=1/sub` is the SINGLE source of the cell step (was `beats/grid.length`). `gridOk(r)` asserts `grid.length===beats*sub` — a data typo would otherwise silently warp the bar; `rhythmFits(r,metre)` (size + grid check) and `rhythmsForMetre(metre)` are the ONE fitness expression, shared by generation, the panel's rhythm filter, the jam's `fitRhythm` and the drums-only cycle. **18 patterns**: the 8 original (untouched, no `sub` ⇒ 4 ⇒ identical times) + ten 4/4 staples (Рок с подхватом · Поп · Фанк · Диско · Хип-хоп · Босса-нова · Самба · Регги (уан-дроп) · Марш · **Шаффл**, the only `sub:3` one). Patterns are written in **rows, not sounds** (0 kick/1 snare/2 clap/3 hat; row 5 crash deliberately unused) so they play on any kit. `buildArrangement` also takes a **drums-only** selection (`sel.prog<0`): no harmony, no bass, `bars` from `ctx.bars` (= `loop.bars`, which now means the BACKING length). The "size check can't reject it" argument in arrange.js's own comment is stale: `loadArrangement` no longer has a length check at all. Every arrangement layer lies from beat 0 of the song.
- `src/recorder.js` — the **linear multitrack recorder** (it grew out of the looper; many names still say `loop`): `events[]` (a **stable array reference** — `draw` imports it, so it is truncated in place, never replaced), the transport state `loop`, the `W*`/`ENG` indirection, the look-ahead scheduler, tracks (lanes), the repeat brace, the chase, take-based undo, the stops, `softAllOff`, `loadArrangement`. **Time is ABSOLUTE song beats** (slice S3.3): an event's `t` counts beats from the start of the song and is never folded at record time; playback runs from a position to the end of the material and STOPS (`stopAtEnd`); song length is DERIVED (`songBeats()`, a cached `songLen` grown by `push` and recomputed only in `schedInvalidate`). **`loop.bars` now means the BACKING length** — how many bars a newly added arrangement or drums-only backing occupies (1..8, any time) — not a loop length. **`loop` fields:** `on, bars, metre, sub, bpm, t0, pos, sched, layer, clickBeat, quant, rgn:{on,from,to,user}, lead, cnt`; which of them are CLOCK beats and which are SONG beats is set out in "Time, tracks and the recorder". **Metre:** `loop.metre` (seeded by `config.BEATS_PER_BAR`, `setLoopMetre`, clamped to `METRES=[2,3,4,5,6,7,8,9,10,12,16]`) changes **only while the song is empty and the transport stopped**; **no denominator by design** (the engine counts beats at BPM, so 7/8 vs 7/4 = tempo only — honest for talas/Balkan). `METRE_GROUPS` + `METRE_KHALI` drive `beatLevel(metre,b)` → the 4-value metronome accent AND the strip's tick grid; khali is a **weakened** head, not silence. **Live quantise** (`gridFor`): chords 1 beat, bass ½, drums `1/loop.sub` (`setLoopSub`, `SUBS=[4,3]` — an explicit recording setting, changeable any time), solo never. **Chord brightness records** as `a.bri` beside `a.ty` (`recChOn`/`recChSet`; a `|Δbri|>REC_REV_EPS` change alone pushes a `chSet`). **`loadArrangement` passes `drumKitIdx` explicitly** (otherwise every arrangement's drums played the Standard kit), lays every layer from beat 0, and gives each layer its own take number. **Jam:** `loadJam=sel=>loadArrangement(sel,true)` stamps **`ev.jam=true`**; `clearJam()` removes exactly the flagged events. Lanes, arming, delete, undo, the three stops, the seams, the chase and the owner keys are all in "Time, tracks and the recorder". **The per-take effect CAPTURE lives here too** and is deliberately NOT part of `events`: `takeFx` (a `Map` keyed by take number), `takeFxVer`+`takeFxTouch` (its one named staleness point — ⛔ not `schedInvalidate`, hard rule #28 is about events), `takeCapStart`/`takeCapSample`/`takePrune`/`takeReset`, the reserved composition id `FX_CHAIN='#chain'`; the playback side `fxPlayBuild`/`fxPlayDrive`/`fxPlayStop`/`fxPlaySignature`/`fxIsDriven` and the owner resolver `evRole`; and the editor's API over both — `songNotes`/`songSegs`, `editOpen`/`editClose`/`editGuard`/`editPush`/`editUndo`/`editRedo`, `editMoveHit`/`editDeleteHit`/`editInsertHit`/`editMoveSeg`/`editDeleteSeg`/`editResizeSeg`, and the automation lane's `autTakesOf`/`autAddrs`/`autPoints`/`autMovePoint`/`autDeletePoint`/`autAddPoint`/`autChainOf`/`autChainAdd`/`autChainRemove`/`autChainMove`.
- `src/vision.js` — camera + MediaPipe (CDN import, `video`/`canvas`/`ctx`, `roundRect` polyfill, `resize`, `landmarker`, `initVision`). **Camera switching:** `openCamera(facing)` (stops old tracks first, then `getUserMedia({facingMode})` onto the SAME `<video>`) and `switchCamera(facing)` — the landmarker is **never recreated**; on failure the caller (ui) rolls back and toasts.
- `src/clip.js` — **clip/audio recorder** (one engine, two kinds): `startClip('video'|'audio')`/`stopClip`, `activeKind()`, `onClipChange(fn)`. Video = `canvas.captureStream(30)` video track + the audio tap combined into ONE `MediaStream` → one WebM with picture+sound (HTML chrome is a separate DOM layer, excluded from the canvas capture); audio = the tap only. `recKind` is the single source of truth; `fireChange` notifies ui after every real transition (start / real `onstop` / error / external track-end) so the buttons can't stick. Sets `videoRec` only for video, only once recording truly starts.
- `src/demo.js` — the start-screen "путешествие по строям" demo (six tunings, no camera; own mini-voices, self-contained). Side-effect module; wires the (now removed-from-UI) demo button defensively (`if(db)`). **Scenes reference scales by STABLE INDEX (`SCENES[].idx` into `SCALES`), never by name** — it used to `find` by `s.name`, which localisation would have broken silently (see "Localisation").
- `src/tutor.js` — the interactive tutorial: the lesson list overlay + the step engine. ## Architecture

The render loop lives in `main.js`. Each frame: draw the video → MediaPipe detects hands → `processHands()` updates the gesture state machine and drives audio → `drawOverlays()` renders. The recorder thins the ~60/sec engine calls into a few intent events per note.

### Screen model — one layout, optional split
- **Single role (default):** one role fills the screen (`phoneInstr` = `'ld'/'ch'/'bs'/'dr'`, cycled by the role button `instrBtn`). What each hand does in a **solo/bass** role comes from the **hand-function table `handFn`** (see "Hand functions"): the default `ld:{L:'fx',R:'note'}` reproduces the old "left=effects, right=notes" without a `swapHands` flag. The chord-type palette is **position-only** here too (same gate as split) — no hand is bound to it.
- **Split (`splitOn`, landscape only):** the screen halves — **left half = `SPLIT_ROLES[0]`, right half = `SPLIT_ROLES[1]`** (each cycled by its own button, `instrBtnL`/`instrBtnR`). **ZONE = INSTRUMENT:** either hand plays whichever half it pinched in. Inside a half everything is by **POSITION** — the chord palette is position-only (thumb+index left of the half's `palSplitX`). **Hand functions apply PER HALF, keyed by that half's role** (`handFnOf(key, h.role)`) — a `ld`/`bs` half behaves exactly like single-role (effects/hold/theremin all available); a `ch`/`dr` half ignores `handFn`. There is **no hardcoded "effects on the left hand in the solo half" special case anymore** — the default `handFn.ld.L='fx'` *derives* it (see hard rule). Each half has its **own** octave/register rectangle writing ITS role's register (`setRectOctReg(S.role,…)`).
- **Frozen at capture:** at pinch the hand's role + X-range are frozen onto `S` (`S.role`/`S.rx0`/`S.rx1`) from the half `px` lands in; play and draw then read that frozen range, so hit-test and render never drift. **Single-source geometry:** halves from `phoneHalves(W)`, the internal palette split from `palSplitX(rx0,rx1)`, bands from `rectBandY`/`rectRows` — each computed **once** and shared by gestures and draw.
- **Skip-in-cycle invariant:** `cycleHalf` never sets a half to the role the other half holds, so the pair is **always two different roles** → duplicate halves are impossible and the mono-voice chains (**solo and bass are single-voice**) can never appear twice. Two solo (or two bass) halves would fight over one voice; the invariant makes that unreachable by construction.
- **Landscape gate:** `canSplit()=innerWidth>innerHeight`. `splitBtn` shows only in landscape; rotating to portrait with split on **auto-disables** it (`softAllOff`, nothing left ringing) and does not auto-re-enable.

### Gesture model
- **Pinch** = thumb (4) near a fingertip (8/12/16/20), normalized by hand size. The pinched finger (`S.oct`) selects the **octave register** (index=I … pinky=IV), switchable mid-pinch to glide — **except in the rect model** (below), where it selects the note-in-rectangle and the octave comes from the octave rectangle.
- **Multi-finger pinch (SOLO only):** several fingers may touch the thumb at once and **each sounds its own note** — up to four per hand, eight across two, i.e. chords built by the fingers. `touchedFingers()` returns the whole set with the *same* `PINCH_ON`/`PINCH_OFF` hysteresis one finger always had; `S.order` keeps the order of engagement so the **first-pressed finger stays primary** (position, zone, volume and the Z-reverb are read from it — a hand has one position, and all its notes live in one rectangle). Per-finger: `S.fing[f] = {deg,oct,slot}` and one pool voice each, via the finger-aware owner key. The ceiling is **`state.pinchFingers`** (1..4, panel «Пальцев в руке»); **`1` restores today exactly**, including the mid-pinch nearest-finger switch. ⚠️ At ceiling 1 (and for the theremin) the owner key carries **no finger number** — otherwise the mid-pinch switch would become note-off + note-on instead of the 20 ms glide it has always been. **Bass, chords and drums stay single-finger** (bass is deliberately still mono). **Theremin is one note per hand by design:** pitch there comes from the hand's *vertical position* and the finger selects nothing, so extra fingers would only produce unisons — inventing an offset per finger would be invention, not an instrument. **Hold works per finger** for free: each finger's record freezes on its own first frame and stops when *its* fingers part.
- **The ceiling is settled at 4, and the temporary pinch diagnostic is GONE.** `pinchFingers` defaults to **4** — the intent is that closing all four fingers on each thumb sounds all eight notes. The temporary measuring tool that decided it — an on-canvas readout of every finger's live pinch ratio against the ON/OFF thresholds, plus its panel row and dictionary key — has been **deleted** as this file required; don't reintroduce it. The caution lives in the *control* instead: fingers occlude each other and MediaPipe partly *infers* the far ones, so if the ring or little finger fires falsely, lower the ceiling in «Пальцев в руке».
- **Y** = scale degree (`degHyst`); **X** = volume, mapped over the hand's frozen range — `[palSplitX(rx0,rx1), rx1]` in a typed-chord role, else `[rx0, rx1]` (a role whose chain uses the `play:x` address freezes its volume at the menu value instead); **Z** = the playing hand's depth (`dist(lm[0],lm[9])`, calibrated by `config.REV_NEAR`/`REV_RANGE` — the names are historical) — an **address** (`play:z`) that any chain parameter can subscribe to; by default the chord chain's brightness listens to it. The reverb no longer follows the playing hand (effects Plast 3.1).

### Camera frame margin — COVER fit + two coordinate roles (RAW vs REMAPPED)
The camera frame has its own aspect (usually 4:3); the canvas has the window's. Painting one onto the other without matching aspects **stretched** the picture (horizontally on a wide desktop). **`config.coverView(vw,vh,W,H)` fixes it:** it returns the centered sub-rectangle of the frame `{ax0,ax1,ay0,ay1}` whose **pixel aspect equals the canvas** (COVER — fills, no bars, crops the overflow, no distortion), then insets it by `CAM_MARGIN` on both axes. `drawVideoBackground` computes it **once per frame**, uses it as the `drawImage` source rect, AND writes it to `state.viewRect` — so the SAME sub-rectangle drives the picture and the coordinate remap. If the two diverged the drawn hand would sit where the finger is not. We still **display and play only the inner region**, while MediaPipe keeps receiving the **FULL** frame (`detectForVideo(video)` is never cropped) — a hand at the outermost rectangles travels off the visible edge while the camera still sees it. `remapAxis(v)=(v-M)/(1-2M)` stays exported as the **aspect-equal special case** (the default `viewRect` before video is ready is exactly `[M,1-M]²`, so pre-video `sx`/`sy` are byte-for-byte the old formula). **Two coordinate roles are kept strictly separate (hard rule):**
- **RAW full-frame coords** (untouched `lm.x`/`lm.y`, 0..1) drive **all gesture math** — pinch distance (`pinchRatios`), hand size (`dist(lm[0],lm[9])`), the Z-reverb depth, the FX vertical drag, every threshold — so a pinch still registers when the hand is partly off-screen.
- **REMAPPED coords** — `sx(nx,W)`/`sy(ny,H)` (state.js, single source for gestures hit-test AND draw) remap `flipX(nx)`/`ny` through `viewRect`'s per-axis ranges — drive **only** on-screen position and hit-testing (which half/rectangle/zone, the volume X, the drawn hand). `viewRect` is symmetric in X about 0.5 so it commutes with `flipX`.
- **Coordinates and rendering are never clamped** — a hand in the margin runs off the visible edge (that's the point). Only the resulting **selection** saturates (there is no rectangle beyond the outermost; a margin pinch's half is clamped to the nearest edge so it can't fall into the wrong half). The video crop and the remap read the same `viewRect`, so picture and hand stay aligned.
- **Margin outcome (cover eats into the safety margin — measured, not raised):** the inset is applied on top of cover, so the canvas's **long axis keeps a full `CAM_MARGIN` (~12%)** and the cover-cropped axis gains **more** (e.g. wide 16:9 desktop with a 4:3 sensor: ~12% X, ~21% Y). No axis drops below 12%, so `CAM_MARGIN` was NOT raised. The real cost is on a **portrait phone with a landscape sensor**, where cover shows only the central vertical strip of the frame (inherent to cover — the alternative is letterbox bars).

### Camera switching & mirroring
`camFacing` + `mirrored()` + `flipX` (state.js) are the **single source** of "do we mirror". Front camera (`'user'`) is mirrored (you see yourself as in a mirror); back camera (`'environment'`) is not. Both the video draw (`drawVideoBackground`) and every landmark→screen conversion read `flipX`/`sx`, so picture and hit-test flip together. `🔄` re-acquires the stream on the SAME `<video>` (landmarker not recreated); a failure rolls back to the previous camera and shows a Russian toast.

### Which hand is the solo note hand (formerly "Reverb aim under split")
The reverb preview `revDisp` is **DELETED** — the reverb left the playing hand in effects Plast 3.1, and there is nothing to aim before a pinch any more. What survives is the rule for WHICH hand counts as the solo note hand: `soloNoteHand(key,S,W)` (gestures) decides whose depth drives solo-chain parameters subscribed to `play:z`. Single-role: `phoneInstr==='ld'`. Split: the hand's frozen `S.role` when pinched, else the live half under `lm[8]` via `phoneHalves`. With no note hand in frame nothing is written — the parameter holds its last value, because this is sound, not a display, and a snap to zero would be heard.

### Rect model — "4 notes per rectangle" (SOLO, BASS, CHORDS; now a SWITCHABLE layout, not a scale property)
The note grid is either N narrow rows or **fat rectangles**: `rects` note rectangles + a register rectangle **only where one is needed** = `bands` in total. Band pixel geometry is single-sourced in `rectBandY` (config) and **every count in `rectLayout` (scales)**; gestures' hit-test (`degHyst` on `bands`) and draw partition H the same way, so finger and screen never drift. **Y selects the rectangle** (band); the pinched **finger = 1 of `k` notes/roots** inside it (slot `g = rect*k + finger`, then `rectNoteAt(g,base)`), and where several periods are on screen the band also carries the octave.

**The layout is STATE the person switches** (`state.rectPref`: `'auto' | 'rect' | 'rows'`, default `'auto'`), and the scale's `rectGrid` property is now only its **DEFAULT** ("what the scale opens as"). One resolver decides, `scales.rectGrid(s) = rectEligible(s) && (rectPref==='auto' ? !!s.rectGrid : rectPref==='rect')` — eligibility is folded in, so a data typo can no longer produce a fractional grid. `'auto'` **must stay the default**: a plain boolean seeded from the first scale would carry Partch's rectangles onto major at the next scale change.

**The arithmetic — ONE function, `rectLayout(s)`** (memoised on the scale reference). Two things are variable, not fixed:
- **`k` = notes per rectangle**, the first of `[4,3,2]` that divides; within each `k`, `dup=0` is tried before `dup=1`. Fingers beyond `k` are **idle** — they play nothing (never a substitute note) and are drawn as a dim `—` line.
- **`dup` = 0|1**, whether the tonic is **repeated at the period boundary**. Its purpose is **alignment**, not equivalence: with `dup=1` a period occupies a whole number of rectangles, so the hand always knows where it is. ⚠️ **The old `periodOf===2` gate on `dup` is deliberately GONE** — without it Bohlen–Pierce (13, prime) and Carlos beta (11, prime) could not be laid out at all. `periodOf`'s pitch meaning is untouched. Honest caveat recorded in the code: the duplicated slot is labelled `Т`, which is **true for BP** (the tritave is its equivalence) and an **overstatement for Carlos** (her fifth is a generator, no equivalence exists); accepted for now, an `equiv:false` property later if it grates.

Derived, all from the one object: `block=iv.length+dup`, `perOct=block/k`, **`octaves=clamp(floor(RECT_MAX/perOct),1,REG_N)`**, `rects=perOct*octaves`, **`hasReg=octaves<REG_N`**, `regBands=hasReg?1:0`, `bands`, `notes=rects*k`. **`REG_N=OCT_ROMAN.length`** is not an arbitrary 4 — it is the register count, which is *why* a grid showing all `REG_N` periods loses no pitch. `RECT_MAX=12`. Wrappers keep the old names (`rectRows`→`rects` — **meaning changed: all octaves, not one**; `rectRowsFull`→`bands`; `rectNotes`→`notes`).

**Every scale is now eligible** (even counts divide at `k=2`; odd ones at `k=2,dup=1`), so `rectEligible` can never fail and the panel's "unavailable, because…" branch and its two dictionary keys were **removed** — a dead explanation is worse than none. The predicate survives only as the resolver's guard.

**Slot ↔ note, the two inverse formulas** (nothing may re-derive them): `rectNoteAt(g,base)` → `{deg: g%block, oct: base+floor(g/block)}` where `g = rect*k + finger`, and `rectSlotOf(deg,oct,base)` → `g` (or `-1` outside the window) for the **highlight**. Ranges out are exactly today's — `deg ∈ [0,iv.length]`, `oct ∈ [0,REG_N-1]` — so **the event format is untouched and old loops replay identically**. For a 4-octave scale the pitch set is precisely the one narrow rows already offer (4 registers × the octave), only rearranged.

**Octave/register rectangle** (band 0, bottom) — **exists only when `hasReg`**, i.e. when the grid does *not* already show all `REG_N` registers. That single predicate is the one place the band is decided (gestures' `'oct'` capture, draw's band offset via `regBands`, and `thereminSpan` all read it). Where it exists it now shifts a **window of `octaves` periods**, not one octave: the base is clamped by `rectBase()` (same clamp on read and on write) and `drawRectOctBand` lists `rectBaseMax()+1` selectable bases (4 at one octave — as today; 3 at two, labelled «окт II–III»), the rest dim. Pinching it is by **position**, any hand (`'oct'` zone, overrides role; in chords kept right of the palette **only when `typedChords`**). The `'oct'` hand is silent. ⚠️ Bands are **equal**, and that cost is accepted deliberately: do not special-case band heights, it would move Partch and 19/31-TET.

**Chords**: rect applies to the ROOT grid — right of the palette `[palSplitX,rx1]` for a `typedChords` scale, the **full role range** otherwise. The type still rides the sticky palette; latch logic unchanged; only the root degree + octave source changed.

⚠️ **The rect chord branch must NEVER live inside the `chTyped` branch of `drawRole` again** (see hard rule #26): `gestures` decides rect by ROLE, so a non-typed chord scale in rectangles would take input by rectangle and draw narrow rows. It was invisible for as long as every rect scale was either `typedChords` or `noChords`.

- **The rectangle's finger legend runs LOW AT THE BOTTOM, high at the top** — the same direction as the grid around it. It used to list top-to-bottom, so pitch rose *downwards* inside a block while rising *upwards* everywhere else. ⚠️ **Visual only:** the row is drawn at `(NF-1-n)`, while finger `n` still takes slot `rect*k + n` (index = the rectangle's first note, little finger = its last) and the highlight still looks up that same slot. Never "fix" the order by touching the mapping.
**Labels depend on the SCALE, not the layout** — one function, `draw.noteLbl` (see hard rule #26). Under rectangles a 7-note scale shows **real note names** per row, a raga shows swaras, Werckmeister shows names + its true cents, 19/31-TET keep ordinals. When `octaves>1` the legend drops the cents suffix (identical in every block, 48 slots of noise — the live tag still shows them) and gains a **per-band register marker** at the right edge. That marker is **load-bearing, not decoration**: four identical-looking blocks otherwise give no way to tell which octave you are aiming at. It is derived from `rectNoteAt`, the same formula that makes the sound, so it cannot lie.

Scales left in narrow rows keep the narrow-row model byte-for-byte, and an untouched app (`'auto'`) reproduces today on **every** scale. ⚠️ **19-TET and Carlos gamma deliberately changed** with the multi-octave step (2 octaves, 10+1 bands, the band now shifting a 2-octave window): the previous round's "all four legacy rect scales are byte-for-byte" guarantee now holds for **31-TET and Partch only** (plus the newly eligible 22-shruti and BP, which land single-octave and behave like them).

### Hand functions (replaced the theremin toggle + the swap-hands control)
Each hand is assigned a **function per role**, held in `state.handFn` (`{ld:{L,R}, bs:{L,R}, ch:{L,R}, dr:{L,R}}`, defaults `ld:{fx,note}`/`bs:{note,note}`/`ch:{latch,latch}`/`dr:{hit,hit}`). Solo/bass functions:
- **`'fx'` (Эффекты)** — the effects hand; **available on all four roles** (effects goal (б)). Its fingers drive the parameters of the role's effect CHAIN that are addressed to them (see HANDOFF «КОНСТРУКТОР ЭФФЕКТОВ» for the address model). A chain also sounds with no effects hand at all — fixed values, or the playing hand's `play:z`/`play:x` addresses. The effect bars (`drawFxBars`) draw the role's CHAIN at its right edge with **no gate on the hand** — an empty chain (bass and drums by default) simply draws nothing. The separate REV bar and the reverb-from-the-playing-hand path (`S.rev` → `payload.rev` → `revLead.gain`) are gone (effects Plast 3.1; `rev` left the payload in 3.7.2).
- **`'note'` (Ноты непрерывно)** — normal play: degree follows the hand while pinched.
- **`'hold'` (Ноты с удержанием)** — the note captured on the first pinch frame is **frozen** (`S.deg`/`S.oct`, and the finger→octave change is gated off) while the hand roams; **volume keeps following X** (swell); it stops only on finger-release. It records as an ordinary long note — no new event format.
- **`'therm'` (Терменвокс)** — continuous pitch, **solo AND bass**. `thereminSpan`/`thereminHz` (scales) map y→a fractional note position over the SAME partition draw uses, then interpolate **linear-in-cents** (`log2` of the neighbours' `leadFreq`); bass Hz = `thereminHz/4`. Drawn as an **additive centre-line overlay** (`drawThereminLines`) on top of the normal grid, shown only when a hand of that role is `'therm'` (`roleHasTherm`). Live-only: the continuous Hz rides the **named live-only option `live` of `ENG.leadOn`/`ENG.bassOn`** (`ENG.x(a, ctx, {when, live, own})`, passed only by `WleadOn`/`WbassOn`; never recorded); the recorder stores the nearest step, and for solo the glide as a cents curve `a.bend` relative to that step.

**Chord functions** (`ch` role — the chord role joined `handFn`; only two, no `fx`/`therm`):
- **`'latch'` (Аккорды (защёлка))** — today's default and behaviour: a pinch sets the chord, it keeps ringing after the fingers open; same-degree re-pinch turns it off, a different degree glides. **Jam and split depend on this** — a half or a hand must be able to leave a chord ringing while the other plays.
- **`'hold'` (Аккорды (с удержанием))** — the chord is frozen while the fingers stay together and **stops on release** (`endPinch` → `WchOff('latch')`), reusing the **same solo-hold mechanism** (`S.fn==='hold'` freezes root+octave; the type still rides the palette; volume swells with X).

**Drum functions** (`dr`, effects slice б.4 — the list was created from nothing): **`'hit'`** (default, both hands — a hit per pinch on the row under the hand), `'fx'`, `'loop'`. Drums are genuinely two-handed (rolls are played between the hands), so a hand given to effects or the looper costs half the drummer — unlike bass and chords, which are mono (see the comment on `ui.HANDFN_OPTS`).

**`'loop'` (Лупер (управление))** — available on **all four roles**: the hand plays nothing and drives the recorder (see "Looper hand").

**`'expr'` (Выразительность)** — **solo only** (first pass): the hand plays nothing and breathes into the sound (see "The expression hand").

Option lists live in `ui.HANDFN_OPTS` — `ld`: fx/note/hold/therm/**expr**/loop · `bs`: fx/note/hold/therm/loop · `ch`: fx/latch/hold/loop · `dr`: fx/hit/loop.

**UI:** the «Функции рук» section (`renderHandFn`) shows a select per hand for each role in play — options come from `HANDFN_OPTS`, rows group under the role heading `INSTR_LBL[role]` (🎸 Соло / 🎹 Аккорды / 🎚 Бас) over `Левая рука`/`Правая рука` rows, so a split with two roles makes clear the assignment is per **hand within a role**. `noteRolesInPlay()` picks the role(s) in play (single-role, or the unique split halves; since б.4 drums have an entry too — `ui.HAS_HANDFN` covers all four). A change fires `setHandFn`+`softAllOff`. Solo/bass/chords keep **separate** assignments (persisted across role switches). In split it's consulted **per half by the half's role**.

**Solo: no hand-over any more — every hand has its own voice.** `leadOwner` and the solo handback are **deleted**, not forgotten: they existed only because the voice was single, and with a pool they would actively misbehave (reassigning an owner key that now names a specific hand, handing one hand another hand's note). Both hands simply sound; releasing one stops only that one. **Bass is STILL MONO** and keeps `bassOwner` + the `otherPinched` handback (last-pinch-wins, the still-held hand resumes, no stuck note, watchdog included) — **do not refactor the two together** until bass gets the same pool.

### Typed chords — the palette
Scales with a `typedChords` property split the chord role: **left = a palette of chord types** (columns = families, rows = variants; counts from `chordFams()`/`types.length`, geometry in `palColX`/`palRowY`), **right = note rows**. The palette selects a cell by POSITION on a thumb+**index** pinch inside it (`S.oct===0 && S.x<palSplitX`); sticky, default first family/type. **Position-only in BOTH single-role and split** (one gate, one law): either hand picks a type by being left of the split with thumb+index, either hand plays roots on the right, and the SAME hand can do both in turn (the chord keeps sounding after the fingers open). The cost, accepted on both paths: a playing hand that pinches thumb+index left of the split picks a type instead of sounding a root — but no roots are drawn there (the grid lives in `[palSplitX,rx1]`) and volume there measured as the minimum, so nothing playable is lost. Play: Y=root, X=volume, and the octave — **on non-rect typed scales (chrom12, BP, Pythagorean, both Naturals, meantone)** the finger picks it, **on the rect typed scales (19-TET/31-TET/Partch)** the finger picks the root-in-rectangle and the octave comes from the octave rectangle (`chordOctReg`). `ty` is a live reference into `CHORD_FAM_SETS`; latch identity = (degree + type). Two-axis hysteresis `cellHyst`.

`typedChords` keys → sets in `CHORD_FAM_SETS` (**8 keys**):
- `'chrom12'`, `'edo19'`, `'edo31'` — **integer steps** in that scale's own edo (priced by the integer `chordSteps` fallback).
- `'partch'` — 11-limit **ratios** (4 columns × 6: О otonal / У utonal / Диез 7-11 / Станд.); priced by the pure-ratio cents branch.
- `'bp'` — Bohlen–Pierce 3.5.7-subgroup **ratios** (15 chords: 3:5:7 major / 5:7:9 minor / characteristic); priced by the **period branch**.
- `'pyth'`, `'nat'` — the same 24-type vocabulary as chrom12 but as **pure ratios** (Pythagorean 3-limit / Natural 5-limit); priced by the pure-ratio cents branch (root × ratio, so every chord is pure from its own root).
- `'natfix'` — the same 24 types as **integer semitone offsets**, but used by the **fixed-grid** scales (Natural-fixed, meantone) whose `gridChords:true` reads each note out of the frozen cents grid → some chords pure, others wolf.

### Behaviour properties (prefer these over `tag`/index checks)
- `noChords` → chord role builds nothing (`supportsChords()` false). Maqams; the **gamelan** cents-scales and **pelog patets** (monophonic by choice); the **Carlos** scales (stage 1). Partch/Pythagorean/Natural are **not** `noChords` — they have typed chords.
- `typedChords: '<key>'` → palette mode; keys a set in `CHORD_FAM_SETS`. Keys: `'chrom12'`, `'edo19'`, `'edo31'`, `'partch'`, `'bp'`, `'pyth'`, `'nat'`, `'natfix'`.
- `cents: [...]` → non-equal tuning; pitch from `2^(cents[i]/1200)` instead of the equal step (see "Music theory & pitch").
- `period: <n>` → **interval of equivalence ≠ octave** (BP `3` = tritave, Carlos `3/2` = fifth). `periodOf()=s.period||2`. Absent ⇒ `2` ⇒ every octave scale byte-for-byte. Drives register/step (`P^oct`, `P^(step/edo)`), the `centsOf` period (`pc=1200*log2(P)`), `regWord` and `noteLbl`. It no longer gates the rect grid's `dup` (see "Rect model"): layout alignment is not a claim about equivalence. **Never hardcode `2` on any pitch/label path** — use `periodOf`.
- `gridChords: true` → (cents scale only) typed chords read their notes **out of the fixed cents grid** by integer semitone offset (fixed-keyboard model), instead of pure ratios from the root. Selects the first `chordFreqs` branch. Today: Natural-fixed, meantone, and the three well temperaments. **Distinct from `fixedKey`** (chord CONSTRUCTION vs the tonic being a key) — memberships overlap but differ.
- `fixedKey: true` → the tonic is a KEY within a grid nailed to absolute C, not a multiplier (see "fixedKey"). The six historical fixed tunings. Drives the `fixedKey` branch of `leadFreq`/`bassFreq`/`chordFreqs`/`centsOf` and real-note-name row labels. **NOT** on mobile Natural or any world/EDO/BP/Carlos/Partch/raga/maqam scale.
- `rectGrid: true` → the scale **opens** in the rectangle layout. It is a **DEFAULT, not the layout** — the live answer is `scales.rectGrid()`, which resolves `state.rectPref`. The geometry (how many notes per rectangle, whether the tonic is duplicated, how many octaves fit, whether a register band exists) is **entirely** `rectLayout(s)`; every scale can be laid out. Never re-derive that arithmetic anywhere else.
- `supportsProgressions()` = 7 degrees. Note: a 7-note `noChords` scale (maqams, pelog) is still gated out of progressions because `refreshProgAvail` uses `supportsProgressions() && supportsChords()`. (Partch/12-note tunings/BP/Carlos aren't 7-note, so progressions stay gated regardless.)

### Music theory & pitch
`SCALES` is the source of truth: each has `edo`, `iv` (degrees in those steps), `tag`, `trad` (tradition/menu section), optional `grp` (submenu), optional behaviour properties. **75 scales (indices 0..74).**

**Menu sections — organised by SOUND, not mechanism (`TRADITIONS`, 6).** The reorg moved each entry's `trad`/`grp` **text only — the `SCALES` array order and every index are UNCHANGED** (so the tail index map below still holds; `scaleIdx`, `state`, `sameDegrees` all depend on it):
- **`common` «Привычное»** — ordinary 12-TET where a newcomer lands: diatonic (majors/minors), modes, ethnic, pentatonics/blues, **the symmetric scales (whole-tone / octatonics / Messiaen)**, exotics, world pentatonics, Japanese.
- **`mideast` «Ближний Восток»** — Arabic maqamat (24-TET), `grp:'Макамы'` (Turkish maqams later).
- **`india` «Индия»** — the 22-shruti grid + ragas (two groups: the grid, then the ragas that pick swaras out of it).
- **`easia` «Ява и Дальний Восток»** — Javanese gamelan (Слендро/Пелог + pelog patets) + Japanese and Far-Eastern pentatonics.
- **`europe` «Европа историческая»** — now its OWN top-level section (was a `grp` shelf inside the old Ладовая), flat and reading **chronologically**: Pythagorean → Natural (mobile) → Natural (fixed) → meantone → the three well temperaments (Веркмайстер III / Валлотти / Кирнбергер III). A temperament and a mode are different things, so they no longer share a bucket. All `fixedKey` except mobile Natural.
- **`exp` «Эксперименты»** — bounded by **TUNING, not mode**: the equal microtonal EDOs (19/31-TET), Partch, Bohlen–Pierce, Carlos α/β/γ. Whole-tone/octatonic/Messiaen are NOT here — they are ordinary 12-TET, so they stay in Привычное.

**Placement rule (for future scales):** a new scale goes to the section matching its **culture or sonic character**; never invent a generic "прочее" bucket.

**Indian tradition (`indian`):** a 22-shruti just-intonation grid (`cents:[0,90,112,182,204,…,1110]`, min step 22¢, the syntonic comma — same cents mechanism as gamelan/Partch, octave, no `period`) plus **10 ragas** that each pick 7 swaras out of that grid. All are `noChords` (Indian classical is melodic — a deliberate model choice, not a limitation). Labelling uses the `swaraNames`/`swaraFull` properties → `swaraLbl`: the full grid shows **«свара · имя-шрути»** (`SWARA_OF`+`SHRUTI_OF`, both keyed on real cents so they can't drift), ragas show swaras only (Са Ре Га Ма Па Дха Ни). The swara sits on the **LAST shruti of its group** (Sangita-Ratnakara: Са=Чхандовати, Па=Алапини), so the tonic reads «Са · Чхандовати», not «Са · Тивра»; the modern positional convention (Са=Тивра) is documented in the source as the rejected alternative. Honesty notes in the code: a raga is **more than a scale** (aroha/avaroha, vadi/samvadi, pakad, time-of-day — none modelled); Кафи and Мальхар share the same scale by design (they differ in movement, which we don't model).

**Tail index map:** 50 = Bohlen–Pierce · 51/52/53 = Carlos alpha/beta/gamma · 54/55/56 = Pelog patets Lima/Nem/Barang · 57 = Pythagorean · 58 = Natural (mobile/choir) · 59 = Natural (fixed/harpsichord) · 60 = quarter-comma meantone · 61 = 22-shruti grid · 62..71 = ragas (Бхайрав, Йаман, Кафи, Бхайрави, Тоди, Кхамадж, Асавари, Мальхар, Пурви, Мармари) · **72 = Веркмайстер III (1691) · 73 = Валлотти (1754) · 74 = Кирнбергер III (1779)** (the well temperaments — see "fixedKey"). **75 scales, 0..74.**

**Three ways to define pitch — equal steps, cents overlay, or non-octave period:**
- **Equal (default):** within-period ratio = `P^(iv[i]/edo)` where `P=periodOf(s)` (`2` unless `period` set). All EDO scales (12/19/24/31-TET) and the non-octave equal scales (BP `P=3`, Carlos `P=3/2`).
- **Cents overlay:** an optional `cents:[...]` array (`length === iv.length`) gives each degree's exact cents above the tonic — for **non-equal** tunings (gamelan, Partch, the historical temperaments). When present, `leadFreq`/`bassFreq`/`centsOf` use `2^(cents[i]/1200)` with the appended top = 1200¢. `edo`/`iv` stay as **nominal structure** (degree count, row layout, hysteresis). Cents scales are octave (`period` absent).
- **Non-octave period:** `period:<n>` replaces the hardcoded `2` in register (`P^oct`), equal step (`P^(step/edo)`), and the cents period (`pc=1200*log2(P)`). Register shifts by the period (BP tritave, Carlos fifth), not the octave. `period` and `cents` are mutually exclusive in practice (BP/Carlos are equal; the temperaments are cents+octave).

**Chord pricing — `chordFreqs` has four branches, checked in this exact gate order** (order decides which scale gets which — do not reorder):
1. **`s.cents && ty && s.gridChords`** → **fixed-grid**: `ty` is integer semitone offsets; each note = grid pitch `корень+off` read from `s.cents` (octave carry for off≥12). Natural-fixed, meantone. Produces the pure/wolf spread of a fixed keyboard.
2. **`s.cents && ty`** → **pure-ratio cents**: `ty` is ratios; note = `baseF()/2·2^(o)·2^(rootCents/1200)·ratio` — root from the cents overlay, each interval a pure ratio. Partch, Pythagorean, Natural-mobile. Every chord pure from its own root.
3. **`periodOf(s)!==2 && ty`** → **period-equal**: `ty` is ratios; root by `P^(iv/edo)` (period register `P^o`), note = root·ratio. Bohlen–Pierce.
4. **fallback** → `chordSteps()`: integer path. Typed `ty` adds its step array to the root; else 7-note diatonic/ethnic/maqam stack thirds, pentatonic/blues/chromatic power chords, pure-EDO (`tag:'edo'`) by interval ratios. chrom12/edo19/edo31 and every non-typed scale. **Byte-for-byte unchanged** — a scale reaches here only when the three gates above all fail.
- `CHORD_FAM_SETS` `iv` are **integer steps** for `chrom12`/`edo19`/`edo31`/`natfix`, and **plain-number ratios** for `partch`/`bp`/`pyth`/`nat`. Never give a step-set to a scale with a different `edo`, and never give a ratio-set to a non-cents/non-period scale.

### Reference pitch (`aRef`) — ONE source
`aRef` (A4 in Hz, default 440, adjustable 380–480 in the scale panel) lives in `state.js` beside the tonic. `scales.js` derives **both** `baseF()` (the mobile tonic pitch) **and** `cFix()` (the fixed-C anchor for `fixedKey` scales) from the single `a3()=aRef/2`. There must be **exactly one** reference — a second copy would move world scales to 415 while the historical fixed tunings stayed at 440, surfacing much later as a "detuned instrument". Changing `aRef` re-tunes everything live (solo/bass/chords via `baseF`, drone via `tonicFreq()`, theremin, and every loop layer on its next replay); the UI clamps and falls back to the last valid value on bad input.

### fixedKey — the tonic is a KEY, not a multiplier (historical fixed tunings)
Scales with the **`fixedKey`** property (the six: Пифагоров, Натуральный фиксированный, Мезотон, Веркмайстер, Валлотти, Кирнбергер) nail their grid to **absolute pitches anchored at C** (`cFix()`); the tonic then selects **which key** you play within that fixed grid, instead of transposing the whole tuning. That is why Веркмайстер's major third reads **≈390¢ in C and ≈408¢ in F#** — the whole lesson. `leadFreq`/`bassFreq`/`chordFreqs`/`centsOf` each have a `fixedKey` branch (via `fixedSlot`); row labels show **real note names** (`rowLabel`) because the grid is absolute, so the names are true again — all other cents scales keep ordinals. **`fixedKey` is a SEPARATE property from `gridChords`** — the memberships differ: «Натуральный (подвижный, хор)» deliberately stays **mobile** (the pair's contrast is the lesson), and Пифагоров is `fixedKey` but keeps **pure-ratio chords** (not `gridChords`). The three well temperaments (Веркмайстер III / Валлотти / Кирнбергер III) sit in the **`europe` «Европа историческая»** section, `natfix`+`gridChords`+`fixedKey`, each with its own comma recipe; A/B them to hear near vs far keys.

### Scheduler — look-ahead is a hard invariant
Track events of the prepared roles (`isLayer`: chords/bass/drums) are scheduled at their **exact** times `loop.t0 + (ev.t + off)*spb` inside a `SCHED_AHEAD`(≈300 ms) window (`scheduleLayers` → `ENG[fn](ev.a, ev, {when})`). `off` is 0 without repeat; with the brace cycling, the window is cut at each pass boundary and `off` is the whole-pass offset that maps the MONOTONIC beat onto the song beat. Live `W*` calls pass no `when` → `AC.currentTime`. Every voice function takes an optional `when` defaulting to now — **do NOT "simplify" that away.** Solo and drone also accept `when` since slice S2, but they still fire "almost now" through `fireNear` over the song-position interval `(loop.pos, p]`; moving them into the window is a separate, audible change that nobody has made. **Cost is bounded by the window, not the song** (slice S3.2): both loops walk a sorted prefix of `events` from a cursor (`curSched`/`curNear`, positioned by binary search `cursLowerBound`) instead of the whole array — see "Time, tracks and the recorder → cursors". Why it exists: layers used to fire "now" at whatever instant the poll ran, and a blocked main thread (synchronous MediaPipe + three synthesis paths on one thread) bunched them; the metronome was already scheduled ahead, and that asymmetry was the audible drift. The window **masks** blocking, it does not remove it (root cause = vision on the main thread — see BACKLOG). Known bounded costs (accepted): drum hits already scheduled inside the window still play after stop, panic, mute, delete or a brace jump (one-shot oscillators can't be cancelled), and surviving tracks can drop out for up to one window after undo/`clearJam` (rewinding `loop.sched` would double-fire drums).

### Metre & accent grouping (variable time signatures)
`loop.metre` (default from `config.BEATS_PER_BAR`, set via `setLoopMetre`, clamped to `METRES=[2,3,4,5,6,7,8,9,10,12,16]`, changeable **only while the song is empty and the transport stopped** — `setLoopMetre` refuses otherwise and `ui.refreshMetreCtl` disables the control) replaced the old `BEATS_PER_BAR` constant. **No denominator by design:** the engine counts beats at BPM, so 7/8 and 7/4 differ only by tempo — which fits talas (counted in matras) and Balkan pulses honestly; quantisation was already beat-relative. **Accent grouping:** `METRE_GROUPS` (`7=3+2+2`, `9=2+2+2+3`, `16=4×4`) + `METRE_KHALI` (`16→[2]`, the empty third vibhag) feed `beatLevel(metre,b)` → four metronome accent strengths (2 bar-head / 1 group-head / 0 beat / −1 khali) AND the `drawLooper` tick grid, so grouping is seen and heard; **khali is a weakened head, not silence** (a tala's structural feature). **Subdivision is orthogonal to metre:** `loop.sub` only sets the live drum quantise grid (and its faint ticks in `drawLooper`, drawn **only when `sub!==4`** so the 4/4 view is byte-for-byte); a pattern's own `sub` lives in the pattern. `arrange.js` patterns declare their own `beats` (`Вальс`/`Дадра`/`Балканский 7`/`Кехерва`/`Балканский 9`/`Тинтал`, …); a pattern whose `beats ≠ loop.metre` is skipped. Count-in is always ONE bar (`loop.metre` beats) at any metre, and it counts in to the **start point** (`loop.lead` — the brace start when recording from stop), not to beat 0; clicks before `lead` are the count, and nothing is recorded or fired there. A brace is quantised to whole bars, so under repeat the monotonic and song beats differ by whole bars and the accents never drift.

### Chord readout — live Hz from the sounding voices
While a chord SOUNDS, its highlighted root rectangle lists each note's **Hz** with the interval **above the root** in cents (`drawChordReadout` in draw.js). The numbers are read from the **sounding voices** (`chordHold['latch']` → `latchChordFreqs`), **not recomputed** — so the display can never disagree with what's heard, and it works for all four `chordFreqs` branches for free. It shows only **live latched** chords; loop-played chords (owner `'loop:N'`) keep the plain highlight.

### Chord brightness — hand depth → expression, and the TWO-FILTER invariant
The chord role gets a Z-axis like solo's reverb: hand depth (`dist(lm[0],lm[9])`, the SAME size that drives the solo reverb) → a brightness value `bd` (0 near/bright … 1 far/dark) that rides into `WchOn`/`WchSet` **beside `ty`** and is **recorded on the event as `a.bri`, exactly as `a.rev` rides the lead event** — so a replayed layer keeps its own brightness curve (`recChSet` pushes a `chSet` on a `|Δbri|>REC_REV_EPS` change alone). **Two-filter topology is an INVARIANT, not redundancy** (`buildChordPool`: `o1/o2 → f → fb → g`): `f` bakes the **attack envelope** (timbre — `fo/ft/fv`, set once at attack, never touched per-frame); `fb` carries the **continuous brightness** (expression — `briToHz(bri)` via `setTargetAtTime` all note). On a single node a brightness change would fight the scheduled attack ramp (within `ft`) and permanently couple timbre to expression — **a future session must not merge `f` and `fb`.** Per-layer isolation is by **owner key** (`'latch'` live vs `'loop:'+layer`, plus `':'+k` for merged takes and later repeat passes): each owner holds its own pool voices → its own `fb`, so the live hand physically cannot change a replayed track's brightness — which is why brightness left the old shared bus (a global filter) for a per-voice `fb`. **Since effects goal (а) brightness is an ordinary CHAIN EFFECT:** `bright` (`kind:'voice'`, no nodes) in the chord chain, seeded on the `play:z` address, so the old built-in behaviour is now a default setting that can be removed, fixed to a number or moved to another axis. The recorded value comes from that parameter (`fxChordBri()`). ⚠️ An ABSENT `a.bri` means **"not set"** (the filter opens at attack, a glide leaves it alone) — NOT "take the live value": arrangement and jam chords never carried brightness, and reading the live hand would repaint every backing chord. This is the OPPOSITE of solo's rule for an absent effect map (see "Known limits"). The separate ЯРК indicator (`chBrightDisp`/`drawChordBright`) is deleted; the chain's own bar shows the value.

### Looper hand — commands by finger, single-fire by construction
Assign a hand of any role the **`'loop'`** function and it plays nothing; instead it drives the recorder by finger on a pinch: **index = record** (`onRec` — not recording → start a take into the armed track or a new one; recording → stop), **middle = play/pause**, **ring = undo the last take**, **pinky = clear-all** — clear-all needs a `CLEAR_HOLD_MS`(3 s) hold with a **visible countdown** (`setLooperClear`), and **releasing early cancels** (`endPinch` clears the countdown). **Single-fire is STRUCTURAL:** `fireLooperCmd` runs inside the **pinch-capture block** (the `false→true` edge), which by construction runs once per pinch; held frames take a different branch and do NOT repeat the command (only the pinky countdown lives in the hold branch, itself gated by `S.clearFired`). The pinched finger is **frozen** for loop (and hold) hands — the `S.fn!=='hold'&&S.fn!=='loop'` gate on mid-pinch finger-change — so drift can't slide onto another finger and fire a second command. `doLooper` **confirms each command on screen by name** (`setLooperMsg` → «● Запись»/«Запись стоп»/«▶ Пуск»/«⏸ Пауза»/«↶ Отмена дубля»/«✕ Очищено») and **impossible ones say why** («Нечего играть»/«Нечего отменять»/«Уже пусто»). The transport buttons in the UI still work — the looper hand is ONE more input, not a replacement.

### Audio engine (`initAudio`) — five chains into one master
`master → limiter → destination`. **FDN reverb** networks (`buildFDN`, constants in `REV_A`), one instance per role whose chain holds a reverb — solo and chords by default, so two networks run out of the box. Chains: (1) **solo pool** (see below); (2) chord pool (`CHORD_POOL_N` always-on 2-osc voices, gain-gated); (3) bass pool (`BASS_POOL_N` **still mono per layer**, timbre baked on attack); (4) drums (synth per hit, kit from `a.kit`); (5) drone (detuned saw pair, LFO-swept LP, follows `tonicFreq()`). Plus the metronome.

**Reverb is an FDN (feedback delay network), NOT a convolver** (`buildFDN`; `makeIR` and the `ConvolverNode` are gone). Signal: `verb` (input `GainNode`) → 80 Hz highpass → pre-delay → **3 input allpass diffusers** (`apStage`) → **4 delay lines**, each `delay → damping lowpass → feedback gain`, mixed by a **Householder matrix** (`in_i = src + x_i − (2/N)·Σx`, built from one Σ node + one `−2/N` node instead of 16 connections) → **stereo taps** (different sign patterns per line into L/R) → merger → `outTrim` → `verbOut` → `master`. ~49 nodes per network, no oscillators and no worklet. The sends are **not part of the network's own code**: each role's instance owns its `send` (the chord chain's reverb mix starts at the historical 0.12, `CH_REV_SEND`), and solo notes send per voice, with the mix value carried in the note's `a.fx` under `'reverb:mix'`. Numbers live in **`REV_A`** beside `EXPR_A` (sound-side numbers belong in audio, not `config`). **Three real-time params:** *mix* = the sends, *decay* = `setRevDecay(sec)` (RT60 → per-line `g_i = 10^(−3·d_i/RT60)`, which is why one number gives one tail across four different delay lengths), *tone* = `setRevTone(hz)` (the in-loop lowpass cutoff). Decay and tone are genuine `AudioParam`s written via `setTargetAtTime` and are now parameters of the reverb module (`REV_PARAMS`, reachable from the effects constructor) — the frozen convolution buffer could only ever offer *mix*, and that is the whole point of the swap.
- **Reverb was the first EFFECT MODULE** (`makeReverbFx`, Plast 1 of the effects-constructor work), and the shape has grown since: a factory entry `{id, labelKey, kind, params, make}` in `FX_FACTORY`; a per-role instance built by `make()` and kept in `FX_INST[role][fxId]`; param descriptors `{key, labelKey, short, unit, def, min, max, curve, attach?}` that `fxWrapParam` gives a `set` and a `cur` (ranges are advisory — the setter's own clamp is the authority). A network is a **real instance, not a singleton**: `buildFDN` returns its lines and they live inside the object. `attach:true` marks a **per-note** parameter (mix, a send) that rides into the SOLO event's `a.fx`; every other parameter is a **network** parameter of the instance, shared by everything that role plays. ⚠️ The original warning still holds, narrowed: attachment kinds really differ (bus / insert / voice — see the module map), and the per-voice modulation effects — drive and vibrato, plus the per-voice solo tremolo — are **still not modules** and must not be forced into this shape; see HANDOFF «КОНСТРУКТОР ЭФФЕКТОВ».
- ⚠️ **The in-loop lowpass MUST stay at Butterworth Q (`REV_A.toneQ = −3.0103`), and this is load-bearing, not tidiness.** Web Audio interprets `Q` **in decibels** for `lowpass`/`highpass` (`α = sin ω₀/(2·10^(Q/20))`), so the **default `Q = 1` is a quality factor of 1.122 — a +1.96 dB resonant peak (|LP| ≈ 1.25) just below cutoff.** Outside a loop that is a harmless colouration; inside one it is fatal: `g·|LP| = 0.886 × 1.25 = 1.11 > 1` on all four lines at once, and the reverb **self-oscillated into a whistle at ~3.9 kHz**. `−3.0103` dB = quality factor exactly `1/√2`, monotonic, max magnitude 1 at DC — which makes `loop gain = radius(M)·g·|LP| ≤ g < 1` true for *every* reachable `decay`/`tone`, not just today's constants. Note what did **not** save it: `gMax` clamps `g`, and the runaway came from the filter; the master limiter caught it but is a backstop, never a design guarantee. **Compute the loop gain — never assume "a lowpass reduces gain".**

**Solo is POLYPHONIC — a pool with owner keys, like chords** (`lv[]` / `leadHold`, **`LEAD_POOL_N=12`, `LEAD_POOL_KS=8`**). Owners: live hand `'lead:L'`/`'lead:R'` (built by the single helper `gestures.soloKey(key,finger)` — **the finger argument is already there so multi-finger input is a one-line change**), replayed layer `'leadloop:'+layer+':'+v`. Live play and a replayed solo layer therefore **no longer fight** — the same separation `'latch'`/`'loop:N'` gives chords.
- **A voice builds ONLY its own bank, lazily.** `buildLeadBanks(preBus, ksOk, only)` now builds one instrument (each block gated by `sel(i++)`, bodies untouched; `banks` is a scratch array the caller drains). ⛔ **Never rebuild "all banks"** — the old design kept all 23 alive permanently (40 oscillators + 7 KS worklet nodes on every device), and replicating that per voice would be 6× that. Because of this the pool is **cheaper than the status quo**: one instrument in play = 1–5 oscillators, and KS costs at most `LEAD_POOL_KS` worklet nodes instead of a permanent 7.
- **Per voice:** bank → `satDry/satWet` (drive) → `env` → `vol` → `trem` (the per-voice tremolo) → `leadSum`, with the delay send (`dlySend` → the solo delay's gate) and the reverb send (`revSend` → the solo reverb's gate) tapped after `trem`, a per-voice vibrato depth, and its own humanisation `ConstantSource`. All of them take the note's OWN values at attack (`applyFx(a.fx)` → `pendFx` → `applyVoiceFx`), which is what lets a recorded solo note replay with the effects it was played with (effects Plast 3.7.1/3.7.2). **Drive is per-voice on purpose:** saturation sits *before* the envelope and `tanh` is non-linear, so moving it to the bus would change how a **single** note sounds at `drv>0` (and the default `drv` is 0.12, not zero).
- **On the bus (shared):** the expression stage (amplitude shimmer on `exprGain`, the soft/hard shaper morph, the wah) → `leadOut` → master, plus any INSERT in the solo chain (registered by `fxRoleOut('ld', leadOut)`) — so two notes still intermodulate through one expression shaper. Accepted.
- **Allocation:** same owner → same voice (per-frame calls lead the note, they do not reallocate); else a free voice **that already has that instrument built** (affinity, or a Sitar layer and an Organ hand would rebuild a bank per attack); else any free voice; else a new one up to the cap; else **steal, released voices first** (a cut melodic note is far more audible than a cut chord tail).
- **Three latent defects were fixed with it, all invisible while solo was mono:** the humanisation `ConstantSource` was **global** and re-randomised per attack (a second attack would have re-detuned the first, still-sounding note — it is now per voice, wired via `mkOsc`'s `bldHum`); the recorder's open-note state was **single** (`recLead`/`recLeadBend`/`noteStartBeat`/`bendLastC` — two hands recording at once would have interleaved into one corrupt stream; now a `Map` per owner); and `ENG.leadOn` called **`setLeadInstr(a.inst)` globally**, so a replayed layer hijacked the live instrument and the panel button — baking the timbre per voice removes it.
- **Sizing the pool is sizing the ceiling, not the cost.** The live maximum is **8** (2 hands × 4 fingers), so `LEAD_POOL_N=12` = 8 live + 4 for replayed layers and stealing headroom; below that the eighth note would steal the first. Voices are **lazy** and each carries only its own bank, so playing two notes costs two voices no matter how big the pool is. **`LEAD_POOL_KS=8`** is deliberately tighter — the live maximum with *no* layer headroom: a KS voice is an `AudioWorkletNode` (a JS callback every 128-sample quantum) and **Sitar adds 5 tarab bandpasses per voice**, so eight Sitar notes are 8 worklets + 40 biquads — the heaviest thing the app can be asked to do. Worst subtractive case is ~5 oscillators per voice (Organ full, SuperSaw) plus one 2× waveshaper each. If a phone crackles, that is the audio thread, not MediaPipe — lower these two numbers, not the frame rate.
- **Two accepted behavioural deltas:** an instrument change **no longer morphs a sounding note** (it applies from the next attack — the rule chords and bass already follow), and the mono **hand-over is gone** (§ below).

**Three synthesis paths for the lead banks (not one) — a bank is just `{gain, setFreq, cancel, strike?}`, so all three ride the SAME solo chain and effects:**
1. **Subtractive** (most banks): oscillators via `mkOsc` (which wires `vibGain`+`humDetune` into `.detune`) → optional filter → gate. Velocity→brightness (`fstrike`/`strike`) fires at ATTACK, not per-frame (a per-frame cutoff would stomp the filter envelope; `setFreq` deliberately never touches the filter). Humanisation (`HUM_CENTS=4`, in `humDetune`) is fresh at each attack and **never recorded** — a replayed loop gets new variation. **Pads and organs are pitch-clean** (`hum:0`, `det:0`): the beating you hear is the TUNING, not the timbre. **Bass is not pitch-humanised** (low-frequency detune muddies).
2. **FM** (`buildFMBank({ratio,peak,sus,tau})`): carrier via `mkOsc` (so it flows through the shared chain), modulator is a bare osc → `modGain` → `carrier.frequency` only (not the output). The modulation-index envelope (`strike`) decays FASTER than amplitude (`rel` > `tau`) — that struck-metal read. **Non-integer `ratio` gives inharmonic spectra the subtractive path physically cannot produce.** Banks: «Колокол (глубокий)» (ratio 1.41), «Металлофон» (3.51).
3. **Karplus–Strong** (`buildKSBank`, wraps the `ks-string` worklet): `node → [body resonator] → gain → chain`; `setFreq` is the a-rate `freq` param (same `setTargetAtTime` as every bank → glissando/bend/theremin free), `strike` fires the `pluck` param edge. `KS_BANKS` params: `fb` (decay), `damp` (loop filter), `exBase`/`exSpan` (pluck brightness), `nl` (loop nonlinearity = **jawari** on Ситар / metal edge on Сантур), `symp` (bandpass resonators following `baseF()` = **tarab** on Ситар, retuned like the drone), `body`. KS has no `oscillator.detune` (`hum:0`). Banks: «Струна», «Ситар», «Уд», «Кото», «Сантур», «Гитара», «Пиццикато». If the worklet fails to load, `buildKSFallback` fills those slots so indices never desync.

Drum kits are per-hit synths (`drumHit(row,vol,kit,when)`): Стандарт, Дарбука (`dDum`/`dTek`), Табла (`tabBaya` with the signature downward pitch bend + `tabNa`), Гамелан (inline FM `gmlFM` → inharmonic bronze), Тайко (`taikoDrum`/`taikoKa`) — same 6 rows/indices across kits.

### Time, tracks and the recorder (replaced the loop model — slices S1…S3.5)
The app **stopped being a looper** in slice S3.3. There is no loop length and no unconditional wrap; the song is a linear sequence of events in absolute beats, and looping came back later as an OPTIONAL marked span (the brace). Most names still say `loop` (`loop`, `loopPos`, `drawLooper`, `'loop:N'`, `setLoopBars`) — they are history, not the model.

**The event** — created in exactly TWO places, `push` (every recorded event) and `loadArrangement` (every backing event):

`{t, layer, fn, a, sc, sev, tk}` (+ `jam:true` on backing events)
- **`t` — ABSOLUTE song beats, `t ≥ 0`.** Quantised at record time by `gridFor` (chords 1 beat, bass ½, drums `1/loop.sub`, solo never). While the brace cycles, `push` records the FOLDED song beat (`songAt`), so each pass accumulates into the brace; a quantise that would round past the brace end is folded onto its start.
- **`layer`** — the track's layer number: the address of its SOUND (owner keys), not its identity (see lanes).
- **`fn`** — `leadOn`/`leadSet`/`leadOff`, `chOn`/`chSet`/`chOff`, `bassOn`/`bassSet`/`bassOff`, `drum`, `drone` (drone only from arrangements).
- **`a`** — intent, never frequency. All pitched roles: `deg`, `oct`, `vol`. Solo: `inst`, **`v`** (the note's slot among notes open at once in that track — pairs `leadOn` with its `leadOff`; absent reads as 0), **`fx`** (the note's effect map `'fxId:paramKey' → 0..1`, COPIED by `push` so later hand movement can't rewrite the past), `bend` (theremin cents curve), `hold` (a set that must not re-pitch a bend). Chords: `inst`, `ty`, `bri`, **`k`**. Bass: `inst`, **`k`**. Drums: `row`, `vol`, `kit`. Drone: `lvl`. **`k`** is the owner suffix that keeps takes and repeat passes of one track apart; absent reads as 0 = no suffix.
- **`sc`/`sev`** — the frozen scale REFERENCE and seventh (hard rule #7). `push` takes an explicit frozen context `fz` for exactly one caller: the chord re-open at a repeat seam.
- **`tk`** — the TAKE number, on every event. `takeSeq` is monotonic for the session: `onRec` assigns `curTake=++takeSeq` and `push` stamps it; `loadArrangement` gives each backing layer its own number. An event without `tk` cannot arise today (nothing is saved); it would read as 0, the oldest.
- ⚠️ **Anything that creates events later — the piano roll inserting notes nobody played — is a THIRD creation site** and must stamp `tk`, keep `t` absolute, pick `v`/`k` that don't collide with what the track already stores (`layerSlotTop`/`layerTakeTop` compute exactly that), and call `schedInvalidate` once afterwards.

Frequency is derived at play time via `leadFreq/chordFreqs/bassFreq(..., ev.sc)`, so a track re-tunes to the live tonic while keeping its frozen scale (**and its `cents` tuning**, for free). Replay goes through `ENG` directly and is never re-recorded. This is polymodality — don't "simplify" replay to the current scale.

**Two kinds of beat — every consumer must pick the right one** (the comment on `loopPos` is the canonical statement):
- **MONOTONIC** `m = (now − loop.t0)·bpm/60` — the CLOCK, never goes back. Used only for time arithmetic: `loop.t0` rebases (tempo change, brace edits), the scheduler window (`loop.sched`, the horizon), counting repeat passes (`rgnReps`), the count-in (`m < loop.lead`), metronome click numbering (`loop.clickBeat`).
- **SONG** `p = songAt(m)` — the place in the MATERIAL; identical to `m` unless the brace cycles. Used by everything that points at events or at song length: recording (`push`, `curBeat`), lead/drone replay (`fireNear`, `loop.pos`), the resume point, end of song, and everything the person sees (the strip's playhead and width).
Mixing them was a real bug: the strip once used the monotonic beat, so under repeat the playhead ran off the end and new bars kept appearing.

**Transport.** `startTransport(countIn, from)` is the ONE way playback starts (play, record from stop, arrangement, `seekTo`): it rebases the cursors, sets `lead=from`, puts `t0` so the song beat is `from` after the count-in (one bar) or a 60 ms lead-in, and CHASES held state if `from > 0`. The tick is silent until `m ≥ loop.lead`. `setLoopBpm` keeps the current beat by moving `t0`. `stopAtEnd` stops at the end of the material — never while recording, never while cycling. `seekTo(beat)` exists (refused while recording) but has no UI caller yet.

**The brace — repeat as a marked span** (`loop.rgn = {on, from, to, user}`):
- **ONE control, TWO jobs** (like a DAW loop brace): its bounds are WHAT cycles when ⟳ is on, and its START is WHERE RECORDING BEGINS when ● is pressed from stop. There is deliberately no second "record start" ruler.
- **Two states.** `user:false` — it FOLLOWS the material (`[0, end of material rounded up to a bar]`; drawn dashed with «auto»). `user:true` — the person set it; it stays put, recording past it does not move it, and only a song that shrinks below its end pulls it in. ✕ returns it to following.
- **Quantised to the bar, minimum one bar, clamped to the material** (`braceClamp`). Bar resolution is honesty about pixel density, not an unfinished feature; do not "improve" it to sub-bar without timeline zoom. Whole bars also keep `m − p` a whole number of bars, so accents never drift and rebases are exact.
- **Edited by tap/drag** on its own band in the strip: a tap snaps to the nearest bar line and moves the NEARER edge (a tie is broken by the side of the brace midpoint). Edits are refused while recording.
- **`rgnApply` is the single writer** of bounds and on/off (the one exception, `braceFollowGrow` in `push`, writes only while NOT cycling). While playing it **rebases** `t0`/`sched`/`lead`/`clickBeat` by whole bars so the song beat does not jump; if the playhead ends up past the new end it jumps to the brace start (a seek, with a seek's cost). A playhead BEFORE the brace plays into it linearly. `rgnSync` (called from `schedInvalidate`) keeps the bounds in step with the material.
- **Region-only machinery** — all of this is inert without the brace cycling: the `songAt`/`rgnReps` fold; the pass split and seam release in `scheduleLayers` (`releaseLoopLayersAt(when)`) plus the chord/bass chase at each seam; the wrap branch in `tick` (sweep the pass tail, `liveWrapRelease`, the solo chase, then fire from the brace start); the quantise fold in `push`; the per-pass closing in `recFoldRoll` (which fires when recorder time goes backwards — only a cycling brace or a ⟳ jump can cause that); and the `stopAtEnd` suppression. **Unconditional:** absolute time, the chase at `startTransport(from>0)`, the stops, lanes, arming, undo and delete.

**The chase — why entering the song after beat 0 needs one.** Chords and bass have ONE voice per track (`'loop:N'`, `'bassloop:N'`), and a chord change GLIDES that voice instead of re-attacking: a latched progression is one `chOn` followed by `chSet`s, and a sustained bass line is one `bassOn` followed by `bassSet`s. `chordGlide`/`bassSet`/`leadSet` do nothing when no voice is open. So entering after the `on` — resume from pause, a pass that starts at a brace not at bar 1, recording from the brace, a jump — would leave the whole role silent until its next `on`. `chaseFor(x)` folds the sorted events before `x` into "the last `on` per owner plus the latest `set` after it, minus owners an `off` closed" (skipping owners whose own on/off sits exactly on `x`, and events of the take being recorded); `chasePlay(x, when, lead)` starts those voices through the ordinary `ENG.chOn`/`bassOn`/`leadOn` at the entry time, with the event's own frozen scale, its effect map and, for a theremin note, the REMAINING part of its bend. Muted/silenced tracks are skipped at play time. Called from `startTransport` (from>0), the brace jump in `rgnApply`, each seam in `scheduleLayers` (chords/bass) and the wrap in `tick` (solo). Cost: the fold is one pass over the prefix, cached per entry beat and reset by `schedInvalidate`, so a seam that repeats costs O(open owners). Entry at beat 0 costs nothing.

**Tracks (lanes).** A track is a layer number plus a generated **lane id**. The id is the identity — mute, solo, the arm and a pending delete are keyed on it — because layer numbers are REUSED (a new track takes `maxLayer()+1`, so after undo it gets the freed number) and can have holes (`clearJam` removes by flag). `laneNew` is the ONLY writer of `laneId` and always issues a fresh id, overwriting whatever that number carried (hard rule #27). Mute/solo: `laneAudible(layer)` — solo overrides mute — gates both replay loops and the chase; `laneGated()` is computed once per scheduler call so an untouched mixer costs nothing per event; `laneHush()` releases newly inaudible tracks immediately through `releaseLoopLayersAt(undefined, layer)` and keeps the drone's level in step.
- **A track is NOT typed by role.** One track can hold solo, chords, bass and drums at once: switching role in the middle of a take is a normal gesture, and a take recorded into an existing track MERGES with what is there. Anything that edits or displays a track (the piano roll) has to be designed around that.
- **Arming** (`toggleArm` — tap a row outside its buttons; `armLane` holds a lane id or null): ● records into the armed track instead of a new one, without calling `laneNew` (the track keeps its id, mutes and arm). Arming is frozen while recording. A muted armed track is allowed (a punch-in) and the header says «(not heard)». Undo/delete/clear of the armed track clears the arm.
- **Owner keys keep merged material apart.** Replay owners are `'leadloop:N:v'`, `'loop:N[:k]'`, `'bassloop:N[:k]'`; live owners are `'lead:L'`/`'lead:R'` (+finger), `'latch'`, `'bass'`. At each ● the recorder computes `vBase = layerSlotTop(layer)` and `takeK = layerTakeTop(layer)` — above everything the track already stores — and both RISE at every repeat seam (`recFoldRoll`), so no new note can share a voice with a stored or earlier-pass note. `releaseLoopLayersAt(when, layer)` matches a track by the key tail `N` or `N:…`, so suffixes never make track 1 catch track 12.
- **Replay skips only what sounds live:** `recording && ev.tk === curTake`, in `scheduleLayers`, `fireNear` and the chase fold. For a take into a new track that is the whole track (the old behaviour); for a merge the track's earlier material keeps playing.

**Undo, delete, clear.** **⤺ removes the LAST TAKE** (the highest `tk` still present), repeatable back through the history: a take that created a track removes the track, a merged take removes only its events. Each backing layer is its own take, so a backing is undone layer by layer, rhythm first. Undo never resurrects anything a row delete removed. **✕ on a row deletes that track** — two taps within `DEL_CONFIRM_MS` (3 s; the button fills red and the header asks), any other strip tap cancels; it is **NOT undoable**; it releases only that track's voices (the mute path, not `softAllOff`); the track being recorded into cannot be deleted. **✕ in the transport clears everything:** events, lanes, arm, brace (back to following), repeat off.

**The three stops mean three things.** **Pause** (▶ while playing, `onLoop`) HOLDS the position and closes held notes in the recording first. **Panic** (■) RESETS: `recStop()` if recording (the same close-and-stop path as ●, without the tutorial hooks), then halt the transport, then `softAllOff`, then rewind to the brace start — keeping the song, the brace, mutes/solos and the arm. **Clear** (✕) resets everything, brace included.

**Closing notes — nothing may stay open in the recording.** Every stop that ends a recording closes what is held (`recAllOff`: every solo owner, the chord, the bass): ●, pause, panic. At every repeat seam (`recFoldRoll`): open solo notes get `leadOff` at the pass end and the slot base rises; a held bass gets `bassOff` at the pass end (the hand re-attacks next frame); a latched or held chord gets `chOff` at the pass end and a **written** `chOn` at the pass start carrying its current state and its own frozen scale — the live chord voice itself is untouched (hard rule #20; only the RECORDING changed). `clearJam`, and undo of a take other than the current one, close held notes before `softAllOff` throws the recording state away. The one known loss: a note begun during the count-in has no `on` in the recording (`push` refuses before `lead`), so it is missing rather than hanging.

**Cursors — one rebase point.** Both replay loops walk the sorted prefix `events[0..cursN)`; `push` appends the take being recorded UNSORTED after it, which is safe because replay skips that take. `schedInvalidate()` is the single reset: it re-reads `cursN = events.length`, drops both cursors and the chase cache, recomputes `songLen` and re-syncs the brace. Every path that changes the events or jumps the time base calls it (start/resume, record start/stop, arrangement, undo, delete, clearJam, clear, panic, tempo, brace edits). ⚠️ Because it declares the whole array sorted, any call made **while recording** must sort first (`setRegionOn`, undo, delete, clearJam, panic all do). Removal uses `compactEvents(drop)` — one in-place pass that keeps the array reference draw holds (hard rule #28).

**Known limits the next work has to design around — FREEZE INHERITS EVERY ONE OF THEM:**
- **ONE NETWORK PER CHAIN OWNER.** There is exactly one instance per (owner, effect) pair — `FX_INST[key][fxId]`. A recorded track drives that instance through `fxPlaySet`, and the player's LIVE playing of the same role goes through the same nodes: while a recorded bass line drives the bass reverb, live bass is in that reverb too. ⛳ **This is not hidden, it is impossible:** playing live with different settings than the recording cannot be done today at all, and only freeze — giving a track its own instances — makes it possible. The bars say so on screen (`fxIsDriven` marks a parameter the recording governs), and on stop the sound is pulled back to the hand's aim (`fxRestoreAim`).
- **SEVERAL TAKES THROUGH ONE CHAIN: LAST WRITER WINS.** `fxPlayBuild` merges every take's snapshot and lane into ONE list sorted by `(t, tk)`, and `fxPlayDrive` folds it up to the current beat — so at any point in the song the value is the last one written at or before that beat, ties broken by the higher take number. ⚠️ A take governs ONLY the owners whose roles it actually played (`meta.keys`, built from `evRole` over its own events): a bass take never touches the chord chain.
- **⛳ THE ENGINE VARIES AT EVERY ATTACK — NINE `Math.random()` CALL SITES IN TOTAL, AND SINCE SLICE F1 EIGHT OF THEM ARE SEEDABLE.** The exact arithmetic, because two partitions of "eight" were being used and they are not the same eight: **`src/audio.js` has 8 call sites** — 7 at attacks (chord: humanisation cents, −0..5% level, ±10% attack time, `chordOn`; solo: the same three, `leadOn`; bass: ±10% attack time, `bassOn`) **plus 1 that fills `noiseBuf`** in `initAudio`, read by every drum with a noise component — **and `src/ks-worklet.js` has a 9th**, the pluck excitation inside `excite()`. **All 8 in `audio.js` now go through `rnd()`**, a module-level indirection defaulting to `Math.random` with a `setRnd(fn)` setter (exported; only `render.js` calls it, and only on its own `'./audio.js?render…'` copy). ⛔ **Never seed by patching `Math.random` globally** — the two engine copies share the global object, so that would make LIVE play deterministic and audibly kill humanisation; `render.js`'s probe asserts against it (`liveRandomIntact`). ⚠️ **The 9th cannot be reached from the main thread and is deliberately left unseeded:** `AudioWorkletGlobalScope` is a separate JS realm and `addModule` re-instantiates it per context, so seeding it means passing a seed through `processorOptions` — a real edit to `ks-worklet.js` and `buildKSBank`. Consequence, which the probe reports rather than hides: **a Karplus–Strong instrument still differs between two renders of the same material.** (`demo.js:196` is a 10th call site in the codebase but belongs to the start-screen demo's own mini-engine and its own `noiseBuf`; it is never rendered and is correctly untouched.) ⛔ **None of this is recorded** (hard rule #11 names humanisation explicitly) — a seed is not an event and does not change that; it will ride on the frozen track's own record. Freeze's answer, decided: **"the same performance" is the requirement, and the cheap half of "the same samples" was taken anyway.**
- **⛳ A REPRODUCIBLE RE-RENDER MEANS THE SAME *PERFORMANCE*, NEVER THE SAME SAMPLES — BIT-IDENTITY IS NOT ACHIEVABLE AND IS NOT REQUIRED. MEASURED, NOT ASSUMED.** Slice F1's seeding works (see below), and two seeded renders of the same material **still differ by one to three float32 last-bits**. ⛳ **The whole explanation is the summand rule:** float addition is not associative, so a node fed **two** non-zero inputs has only one possible order, `(a+b)`, and reproduces **bit-for-bit** — while a node fed **three or more** can have its inputs reduced in a different order between runs and moves by about one last bit. ⛔ **This is the platform's arithmetic, not ours:** we build connections in a fixed order; how a node folds its inputs is not reachable from JS. It is why **bass is exactly identical every time** — its busiest summing node takes `g1+g2` ([audio.js:1853](src/audio.js#L1853)) and the pool's other voices contribute exact zeros, which do not change an order — while **chords** (3 pool voices into `chordBus`), **solo** (5 SuperSaw oscillators into `ig`, [audio.js:243](src/audio.js#L243)) and **three overlapping drum hits** all drift by a last bit. **The numbers, so nobody derives them again** (every probe material peaks in the binade `[0.0625, 0.125)`, so one ULP is `2⁻²⁷ = 7.4506e-9` for all of them): same seed → **1–3 ULP**; different seed → **~15 600 000 ULP** (1.16e-1); same seed **with a reverb in the path** → **~10⁶ ULP** (≈8 % of peak), because a feedback network with RT60 1.7 s amplifies last-bit rounding into a **decorrelated tail — the same room played twice**, identical in density, decay and colour, different in micro-structure. ⚠️ That amplification factor (~3·10⁵) is *not* derivable from a linear error model and is recorded as measured-but-unexplained rather than fitted. ⛳ Consequence for the freeze arc: **a refreeze after no edit gives the same performance and a different waveform, and that is correct behaviour, not a defect to chase.** Any future test must compare against a threshold relative to the material's own peak, never `===`.
- **ADDING AN EFFECT IN THE EDITOR TO A TRACK WITH NO CAPTURE CREATES ONE, SEEDED FROM THE LIVE CHAIN** (`autEnsure` → `takeCapStart`). Everything recorded before this arc, every backing and every editor insertion has no capture and therefore follows the live controls. The moment you add an effect to such a track in the editor it gets a snapshot of the chain AS IT STANDS AT THAT INSTANT and from then on is NAILED to it — which keeps it sounding exactly as it did a second ago, but stops the live knobs from ever reaching it again. ⚠️ **This is a real behaviour change for old material and there is no notice on screen.**
- **Chains belong to the OWNER, not the track** — the same fact as the first limit, seen from the freeze side: freezing ONE track through the live graph would pick up other tracks' tails out of the shared network and bake the owner's current network settings. A clean freeze needs its own instances per track, and per role inside that track (a track is not typed by role).
- **NOTHING CAN BE SAVED.** A layer's scale is an OBJECT REFERENCE (hard rule #7) and no scale carries an id; the chord type `a.ty` is a reference into `CHORD_FAM_SETS` as well. The capture itself is plain serialisable data (strings and numbers only) — but it is keyed by take number to events that cannot be written down, so it inherits the same wall. For a five-minute multitrack song that is the feature failing, not a convenience missing — see BACKLOG §1.

### The track editor — a piano roll over the song (slices S4.0…S5.6, plus the automation lane O-4)
**A NOTE IS NOT AN EVENT, AND A "NOTE" IS NOT WHAT THE MUSICIAN MEANS.** Two passes, both read-only, both lazily memoised on `songNotes`' own identity (invalidated by `schedInvalidate` — no second reset point, hard rule #28):
- **`songNotes()`** groups events into notes by **the engine's own owner key** (`chaseRole`/`chaseKind`/`chaseKey` → `ldKey`/`chOwnerKey`/`bassOwnerKey`). ⛔ Never write a second pairing formula: if it diverged from the engine's key the editor would show one note while another sounded. The reading rules follow the ENGINE, not taste: an `…On` while a note of the same key is open closes the previous one (`endBy:'next'`); a `…Set`/`…Off` with nothing open is an **orphan**; an `on` with no `off` inside the sorted prefix is an OPEN note (`end=null`) and no ending is invented; a drum is a note of zero length; the drone is a LEVEL, not a note.
- **`songSegs()`** is what the editor actually edits: **a note groups a VOICE'S LIFETIME, not what a musician calls a note.** A bass line played in one movement is ONE note across a dozen pitches (`bassSet` glides), and drawn as a note it would be one bar at the FIRST degree with every other pitch gone. A **pitch segment** — the event that sets a pitch plus the span to the next change — is the musician's note. ⛳ **The boundary is a PITCH change only:** a `set` that moves volume or effects stays INSIDE the segment, or one crescendo would shatter into ten "notes" at the same pitch. Each segment carries **its own frozen scale** (`sc`/`sev` off its own event), and `byEv` maps event → segment.

**ORPHANS CAN NO LONGER BE PRODUCED, AND THE EDITOR IS DESIGNED ON THAT SENTENCE.** Three recording slices closed every path by which a release could sort before its own note: **S4.1** — recording state follows what actually LANDED in the array (`push` returns a boolean; a note refused during the count-in sets no state, so its `set`s and `off` cannot reference a note that is not in the song); **S4.2** — at a repeat seam only the DRUM hit folds, while everything belonging to a note (`on`/`set`/`off`) is held at the pass END; **S4.3** — the quantise rule is FROZEN ON THE NOTE (`q` in `recCh`/`recBass`, so switching the button mid-note cannot split it across two grids) and a per-key ORDER GUARD (`chLastT`/`bsLastT`) never lets a chord/bass event land earlier than the previous event of the same owner key. `songNotes` still reports `orphans` — for material recorded before those slices, and as a permanent honesty channel — but the recorder no longer creates them.

**THE SHELL.** `openRoll` swaps the top bar for `#rollBar` and puts the transport into its `.roll` state (▶ plus ⏮). `main.loop` takes a different branch entirely: **the camera stream stays OPEN but is neither read nor drawn** (returning to play is instant and asks for no permission again) — and detection, the most expensive thing on the thread, is skipped. ⚠️ `processHands(null)` is still called EVERY frame on purpose: "no hands in frame" is what closes a held pinch through the ordinary watchdog and walks expression back to neutral; `latest`/`lastTs` are cleared each frame so leaving the editor cannot replay a stale detection as a pinch nobody made.

**REFUSALS GO BOTH WAYS, AND BOTH LIVE IN THE RECORDER.** `editOpen` refuses while recording or while a clip records; `onRec` refuses while the editor is open — ONE refusal covering every input, the ● button and the looper hand alike. ui only names the reason in words. A BACKING track (`ev.jam`) is **read-only** (`editBackingOpen`): an edit inside it would survive `clearJam` as an orphaned fragment. ⚠️ **Only TWO of the four roles are editable today** — `ROLL_EDITABLE=['dr','bs']`; the solo and chord tabs are shown with their note COUNT but disabled, with the reason in words (`roll.tabLater`), because each pitched role is its own slice and a tab that silently did nothing would read as a bug.

**EDITING, WITH ITS OWN UNDO AND REDO.** `editGuard` is the single door (editor open, track alive, not a backing, transport PAUSED — it pauses by itself rather than editing under the look-ahead window). Every edit is a third event-creation site and obeys the same law as the other two: absolute time, `tk` on every event, `compactEvents` for removal, ONE `editCommit` (sort THEN `schedInvalidate`, plus `takeFxTouch`). ⛳ **↶ is not a second ⤺**: ⤺ removes a whole TAKE and is off-screen while the editor is open; ↶ removes ONE edit and exists only here. **Redo is not a mirror of undo** — a move carries BOTH states (`from`/`to`) while an insert and a delete are symmetric through one object reference — and **a new edit discards the redo branch** in the single history writer `editPush`, because an undone move describes a song that no longer exists. History and future both die with the session (open, close, track switch): a reference to an event that outlived the session would one day point at nothing.

**THE SCALE IS THREADED THROUGH THE LABEL FUNCTIONS (S5.4), AND THAT IS THE POINT.** `noteLbl(deg, s=CUR())` — the single label function of hard rule #26 — now takes the scale explicitly and passes the same `s` to `swaraLbl`/`rowLabel`/`centsOf`. A track's rows must be drawn in the scale its events were FROZEN in, never the live one: open a raga track while the live scale is chromatic and the rows would otherwise read as chromatic names over raga pitches. The slice is invisible by construction — every existing caller gets the default.

**THE PITCH AXIS (S5.5).** Rows are degrees × registers: `rollDegPerOct(s)=IVX(s).length`, `rollRowOf(deg,oct,s)`, `rollRowsTotal=REG_N*dpo`. ⛳ `IVX` closes the list with a **DUPLICATE TONIC** on top, so the top row of one register and the bottom row of the next are the SAME pitch — and that is not a bug: the recording stores the played `(deg,oct)` pair, and both spellings are playable. The roll lays out BOTH rows and rewrites no event; the duplicate is merely dimmed so the player can see why two rows sound alike. **One track may hold several scales** (changing scale mid-record is not blocked, and merging takes puts them side by side): `rollGroups()` buckets segments **by scale REFERENCE** (hard rule #25 — a name is not an identifier), one group gives the AXIS and the rest are drawn as ghosts; the `#rollScale` chip appears only when there is more than one.

**FITTING, LENGTH AND THE GUTTER (S5.6).** Rows FILL the height when they fit (stretched up to `ROLL_PITCH_ROW_MAX=30`, so a pentatonic no longer leaves half the screen empty) and fall back to the minimum `ROLL_PITCH_ROW_H=18` with scrolling when they do not — one deterministic rule, so nothing flickers at the boundary. A note's LENGTH is edited through **the segment's own ending event** (`endEv`): an open segment, or one closed by the `on` of a NEIGHBOURING note, has no handle at all — dragging it would move somebody else's beginning. The label gutter is **MEASURED, not guessed** (`rollGutterW`: the widest real label of the axis scale plus the widest register suffix, capped at 42% of the canvas, cached on (scale, tonic)) — it used to be a constant 58 px, and «Са · Чхандовати» simply ran off the left edge; the measured width goes into `x0` of the SNAPSHOT, so the drawing and `laneBeatAt` move together (hard rule #9).

**THE AUTOMATION LANE** under the note grid is part of the effects arc — see the next section.

### Effect ownership, capture and playback (slices O-0…O-4) — the arc that makes a track sound as it was played
**O-0 — THE CHAIN-OWNER KEY.** Everything in the effects layer is addressed by an opaque key (`chainKeyOf(role)` → `'role:ld'`), whose only value today is the role. ⛔ **The key is never parsed back** — equality and object indexing only — and its KIND travels beside it (`chainOwners()` → `[{key, kind}]`) rather than being read out of the string. That single field is why chains owned by a TIMBRE will later MERGE into the same tables instead of migrating: `chainOwners` is the one place that will name a second kind, and every walk over owners (capture, playback, the future render, freeze) stays as it is.

**O-1 — THE CHAIN IS SERIAL, AND THAT DELIBERATELY CHANGED THE SOUND.** Effects are applied AFTER the voices of an owner sum, in chain order, each module carrying its own wet/dry. ⛔ **Solo's per-note send amounts are GONE — deliberately, permanently, and irreversibly for material recorded before the change.** The `attach` flag was dropped from `reverb:mix` and `dly:mix` and `applyFx` no longer reads those two keys: an event recorded earlier still carries five keys, three are read (`vib`/`drv`/`trm`) and two are ignored — no error, no silence, no doubling; the layer's drive, vibrato and per-voice tremolo replay exactly as before, while its reverb and delay sound as the LIVE chain stands. **Why this is right:** there is one network per owner, a reverb is a model of a ROOM and a room is one for everyone in it, and every synthesiser and DAW sums voices and then processes them. Freeze will give back "this part in a different room" as a separate track with its own chain — the honest form of that wish.

⛳ **THE BOUNDARY IS THE SUMMING OF VOICES.** Everything below it is untouched and must stay untouched: volume (baked into the voice envelope), pitch, the theremin's live Hz, the recorded bend curve, DRIVE (a `tanh` shaper before the envelope — `env·tanh(x) ≠ tanh(env·x)`, so it can never move to the bus), per-voice VIBRATO (an LFO into `.detune`, with no audio input or output at all), per-voice tremolo, and CHORD BRIGHTNESS (`kind:'voice'`, read by the voice at attack and recorded as `a.bri`). Above the boundary everything belongs to the chain.

**O-2 — THE LAW THAT REPLACED PER-NOTE VALUES: EVERYTHING PLAYED IS CAPTURED, PER TAKE.** `takeFx` holds, for each take: the **chain snapshot** at its start (composition and values, in chain order — `takeCapStart`), an **automation lane** of everything that then moved (`takeCapSample`, thinned by `REC_FX_EPS`), and **composition changes with their times** (the reserved `FX_CHAIN='#chain'` entry carrying the id list — because values alone cannot express a removal or a reorder, and since O-1 a reorder is audible). ⛳ **The lane is sampled from the RECORDER'S HEARTBEAT** (`tick`, every `SCHED_TICK_MS`=25 ms, in SONG beats, after the count-in guard and after the look-ahead window has been served) and not from the gesture loop — which is the whole point of the shape: the heartbeat beats whether or not a hand is in frame, whether or not a pinch is held, whether or not a note is sounding, so "turned a knob while a LATCHED chord rang with the fingers open" stops being a case that cannot be recorded at all.

⛳ **CAPTURE WALKS THE PARAMETER DECLARATIONS — THIS IS THE RULE THAT KEEPS WORKING AS THE APP GROWS.** `fxCaptureChain`/`fxCaptureWalk` iterate the chain and, for each entry, `inst.params` — the descriptors built from `FX_FACTORY`'s `params` spec — emitting `(fxId, paramKey, v01)`. **A new effect is therefore recorded the day it is written, and its author has to remember nothing**: declare the parameters, and capture, playback, the editor's lane, its labels and its defaults all work. The two exceptions are declared just as explicitly: the old scalars (`vib`/`drv`/`trm`, no descriptor — one parameter named `FX_AMT`) and the expression hand's five channels (`EXPR_CH`, emitted under `EXPR_FX='expr'` for the solo chain). This is hard rule #29.

**⚠️ HARD RULE #23 IS CLARIFIED, NOT WEAKENED.** It says the expression hand never writes to an EVENT, and that is still literally true — there is no `a.expr`, and its pitch shimmer stays a live-only couple of cents. Its five OUTPUT scalars (`live`/`wah`/`text`/`space`/`engage`, snapshotted by `applyExpr` into `exprCur`) ARE captured, in the LANE, which is not an event and lives beside `events` with its own cursor and its own staleness point. The parallel is exact: the theremin's live Hz is never recorded either, while its audible RESULT is (as the recorded step plus the bend curve).

**O-3 — PLAYBACK READS THE CAPTURE.** `fxPlayBuild` merges the takes into one sorted list; `fxPlayDrive(x)` folds it up to the current song beat with a forward cursor (a backward jump refolds from zero — the same shape as the chase) and applies each value through the effect's own `setNorm`, so the setter's time constant IS the ramp and no second smoothing model exists. The COMPOSITION is honoured too: `fxPlayPath(key, ids)` makes `fxPathOf` read the recorded id list INSTEAD of the live chain while playing, opening and closing gates so tails still ring out. ⛔ **The live chain is never rewritten** — a person's chain and their finger layout are theirs, and a ▶ that overwrote them would be theft. On stop, `fxPlayStop` returns the path and pulls the sound back to the hand's aim.

⛔ **AUTOMATION DOES NOT DRIVE WHILE RECORDING, AND THE REASON IS NOT SIMPLIFICATION.** Capture and drive hang off the SAME heartbeat, two lines apart in `tick`. Were both live at once, the capture would read back the values playback had just written and record its own output in a loop. A value has exactly one owner at a time: the HAND while the transport is stopped, the RECORDING while it plays.

**O-3.1 — AIM AND SOUND ARE TWO VALUES.** `p.cur` is WHAT SOUNDS (written by the hand and by playback); `FX_AIM` is WHERE THE HAND IS POINTING (written ONLY by the hand, through the single door `fxParamsOf`). The bars draw the aim, so a player can set up a new sound while the loop plays what was already recorded — and a parameter currently governed by the recording is drawn hollow with a dimmed label (`fxIsDriven`). The pinch's relative drag reads the aim too, so the first frame of a pinch cannot jump. ⚠️ This changed only what is SHOWN: while the transport plays, the recorded material is still untouchable.

**O-4 — THE AUTOMATION LANE IN THE EDITOR.** A strip under the note grid, opened by choosing an address in one select (whose first item closes it again). ⛳ **The time axis is not "kept in sync" with the note grid — it is the SAME axis**, read out of the same `rollView` snapshot (hard rule #9). **Part 1 — view and edit what was played:** the lane shows one address (owner, effect, parameter) across the WHOLE track, merged over its takes exactly as playback merges them; the left shelf is the take's chain snapshot (the level before the first point, which has no handle — moving "the state at the start" would be editing the snapshot, not the automation). ⛳ **The line is drawn as a STEP, not a diagonal, and that is honesty, not style:** `fxPlayDrive` holds the last point's value until the next one arrives, so a diagonal would promise an interpolation that does not exist. Points are dragged with **one axis per gesture** — the axis latches on the first movement (vertical = value, horizontal = time) — the value snaps to **tenths near the point and single units once the finger pulls aside** (distance-dependent precision, which costs no screen space), the number rides beside the finger, and **TIME IS FREE: the lane ignores quantise on purpose**, because a note must land on a beat or the rhythm collapses, while an effect curve belongs to no beat at all. **Part 2 — add effects that were never played:** the editor can add, remove and reorder effects for one track. ⛔ They live in the TRACK'S CAPTURE (`rec.chains[key]`), never in the live chain — and playback picks them up for free, because `fxPlayBuild` already emits the snapshot as a composition entry.

### Clip / audio recording
One engine (`clip.js`), two kinds. **Video** = `canvas.captureStream(30)` (the game canvas only — HTML chrome is a separate DOM layer, so buttons/panels are excluded) + a parallel audio tap (`createRecordingTap`, off `limiter`) combined into ONE `MediaStream` → one WebM file with picture AND sound. **Audio** = the tap only. The two are **mutually exclusive** (`activeKind()` gates the buttons + an `if(rec)return` guard). Button `.act`/`disabled` are driven by real recorder transitions (`onClipChange`), so they can't stick. Format is honest: WebM/Opus (Safari may give mp4) — no MP3/WAV/MP4 promise. While a video clip records, `videoRec` hides the on-canvas looper box from the frame.

### Backing (`🎵`) — two paths from one button: Jam, or Drums only
A tap on the **resting** button opens a tiny two-item menu (`#backingMenu`): **«Джем (вся подложка)»** (harmony + bass + drums, as before) or **«🥁 Только ударные»**. Picking one starts it immediately, so starting costs 2 taps; **every later tap switches the variant WITHIN the chosen path in one tap**, as before, and the cycle ends with OFF (back to rest → the next tap asks again). A **long-press / right-click** re-opens the menu without cycling to the end. The menu counts as "open" for the auto-hiding bar (`armBarHide` checks `backingMenuOpen()`) — it is anchored to `🎵`, which the collapsed bar hides, so it would otherwise drop out from under itself.

**The playing variant is NAMED, in three places** (a bare `4/10` says nothing once there are 18 patterns): the button reads `🥁 <name> · 4/10` (CSS-ellipsised, `#jamBtn{max-width:44vw}`, so a long name can't wrap the bar), the `title` carries the full name, and **every change raises a short toast** (`showCamMsg`) with the full name — the toast matters because the collapsed bar hides `🎵` entirely. `backingSel` holds the **actually-loaded** selection (after `fitRhythm` may have substituted a pattern), and `backingName(sel)` resolves it live through `L()`: drums-only → the pattern name; jam → `«harmony · rhythm»` (or `· без ударных`), since a jam variant is a combination.

It's a **shortcut, not a mode**: both paths are ordinary looper layers, so the ⚙ panel, undo, and record all work as usual. Jam variants are keyed on **scale properties** (`supportsProgressions`/`supportsChords`, `edo===24` for maqam rhythm), selecting only from existing `HARMONIES`/`RHYTHMS`/`BASS_MODES`. The drums-only variants are `rhythmsForMetre(loop.metre)` — **filtered by metre**, so a person in 7 is offered only «Балканский 7», never rock; a metre with no patterns (5/10/12) **disables** the menu item with the reason instead of opening an empty cycle.

⚠️ **Known inconsistency between the two halves of this one button:** the jam path has a *cultural* gate (it picks by scale properties, so it won't put a backbeat under a raga); the drums-only path has **only** the metre filter, so under a raga in 4/4 it will happily offer rock, disco and hip-hop. That is a defect to resolve, not a design choice — one button should not have two standards of appropriateness. Fix belongs in BACKLOG §3.33 item 1, and must be **property-driven, never name- or index-driven**.

**Both paths go through `loadJam`, so there is ONE flag:** their layers carry `ev.jam` and `clearJam` removes exactly the backing, never player recordings (hard rule #14 unchanged — do NOT add a second flag). Honest consequence: a jam and a drums-only backing cannot coexist — switching paths clears the previous backing, exactly as switching variants does.

### The expression hand — few inputs, a RICH MIDDLE LAYER
Assign a solo hand the **`'expr'`** function («Выразительность») and it plays **no notes at all** — no owner, no pinch meaning, zone `'expr'` short-circuits everything. Instead it feeds a small dynamical system whose output breathes into the solo chain. **The liveness comes from the middle layer, not from the number of inputs** — this is the whole design and must not be "simplified" into direct parameter mapping:

- **Four features off RAW landmarks** (`exprFeatures`, hard rule #12 — `sx`/`sy` are never used here): **energy** (palm-centre speed in palm-sizes/s: position EMA'd *before* differentiating, then the *velocity* smoothed `tauV` *after*), **openness** (mean centre→5 fingertips / palm size), **tilt** (|vertical component| of the palm normal from landmarks 0/5/17, using MediaPipe `.z`), **finger spread** (mean *pairwise* tip distance — deliberately different from openness: a hand can be open-but-pinched or closed-but-fanned).
- **A rich middle layer** (`tickExpr` → `EXPR`): a **pump-and-decay resonator** on energy (`kPump`/`tauE` — moving pumps liveness, standing still lets the tone die), **an inertia spring** (`springF0`/`springZeta`, semi-implicit Euler) on **each** of the four channels giving overshoot-and-settle = "body", and an `engage` crossfade to neutral over `tauEngage` so a hand appearing or leaving never clicks.
- **Four channels → FOUR DIFFERENT AXES** (`applyExpr`, depths in `EXPR_A`): energy → **liveness** (a pitch+amplitude shimmer, `vibHz`), openness → **wah** (a high-Q peaking peak sweeping `wahLo..wahHi` logarithmically), spread → **texture** (morph between a SOFT and a HARD waveshaper — the *character* of the distortion, not its amount, with a lowpass after so it reads "dirtier" not "brighter"), tilt → **space** (delay send). **Why this split is load-bearing:** an earlier arrangement had three of the four channels pushing brightness, and the result felt like *one axis operated four ways*. Brightness was removed as an axis for exactly that reason. Do not re-point two channels at the same perceptual dimension.
- **Volume is NOT one of them.** It belongs entirely to the note hand (`volGain`, X position) — two hands must not fight over one quantity.

### Expression hand — three invariants that are not preferences
1. **The sub-step integrator is mandatory.** `tickExpr` runs the whole dynamics at a fixed `EXPR_CFG.subDt` (~8 ms) no matter how long the frame was. Without it the `springF0=2.5 Hz` spring **self-oscillated at frame rates below ~13 fps** — which is the real desktop rate with synchronous MediaPipe on the main thread — producing a constant 5–8 Hz wobble that had nothing to do with the hand. That was the mystery wobble. The `dtMin`/`dtMax` clamp on the frame `dt` is a separate guard (a stalled frame would otherwise explode the integrators); **it does not give stability — `subDt` does.**
2. **The dead zone is load-bearing.** `smoothstep(v0,v1,x)` returns **exactly 0** below `v0`, and it is applied to the *smoothed* velocity. A resting hand jitters at ~0.05–0.15 palm-sizes/s; without the dead zone that noise crosses into the resonator and the instrument "plays itself". Same for `orDead` on tilt and `sprMin` on spread. A resting hand must give exactly zero.
3. **The only pitch it may touch is a live-only shimmer.** `exprVibPitch` sums into the same `.detune` as vibrato and humanisation, bounded by `EXPR_A.vibCents` (a couple of cents). It is **never recorded** — like the theremin Hz (hard rule #11). Nothing about the expression hand enters an event payload.

Ownership: the **last expression hand that moved** owns the instrument (`exprMoveT`), so two such hands don't fight; the dynamics are state of the INSTRUMENT, not of the hand, so energy continues across an owner change. On screen it is deliberately **not a dashboard**: one «ВЫР» bar (energy) plus the hand-dot hue/size (openness/energy); texture and space are left to be *heard*.

### The tutorial — six lessons as DATA, chained, driven by real actions
`tutor.js` runs lessons **inside the live app** (real camera, real sound, real grid — you learn by doing). `LESSONS` is data: `{id, titleKey, descKey, steps, next, setup?}`; a lesson with `steps:null` renders as «Скоро» and can't start. Steps are data too: `{key, gate?, enter?, done?, final?, reveal?, skipIfDone?}` — `enter(acc)` zeroes exactly the field this step measures (so the previous step's action can't pre-satisfy it), `done(acc)` is a **pure predicate**, and `gate()` drops steps that make no sense in the current scale (chord steps under `supportsChords`, the palette step under `typedChords`). Adding a lesson = adding a record; the engine is not touched.

The six, in `next`-chain order: **basics → chords → tunings → looper → handfn → split**. Progress is a quiet per-lesson ✓ in localStorage (`handsong.lesson.<id>`), never a gate — any lesson can be started in any order. A final step is a CHOICE card («Дальше: <lesson>» / «Готово — играть»), never an auto-jump; `Skip` returns to the list without the ✓.

**Events, one channel.** Everything arrives through `hooks.tutor(kind,payload)`, emitted at the sites of the real actions (every one marked `ЗАЦЕПКА ОБУЧЕНИЯ` in `gestures.js`/`ui.js`/`recorder.js`) — the event exists **iff** the action happened, so nothing is recomputed in parallel and nothing can drift. `apply(kind,p)` folds events into the accumulator generically. ⚠️ **The hooks teach the CURRENT gesture model — change a gesture and you must move its hook with it.**

**Setup must leave the app in a state where the lesson's own steps can complete, whatever the previous lesson did.** This is the rule the found bugs all violated, and each fix is now in `tutorReset`/`setup`:
- **Hand functions bled forward.** «Функции рук»/«Две роли» rewrite `handFn.ld`, and free play rewrites `ch`/`bs`. Basics would then find the left hand *not* on effects, and Chords/Looper would find the chord hand on `hold` instead of `latch` — the latch step could never fire. `tutorReset` now restores **all** of `ld`/`bs`/`ch` to the `state.handFn` defaults.
- **A jam bled onward.** A loop or jam from the Looper lesson kept playing into the next lesson of the chain. `tutorReset` calls `tutorClearLoop()` (the same `clearRec()`+`resetJamDisplay()` as ✕), and the `lpJam` step re-clears so the jam lands on an empty song and is accepted at any metre/scale.
- **The Looper lesson landed on a chordless scale.** Tunings deliberately leaves the player on Пелог (`noChords`); the Looper lesson's overdub step asks for the Chords role, which would have been silent. Its `setup` switches to **`MAJOR_IDX`** (found by `edo:12 && iv==='0,2,4,5,7,9,11'`, not hardcoded). Likewise Chords and Split start on **`CHROMATIC_IDX`** (found by `typedChords==='chrom12'`, the only scale with the full type palette), and Split's setup order matters — scale FIRST, then `tutorSplitInit()`, which falls back to a **bass** right half if the scale has no chords.

**The strip hides itself under a working finger, driven by FOCUS.** With a panel open the strip collapses to one line (`.mini`); while a finger actually works *inside* the panel it fades out entirely (`.hushed`, `pointer-events:none`) and returns ~1.8 s after the finger leaves. The trigger is **`focusin`/`focusout`/`change`, not `pointerdown`/`pointerup`** — a native `<select>` picker swallows `pointerup`, so the pointer-driven version brought the strip back on top of the still-open picker ("it won't hide"). Focus arrives reliably and *stays* while the picker is open, which is exactly the condition wanted. `pointerdown` inside a panel also hushes (scroll/label taps that take no focus).

### Localisation — English default + Russian, and one identifier hazard
`i18n.js` holds `LANGS=['en','ru']` (the mechanism is shaped for four — `es`/`de` are deliberately empty until someone can check the musical terminology; a wrong translation reads to a native speaker as a bug). **Interface strings** live in `DICTS` and come out through `t(key,params)`; the fallback chain is current-language → `en` → `params.def` → **the key itself**, so a missing translation is visible rather than silent. Static markup carries `data-i18n` / `data-i18n-title` and is refreshed by `applyI18n()`; anything JS builds (dropdown options, composed button labels) is redrawn from an `onLangChange` subscriber. The canvas needs nothing — `draw` calls `t()`/`L()` every frame.

**Musical data names are localised INLINE, not in the dictionaries**, and the three shapes encode the editorial decision:
| Shape | Means | Example |
|---|---|---|
| a bare string | international notation, identical in every language | `'SuperSaw'`, `'II–V–I'` |
| `{default, ru}` | a **proper noun** — transliterated, not translated | `{default:'Tabla', ru:'Табла'}` |
| a full `{en, ru, …}` object | a **translatable word** | `{en:'Bell', ru:'Колокол'}` |

`L(field)` resolves any of the three (`lang` → `default` → `en` → `ru` → first value), so a plain string passes straight through.

**THE IDENTIFIER HAZARD, fixed — do not reintroduce it.** A display name is not an identifier. Two places were using one and would have broken the moment the names became objects: `demo.js` matched its scenes to scales by **`s.name`** (now `SCENES[].idx`, a stable index into the append-only `SCALES`), and `ui.fillScales` bucketed the scale menu by the **displayed** `grp` label (now `grpKeyOf(s)` — `s.grpKey` if present, else the raw `grp` — with `L(grp)` used only for the caption, so one group can't split into four by language). **Nothing else may key on a display name.**

### Tutorial strip visibility — `.on` is the ONLY gate
`#tutorBar` is `display:none` by default and `#tutorBar.on{display:block}` shows it. The position classes `.mini` (a panel is open → collapse to one line at the bottom), `.low` (the canvas looper box is up → move the full strip down) and `.hushed` (a finger is working inside an open panel → fade out) are set by `ui.syncTutorBarPos`/`hushStrip` **and must never carry `display`**. ## Conventions

- Terse, comment-heavy, single-letter helpers, compact lines. Match it.
- Add a feature in the module that owns it:
  - a **scale** = one entry in `SCALES`, **appended at the end** (index is `scaleIdx`; `state` and `sameDegrees` depend on it). Menu position is set by `trad`/`grp`, not array position — `fillScales` buckets by `grp` key.
  - a **cents (non-equal) scale** = same, plus a `cents:[...]` array (`length === iv.length`); keep a valid `edo`/`iv` as nominal structure. Home section: `easia`/`india` for world tunings, `europe` «Европа историческая» for the historical 12-note tunings, `exp` for Partch. It may be `noChords` (gamelan/pelog) OR carry `typedChords` with a **ratio** family set (Partch/Pythagorean/Natural — priced by the pure-ratio cents branch) OR `gridChords:true` + an integer-step set (Natural-fixed/meantone/well temperaments — priced by the fixed-grid branch). A **historical fixed tuning** additionally gets **`fixedKey:true`** (tonic = key, absolute-C anchor, real-note-name labels — see "fixedKey"); the C-anchored `cents:[...]` array is the tuning's recipe from C.
  - a **non-octave scale** = a `period:<n>` (`3` tritave, `3/2` fifth…), `edo`/`iv` equal within that period, section `exp` «Эксперименты» (bounded by tuning). `periodOf` carries it through pitch/labels/register — never add a `2` literal. `noChords`, or a **ratio** family set priced by the period branch (BP `'bp'`). `rectGrid` (the layout DEFAULT) only if `(iv.length)%4===0` — the closed form is octave-only, so a non-octave scale gets no `+1`.
  - a **typed-chord family set** = one entry in `CHORD_FAM_SETS` keyed by a scale's `typedChords` value; **integer steps** for an edo/`gridChords` scale, **or plain-number ratios** for a cents/period ratio scale.
  - a **rhythm pattern** = one entry in `RHYTHMS`, **appended at the end** (`ui.js` holds positional indices `JR_BACK=0`/`JR_MAQSUM=1` — never insert in the middle). Declare `beats` and, if the beat is divided in three, `sub:3`; the grid must be exactly `beats*sub` cells or `gridOk` skips the pattern. Write it in **rows** (0 kick/1 snare/2 clap/3 hat), never tuned to one kit.
  - a **timbre/kit** = an entry in `LEAD_INSTR`/`CHORD_INSTR`/`BASS_INSTR`/`DRUM_KITS`.
  - a **gesture/timing threshold** or palette geometry = `config.js`. **Expression-hand numbers are split by side on purpose:** feature→channel (dead zones, smoothing, spring) in `gestures.EXPR_CFG`, channel→depth/range in `audio.EXPR_A` — gestures imports audio, so the reverse would be a cycle.
  - a **hand function** = an entry in `state.handFn` defaults + `ui.HANDFN_OPTS` + a branch on `S.fn`/zone in `gestures.js` + a dictionary key.
  - a **lesson** = one record in `tutor.LESSONS` plus its step records and `tutor.<key>.prompt`/`.detail` dictionary keys; its `setup` must make its own steps completable from any previous lesson. Don't touch the engine.
  - a **user-facing string** = a key in `DICTS.en` **and** `DICTS.ru` (chrome), or an inline `L()`-shaped name next to the data (musical names).
  - a **behaviour gate** = a scale property + a predicate in `scales.js`, never a `tag`/index check.
  - a **path that creates or removes events** (the piano roll IS the third one, and it is written — `editInsertHit`/`editMoveHit`/`editDeleteHit`/`editMoveSeg`/`editResizeSeg`/`editDeleteSeg`) = stamp `tk`, keep `t` in absolute song beats, choose `a.v`/`a.k` that don't collide with what the track stores, remove with `compactEvents`, then call `schedInvalidate` exactly once — sorting first if a take is being recorded (see "Time, tracks and the recorder" and hard rules #27/#28).

## Hard rules — do not break these

1. **AudioContext is created only inside the `#startBtn` click handler.** ⚠️ **An `OfflineAudioContext` is NOT covered by this rule, and that is not a loophole — the rule exists for the autoplay policy, which governs contexts that reach the speakers.** An offline context plays nothing, has nothing to unblock, and is created later, on a deliberate action. Since slice F0 of the freeze arc, `initAudio(mkCtx)` takes an **optional** context factory (defaulted, so the live path is the same line it always was); only `src/render.js` passes it. ⛔ Do not "fix" that branch back — it reads like a breach and is not one.
2. **Never hardcode frequencies, note tables, or the octave `2`.** Pitch derives from `baseF()` and the current (or frozen) scale — `P^(iv/edo)` with `P=periodOf(s)`, or the `cents` overlay `2^(cents/1200)`. A literal `2` in a register/step/period path breaks the non-octave tunings (BP, Carlos) — use `periodOf`.
3. **Pool oscillators start once and never stop** (solo/chord/bass gated by GainNodes; per-hit drums/metronome/drone LFO are the exception). Solo voices and their banks are built **lazily** and then obey the same rule — that is precisely why a voice's banks are **cached and gated**, never torn down and rebuilt: a started oscillator lives until the context dies. ⚠️ **The offline engine copy (`src/render.js`) is a SECOND INSTANCE OF THIS RULE, not an exception to it:** it has its own oscillators, which live exactly as long as its own context, and inside that context the same discipline holds — started once, gated, never disassembled.
4. **The master limiter stays.**
5. **Lower layers never touch the DOM** — `audio.js`, `arrange.js`, `recorder.js` reach the UI only via `hooks`. `draw.js` is exempt.
6. **Live bindings — write state only through its setter**, never a module-level `const`. The looper re-reads `baseF()`/`CUR()`/`chordSteps()` every step.
7. **Per-event scale freeze is the polymodality mechanism** (`sc`/`sev`/`a.ty`, and `cents` rides on the frozen `sc` — including for **chords**: a frozen Partch chord layer replays in just intonation via the `chordFreqs` cents branch on `ev.sc`). ⚠️ **`sc:CUR()` freezes a REFERENCE to the scale object, not an index and not a name.** In memory that is exactly right — replay survives array reordering, renaming and localisation. But **it cannot be serialised, and no scale carries an `id` (0 of 75 entries do)**, so there is currently no way to write down which tuning a layer used. That makes a stable scale id a **hard prerequisite for saving loops and for any user-created tuning** — see BACKLOG §1 «СТАБИЛЬНЫЙ ИДЕНТИФИКАТОР ЛАДА». Don't design either feature around the object reference.
8. **The video draw and `detectForVideo` read the same camera frame** (`drawVideoBackground()` before detect, `drawOverlays()` after, one synchronous tick).
9. **There is ONE layout; never reintroduce a mode gate.** PC/`uiMode` are deleted. New behaviour keys off scale properties and `splitOn`, never a `uiMode`-style global branch. **Hit-test and render must derive geometry from the SAME frozen range** — the hand's `S.role`/`S.rx0`/`S.rx1` (frozen at capture) and the single-source helpers (`phoneHalves` for halves, `palSplitX` for the internal split, `rectBandY`/`rectRows` for bands). Two independent copies of a boundary will drift and the finger takes a different cell than it sees.
10. **The split's role pair stays two distinct roles, at most one mono role.** `SPLIT_ROLES` is mutated only via `cycleHalf`, which skips the other half's role — keeping solo+solo and bass+bass (the single-voice chains) unreachable. Don't add a path that sets both halves to the same role.
11. **Continuous-pitch overrides ride a live-only channel and are NEVER recorded.** The theremin Hz is the named option `live` of `ENG.leadOn` **and `ENG.bassOn`** (every ENG entry has the one shape `(a, ctx, {when, live, own})` since slice S2 — the old positional extras are gone because a time in seconds once could have landed in the Hz slot), passed only by the live `WleadOn`/`WbassOn`; replay never passes it and derives pitch from the frozen `deg/oct` (solo adds its recorded cents curve `a.bend`). Do not fold live Hz into the event payload — for solo or bass. ⚠️ **"Never recorded" is about the EVENT, and the capture is not an event.** Since O-2 the effect values a hand plays ARE written down — into the per-take automation lane beside `events` — and that is not a breach of this rule: the theremin's live Hz is still absent from every payload, while its audible result rides as the frozen step plus `a.bend`. What stays live-only under this rule is the same set as before: the continuous Hz, the per-attack humanisation (fresh at every attack, see the non-determinism limit), and the note layout.
12. **RAW vs REMAPPED coordinates stay separate; the detector always gets the full frame; the picture and the remap share ONE crop.** `detectForVideo` reads the uncropped `<video>`. Gesture math (pinch/hand-size/Z-reverb/FX-drag/thresholds) uses RAW `lm.x`/`lm.y`; on-screen position and hit-testing use `sx`/`sy`. The video is **cover-fitted** (`config.coverView` → `state.viewRect`, written each frame by `drawVideoBackground`) so it never stretches; the SAME `viewRect` is the `drawImage` source rect AND the `sx`/`sy` remap — never let them diverge (the drawn hand would land where the finger is not). Never clamp coordinates or rendering — only the resulting selection saturates. A new `1-x`, a second copy of the crop/remap, or feeding cropped pixels to the detector all break this.
13. **Mirroring has one source.** `camFacing`/`mirrored()`/`flipX` decide it; the video draw and every landmark→screen conversion read them. Never scatter a `1-x`.
14. **`clearJam` deletes only `ev.jam`-flagged events.** The flag is intrinsic to the event so player recordings (never flagged) are safe. Don't switch jam-clearing to layer numbers.
15. **Track events are scheduled AHEAD at explicit times; the `when` option stays.** `scheduleLayers` fires chord/bass/drum events at `loop.t0 + (ev.t + off)*spb` within `SCHED_AHEAD`, where `off` is 0 without repeat and, while the brace cycles, the whole-pass offset of the REGION BOUNDARY the window was split at; live calls default to `AC.currentTime`. Never collapse voice functions back to "fire now" — that reintroduces the main-thread-blocking drift the window fixes (see "Scheduler").
16. **`fixedKey` scales anchor to absolute C; the tonic is a KEY, not a multiplier.** Their `leadFreq`/`bassFreq`/`chordFreqs`/`centsOf` branches read `cFix()`+`fixedSlot`, and labels use real note names. Don't route them through the mobile `baseF()·2^(cents)` path — it would erase the per-key character (C gentle, F# tense) that is the entire lesson. `fixedKey` is a **separate** property from `gridChords`.
17. **The A4 reference has exactly ONE source.** `aRef` (state) feeds `a3()` → both `baseF()` and `cFix()` in scales. Never add a second copy or a per-family reference — mobile and fixed scales must move together, or a `415 vs 440` mismatch surfaces as a "detuned instrument".
18. **In split, hand functions are consulted PER HALF by that half's role; the old fx-hand hardcode is GONE.** `handFnOf(key, h.role)` decides `fx`/`note`/`hold`/`therm`; the default `handFn.ld.L='fx'` *derives* "effects on the left hand in the solo half". Do not reintroduce a hardcoded special case — one source of truth (`handFn`).
19. **Chord voices keep TWO filters; never merge `f` and `fb`.** `f` bakes the attack envelope (timbre, once at attack); `fb` carries continuous brightness (`bd`/`a.bri` expression, `setTargetAtTime` all note). On one node a brightness change would fight the scheduled attack ramp and permanently couple timbre to expression. Brightness lives per-voice (not a shared bus) so per-track isolation holds via the owner key (`'latch'` vs `'loop:'+layer[+':'+k]`) — the live hand can't repaint a replayed track. `a.bri` is recorded from the chord chain's `bright` parameter; there is no separate ЯРК bar any more. ⚠️ **Brightness stays BELOW the summing boundary and must not be "unified" with the serial chain** (O-1): it is `kind:'voice'` — no nodes at all — precisely because the value is read by each voice at its own attack, which is what keeps a replayed track's brightness its own. Everything ABOVE the boundary (reverb, delay, bus tremolo) processes the sum and has no per-note value at all.
20. **The live chord (`'latch'`) survives the REGION BOUNDARY; only the tracks' own voices are released there.** There is no loop wrap any more; the boundary exists only while the brace cycles. At each seam `liveWrapRelease` cuts the live SOLO voices and the live bass (a still-pinched hand re-attacks them next frame) and `releaseLoopLayersAt` releases the track owners (`'loop:'`/`'bassloop:'`/`'leadloop:'`). Never add `chordOff('latch')` there — `chordGlide` can't rebuild deleted voices, so it would cut a held/latched chord that belongs to the hand. ⚠️ Do not confuse this with the RECORDING: since the per-pass closing the recorder WRITES a `chOff` at the pass end and a fresh `chOn` at the pass start for a held chord (`recFoldRoll`). That is events only, never a call on the live voice.
21. **Looper-hand commands fire ONCE, from the pinch-capture block.** `fireLooperCmd` runs only on the `false→true` pinch edge (structural single-fire); held frames take a different branch. The pinched finger is frozen for `'loop'` (and `'hold'`) hands so drift can't fire a second command. Don't move command dispatch into a per-frame branch.
22. **The expression hand's liveness lives in the MIDDLE LAYER; keep the sub-step, the dead zones, and the four distinct axes.** `tickExpr` integrates at a fixed `subDt` (~8 ms) regardless of frame length — remove it and the spring self-oscillates below ~13 fps (the real desktop rate), which was the mystery 5–8 Hz wobble; the `dtMin`/`dtMax` frame clamp is a separate guard and does **not** replace it. `smoothstep` must return exactly 0 below the dead zone or a resting hand's detector noise plays the instrument. The four channels must stay on four **different** perceptual axes (energy→liveness, openness→wah, spread→distortion character, tilt→delay) — three of them once pushed brightness and it felt like one axis operated four ways. Everything reaches the nodes through `setTargetAtTime`, never direct assignment, and every node is identity at neutral. Volume stays with the note hand.
23. **The expression hand never writes to an event.** Its only pitch effect is `exprVibPitch`, a live-only shimmer of a couple of cents summed into `.detune` — same discipline as the theremin Hz (#11). No `a.expr`, ever. ⚠️ **CLARIFIED BY O-2, NOT WEAKENED:** its five OUTPUT scalars (`EXPR_CH` = `live`/`wah`/`text`/`space`/`engage`, snapshotted by `applyExpr` into `exprCur`) ARE captured — under `EXPR_FX='expr'` in the per-take automation LANE, which is not an event, carries no `a.`-anything and never reaches a payload. The rule's letter and its purpose both hold: nothing about the hand enters the event format, while a re-render can still reproduce what it did. Adding a sixth channel means adding it to `EXPR_CH` — never to an event.
24. **`hooks.tutor` is the tutorial's only input, emitted where the action really happens.** Never recompute a lesson's condition in parallel — the event must exist iff the action did. The hooks teach the CURRENT gesture model: change a gesture, move its hook with it. `done(acc)` predicates stay pure (`apply` does all mutation), and **every lesson's `setup` must leave the app able to complete its own steps whatever the previous lesson did** (scale, `handFn` for all four roles, the note layout, and a clean song — see "The tutorial").
25. **A display name is never an identifier.** Musical data names are localised inline (`L()`), so matching on `s.name` or bucketing by a shown `grp` label breaks by language. Use stable indices (`demo.SCENES[].idx`) or stable keys (`grpKeyOf`). This already bit twice; don't make it three.
26. **The note layout is a per-frame CHOICE, resolved once and applied to all three note-roles identically; labels follow the SCALE, not the layout.** Six parts, every one of them a real defect that was waiting to happen:
    - **One resolver, one arithmetic.** `scales.rectGrid()` is the only place the layout is decided (`rectEligible × state.rectPref`, scale property = the `'auto'` default), and **`rectLayout` is the only place the geometry is expressed** — `k`, `dup`, `octaves`, `hasReg`, band counts, all of it. Never re-derive it, never read `s.rectGrid` as if it were the layout, and keep `'auto'` the default — a boolean would carry one scale's layout onto the next. **No literal `4` on the rect path:** notes per rectangle is `k`, the band→rectangle offset is `regBands`, the register count is `REG_N`. A surviving `4` is silently wrong only at `k≠4` — the hardest kind to notice.
    - **The highlight needs the (degree, register) PAIR, never the degree alone, and it is a SET, never one note.** With several periods on screen one degree lives in several rectangles; the register travels beside the degree (`latchOct` / `curChordOct` / the voice's own `deg`/`oct`) and `rectSlotOf` (the inverse of `rectNoteAt`) finds the rectangle. A bare degree lights the lowest block — correct on exactly the scales that worked before, wrong on every multi-octave one. For the same reason the latch identity is (degree + **register** + type). **And since solo went polyphonic the highlight is a `Set`** — `drawGrid`/`drawRectGrid`/`drawThereminLines` all take one, a rectangle lights if *any* of its notes sound, and each sounding finger lights its own legend line (two hands in one rectangle light two). ⛔ Never collapse it back to a single value: it was a single value written in a loop over hands, so the last hand won and the other rectangle stayed dark.
    - **The playing tag lists EVERY note the hand sounds**, Hz and cents each, taken from `leadHold` (same source and same reason as the highlight) and composed with the chord readout's own degradation ladder (`fitLeadNotes` → `packSegs`: all with cents → cents on the first three → Hz only → `…`, never a number cut in half). **One tag per hand, at that hand** — each hand has its own position, volume and chord, and a single combined list would sit beside one hand while describing the other's notes. ⚠️ **With ONE note sounding the old two-line tag is used verbatim**; the multi-note form starts at two.
- **The solo highlight set comes from `audio.leadHold`, not from `HANDS`.** `leadHold` is the register the engine itself uses to decide what sounds, and each voice's `deg`/`oct` are written by `leadOn` — the same call that starts the note, with no second write path — so the picture cannot lag or contradict the sound (the discipline that fixed the chord Hz readout, which reads `chordHold` rather than recomputing). `HANDS` is *intent*: it would keep a rectangle lit after a voice was stolen. **Live hands only** (`'lead:'` prefix) — replayed layers (`'leadloop:…'`) deliberately do **not** light, or a busy loop would set the whole grid glowing and the highlight would stop meaning "what your hands are doing". Bass keeps the old single-value path from `HANDS` because it is **still mono** — do not merge the two branches.
    - **The idle finger must be visible.** Where `k<4` the extra fingers play nothing (never a substitute note); the legend draws them as a dim `—`, and a pinched idle hand still gets a dim ring plus `tag.idleFinger`. Silence with no explanation reads as a bug, and at `k=2` half the hand is idle.
    - **The per-band register marker is load-bearing when `octaves>1`**, not decoration: four identical blocks otherwise give no way to know which octave you are aiming at. Derive it from `rectNoteAt` so it cannot disagree with the sound.
    - **`drawRole` must branch on `rectGrid()` for `ld`/`bs`/`ch` alike, NOT inside the `chTyped` branch.** `gestures`' `rectPlay` keys on the role, so a non-typed chord scale in rectangles would take input by rectangle and draw narrow rows — the finger grabbing a root it cannot see (#9). This was invisible only because every rect scale used to be `typedChords` or `noChords`. For the same reason, everything the palette guards (`gx0`, the `'oct'` band's `octRight`, the hint's `hx0`) is gated on **`typedChords()`**, never on `role==='ch'`.
    - **`draw.noteLbl` is the single label function for both layouts** (grid legend, theremin overlay, play tag, pre-pinch hint). Two functions could only agree while rectangles were confined to scales that all wanted ordinals; split again and the same note reads `C` in rows and `2` in rectangles. Its `edo ∉ {12,24}` clause is load-bearing for 19/31-TET.
    - **The register band exists iff `hasReg` (`octaves < REG_N`)** — one predicate, read by the `'oct'` capture, the draw offset and `thereminSpan`. Miss it in the capture and the bottom *note* rectangle of a 4-octave scale is swallowed as a register band and plays nothing.
    Also: the layout **never enters an event** — it is not frozen on `sc`, and a layer recorded in one layout replays identically in the other (#7/#11 discipline). Use `rectNotes()` (not `IVX().length`) wherever "the notes on the grid" is meant.
27. **A track's identity is its lane id, never its layer number, and `laneNew` is the only writer of `laneId`.** Layer numbers are reused (a new track takes `maxLayer()+1`, which after undo or delete is a number that already lived) and have holes (`clearJam` removes by flag). Everything a person attaches to a track — mute, solo, the arm, a pending delete, and anything later (names, colours, freeze) — must be keyed on the id. `laneNew` always issues a FRESH id and overwrites the number's old one, so correctness comes from the BIRTH of a track, not from cleanup after a dead one (`lanePrune` is hygiene): a skipped cleanup then leaks nothing onto the next track with that number. Keying on the number instead would make a new track silently inherit a dead one's mute — plausible, quiet, and slow to find. The layer number stays what it is: the address of the track's SOUND in the owner keys. Never write the lane id into an event.
28. **The scheduler cursors have ONE rebase point, `schedInvalidate`, and it assumes the array is sorted.** Every path that adds, removes or reorders events, or jumps the time base, calls it — never a scattered `curSched.i=0`. A forgotten call gives missed or doubled notes, not an error, and not immediately. It declares `events[0..length)` the sorted prefix, so a call made while a take is being recorded (whose events are appended unsorted) must sort first. Removal uses `compactEvents` — one in-place pass that keeps the `events` reference `draw` imports; never `splice` in a loop (quadratic on a long song) and never `events = …` (draw would keep the dead array).
29. **Every value that shapes the sound has ONE owner at a time, and is recorded BY DECLARATION.** Three clauses, one law — all three fail SILENTLY, which is why they are here and not in a comment:
    - **CAPTURE WALKS THE DECLARATIONS.** `fxCaptureWalk`/`fxCaptureChain` iterate the chain and then `inst.params`, the descriptors built from `FX_FACTORY`'s `params` spec. Declare a parameter and it is captured, replayed, drawn in the automation lane, labelled and given a default — **the day the effect is written, with nothing to remember**. ⛔ Never add a bespoke capture path for one effect, and never let a value that changes the sound live OUTSIDE the parameter model: it will simply not be recorded, nobody will notice, and a freeze will one day sound wrong for no visible reason. A value that genuinely has no descriptor must be declared as explicitly as the two that already are — the old scalars (one parameter, `FX_AMT`) and the expression hand (`EXPR_CH`).
    - **THE SOUNDING VALUE HAS ONE OWNER AT A TIME:** the HAND while the transport is stopped, the RECORDING while it plays (`fxPlayDrive` is called from `tick` only when `!recording`). ⛔ Never make both live at once: capture and drive hang off the same heartbeat, so the capture would read back what playback just wrote and record its own output in a loop. There is deliberately no third state ("touched it, so I took it over") — editing recorded automation is the EDITOR's job, not a stray touch's.
    - **THE AIM HAS EXACTLY ONE WRITER — THE HAND**, through the single door `gestures.fxParamsOf` (`FX_AIM`, `fxAimSet`/`fxAimGet`). The bars draw the AIM, not the sounding value, so the player can aim a new sound while the loop plays; a parameter the recording governs is MARKED (`fxIsDriven`), not silently hijacked. ⛔ Letting playback write the aim would make the bars lie about the only thing they exist to show — and it reads as a natural "fix", because it is exactly what the code did before O-3.1.

## How to verify a change

No tests. Verification is **manual, in the browser** — do not run node, a server, headless Chrome, or any automated test/git command; that is the user's job.

1. Serve, "▶ Играть", allow camera (light start card; «Обучение» opens the lesson list and a picked lesson starts the app itself). The app **starts in single-role phone** (SOLO full-width, one role button). The top bar auto-hides after ~3.5 s to the role indicator + three record buttons; a tap/mouse-move reveals it; it won't hide with a panel open.
2. Solo/chords/bass/drums roles play; ● records a take, ● again stops; a second take lands on a new track row; ⤺ removes the last take; arrangement drops in from beat 0. Three light/opaque panels open in the same spot at the top (opening one closes the others): «Звукоряд» with the reference pitch, «🎛 Звук» with «Функции рук», «Лупер» with backing length/metre/BPM.
3. Typed chords (Хроматика, 31-TET, 19-TET): left index pinch selects a palette cell; right hand plays; 19-TET pure minor beats less than 12-TET minor; 31-TET `дом7` = 4:5:6:7.
4. Cents scales (Ява и Дальний Восток → Слендро/Пелог): sound UNEVEN (gamelan), octave a clean 2:1, play-tag cents read the real values; gamelan chords show the no-chords hint.
5. Menu **sections (6, by sound)** render in order: Привычное · Ближний Восток · Индия · Ява и Дальний Восток · Европа историческая · Эксперименты. Привычное keeps its `grp` subgroups (Диатоника/Лады/Этнические/Пентатоника-блюз/**Симметричные (whole-tone/octatonics/Messiaen — ordinary 12-TET, they belong here, NOT in Эксперименты)**/Экзотические/…). Европа историческая is its OWN section, flat and chronological (Пифагоров → Натуральный ×2 → Мезотон → Веркмайстер/Валлотти/Кирнбергер). Эксперименты lists only the tunings (19/31-TET, Партч, Болен–Пирс, Карлос). No scale sound changed — only where it sits in the menu.
6. **Split (landscape, `◨`):** the button appears only in landscape; enabling it halves the screen (left/right roles from `SPLIT_ROLES`) with a mid divider. Either hand plays whichever half it pinches; a chord latched in one half keeps ringing while the other half plays solo (two roles sounding at once). Each half sets its **own** register in its own octave band. The two role buttons each cycle соло/аккорды/бас/ударные **skipping the other half's role** (never two-the-same, never two solo / two bass). A **bass** or **drums** half renders and plays inside its half only (drum rows span the half, not the screen). With no solo half the FX bars vanish. Hand functions apply **per half** (a solo/bass half consults its role's `handFn`). Rotating to **portrait** auto-disables split (nothing left ringing) and hides `◨`.
7. Rect model (solo/bass/chords): fat rectangles; Y picks the rectangle, the finger picks 1 of `k` notes/roots; chords keep the left palette with rect roots in the right part. **Single-octave scales keep a bottom «ОКТАВА» band** whose pinch sets a **per-role** sticky register (solo/bass/chords don't share it) — **31-TET (8+1 bands) and Partch (11+1) must be byte-for-byte**, same ordinal labels, same theremin lines. **19-TET and Carlos γ deliberately differ now**: 10+1 bands over **two** octaves, and the band selects a two-octave *window* («окт I–II» … three choices, pinky dim).
8. Partch (Эксперименты): 11-limit JI; solo/bass glide as 11 rectangles; chord role shows the О/У/Диез/Станд. palette; an О7 is a beat-free 4:5:6:7; a recorded Partch chord layer replays in JI.
9. Theremin (now a HAND FUNCTION, «Функции рук» → Терменвокс, solo AND bass): the fine centre-lines appear as an ADDITIVE overlay ON TOP of the normal grid, only when a hand of that role is assigned Терменвокс; pitch glides continuously; the looper still records the nearest step; bass theremin plays an octave-family lower; other functions/roles unchanged.
10. Non-octave (Эксперименты): Bohlen–Pierce solo/bass play in a tritave (register a `3:1` apart), labels read `Т,2,3…` and the register word is `тритава`; BP chords show the 3:5:7/5:7:9/characteristic palette (a 3:5:7 is beat-free). Carlos α/β/γ divide the fifth (register a `3:2` apart, register word `рег.`); **gamma is rect** (5 fat rectangles + register band), alpha/beta are the narrow grid; all three are `noChords`.
11. Historical temperaments (**Европа историческая** section): Pythagorean chords have a sharp third (81/64); Natural-mobile chords are pure from every root; Natural-fixed / meantone / the well temperaments read chords from the fixed grid → some pure, some wolf (meantone concentrates the wolf into one fifth). A/B the same chord across the section. These `fixedKey` scales now show **real note names** (the grid is absolute); mobile cents scales (gamelan/ragas) still show ordinal `Т,2,3…`.
12. Indian (Индийская): the 22-shruti grid sounds UNEVEN (JI, min step 22¢), rows read «свара · имя-шрути» (tonic = «Са · Чхандовати»); ragas read swaras only; all show the no-chords hint in the chord role. `drawStatus` prints «центовый строй · N ступеней», not a fake «N-TET».
13. Camera switch (`🔄`): front camera is mirrored, back is not; the picture and the hand flip together; no second camera → Russian toast, no break.
14. Frame margin + COVER: the camera image looks **natural — no horizontal stretch** — on a wide desktop window and on a phone in both orientations (cover-fit, not stretched-to-fill). At the outermost rectangles the hand runs off the visible edge but tracking survives (the detector still sees the full frame); the on-screen hand and the cell it grabs stay aligned (picture and remap share one `viewRect`). A recorded video clip shows the same un-stretched image (it captures the canvas).
15. Clip/audio (`🎥`/`🎙`): one records canvas+sound, the other sound only; they're mutually exclusive (the other button disables); the file has picture+sound (video) and the buttons return to rest when recording really stops.
16. Backing (`🎵`): a tap from rest opens the two-item chooser (Джем / Только ударные) and the pick starts immediately; **the button names what's playing** (`🥁 Шаффл · 10/12`, ellipsised on a narrow screen, full name in the title) and each change toasts the full name; each further tap switches variant within that path (previous stops, never layers), cycle ends OFF; long-press re-opens the chooser; the drums-only list is filtered by metre (in 7 only «Балканский 7» — no rock) and the item is disabled with a reason on 5/10/12; the chooser keeps the top bar from collapsing; a backing that's cleared/switched never deletes the player's own recorded layers.
17. Hand functions («Функции рук» in the «🎛 Звук» panel): solo, bass, chords AND drums keep separate assignments (switch role and back — they persist); Ноты (с удержанием) holds the note while the hand roams and stops on release, with volume still following X; both solo hands on notes sound independently (no hand-over — solo is polyphonic); the chord role offers Эффекты/Аккорды (защёлка)/Аккорды (с удержанием)/Лупер; drums offer Эффекты/Удары/Лупер; every role offers Эффекты and Лупер.
18. Reference pitch (scale panel, A4): a preset (415 «барочный» … 444 «оркестровый») or free entry clamped 380–480 (nonsense reverts). Choosing 415 lowers everything ~a semitone and **both mobile scales (гамелан, раги) and fixed (Веркмайстер) move together** — intervals in cents stay, Hz drop; the drone follows; 440 is byte-for-byte as before.
19. fixedKey character: on Веркмайстер the solo/bass tag reads the major third ≈390¢ in key C and ≈408¢ in key F# (same instrument, different key); Натуральный (подвижный) still transposes with no character change. Cents show tenths on every scale now, including plain 12-TET.
20. Chord readout: while a live chord sounds, its highlighted rectangle lists each note's Hz + cents-above-root; the numbers match the tuning (Партч О7 → 386/702/969); it disappears when the chord stops; a loop-played chord keeps the plain highlight.
21. Variable metre (loop panel «Размер», only while the song is empty and stopped — the control is disabled otherwise): pick 7 → the metronome accents 3+2+2 and the tick grid groups the same; 16 → four vibhags with a weakened (not silent) third; count-in is one bar at any metre; a drum pattern of a different metre is skipped.
22. Timbres: FM banks «Колокол (глубокий)»/«Металлофон» ring inharmonic with a bright strike over a longer tail; KS banks «Струна»/«Ситар»/… play in tune across the whole range (worklet); if the worklet fails, those slots fall back to plucks with no index shift.
