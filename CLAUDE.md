# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**The app ships as «Handsong»** (renamed from Air Synth 3; the repo folder is still `air-synth-3` and the old name survives only in doc titles). It is a gesture-controlled synthesizer and interactive scales/tunings tutorial that runs entirely in the browser. It uses the webcam + MediaPipe hand tracking to play notes/chords/bass/drums/effects with pinch gestures, synthesizing all sound with the Web Audio API. On top of live play it has a **linear multitrack recorder** (records intent as events in ABSOLUTE song beats onto tracks; a take either creates a track or merges into an armed one; undo removes the last take; an optional bar-quantised repeat brace brings looping back as a marked span — see "Time, tracks and the recorder"; it grew out of a looper, and many names still say `loop`), an **arrangement** system (harmony/rhythm/bass dropped in as frozen tracks), a **track editor** (a full-screen piano roll over the recorded song, with its own undo/redo and an automation lane for the effects), an **expression hand** (a hand that plays no notes and instead breathes into the sound), a **looper hand** (commands by finger), and a **six-lesson interactive tutorial** that runs inside the live app. **Code comments and the musical data names stay Russian; user-facing UI strings are English-first with Russian alongside** — see "Language" and "Localisation".

**The app is split into ES modules under `src/`, loaded via `<script type="module" src="src/main.js">`.** There is no build system, no package.json, no dependencies to install, and no tests — the modules load directly in the browser. `index.html` holds only markup; `style.css` holds all CSS; the only external dependency is `@mediapipe/tasks-vision`, loaded from a CDN via an ES module `import` in `vision.js`. At the repo root there are also **`manifest.json`** and **`sw.js`** — the PWA install pair (see "Publication & PWA").

**One control model (PC mode is gone).** The screen is a single vertical layout: **one role fills the whole screen** (`phoneInstr`, cycled by the role button). In **landscape** an optional **split** (`splitOn`) puts **two roles side by side** — the screen halves, each half is one instrument. **Role is decided by ZONE** (which half a hand pinches in — either hand plays whichever half it lands in), and **work inside a half is by POSITION** (the chord palette is position-only). **There is NO hand-keyed exception left anywhere**: `handRole` is deleted, and "effects on the left hand in the solo half" is now *derived* from the default `handFn.ld.L='fx'` (hard rule #18). There is no more `uiMode`, no `pc`/`phone` toggle, no `drawPC` — the old three-column PC layout and everything unique to it were deleted; the split covers PC's one real capability (two roles at once) and does strictly more.

- **⛳ FROZEN TRACKS — a playback MODE, in `recorder.js` (freeze slice F4).** While a track is frozen the transport plays **its buffer instead of its events**; the events are never discarded, which is the defining constraint of the whole arc and the reason the editor exists. Unfreezing drops the buffer and the track plays its events again — instant and lossless. **⛔ The registry is keyed by the LANE ID, never the layer number** (rule #27: numbers are reused and have holes, so a new track would silently inherit a dead one's buffer), and it is **never written into an event** (rule #28: it is not in `events`, and it touches neither the cursors nor `schedInvalidate`). Both replay paths skip a frozen layer's events — `scheduleLayers` and `fireNear` — and `chasePlay` skips it too, because **a buffer source takes an offset, so entering mid-note plays from the middle of the sample: the chase, for free.** ⚠️ **A buffer source is one-shot**, so a new node is created at every transport start, seek and repeat pass; this is the same sanctioned exception hard rule #3 already makes for per-hit drums and the metronome (nothing is *gated off* — a node is created, plays and is gone), only "per start" rather than "per hit". ⛳ **At a repeat seam at most TWO nodes are alive per track:** the incoming pass starts while the outgoing one keeps playing **its tail** over it — the tail is overlapped, never folded, exactly as live voice releases ring through a seam. ⚠️ Honest boundary: the buffer's tail exists only *after the end of the material*, so when the brace reaches the material end (the default — it follows the material) the overlap is the true tail; when the brace is a mid-song span, what follows the seam in the buffer is the *next music*, not tail, so that node is faded out over ~6 ms instead. Mute and solo are **one assignment on the track's own bus gain** (`makeFrozenBus` — straight into `master`, because the chain is already baked into the buffer and must not be applied twice), driven from `laneHush`, since a frozen track has no events for the scheduler's per-event audibility check to see. Stops go through the doors that already exist: `softAllOff` (panic, pause — ⚠️ **only when the transport is stopped**: ui calls `softAllOff` from ~17 places while playing, e.g. on every tonic change, and stopping the buffers there pre-empted the scheduler's hand-over and left a sustained track silent until its next note-on; ⛳ since A2c, while playing it also stops only the LIVE owners — `'lead:*'`, `'latch'`, `'bass'`/`'bass:*'` (everything `isTrackOwner` rejects) — and hands every event-played TRACK over with `trackResplice`: release at the horizon, then the same `chasePlay`, so a held track note survives a tonic/scale/A4 change (and any other of those ~17 calls) at the new pitch; a track whose events were removed is cut now; while recording `recAllOff` still closes the take first), `stopAtEnd`, `seekTo`, `startTransport`; buffers are dropped with their tracks in `lanePrune` and `laneReset`. ⛳ **BOTH SPLICES — into the buffer (A2) and out of it (A2b) — are made by the SCHEDULER, at the start of its segment `lo` (time T = t0+(lo+pass offset)·spb, the horizon), never "now".** Each segment asks one question per frozen track: *should the buffer or the events own this track now?* **Leaving** (`frzLeave`, checked BEFORE the segment's event loop) covers all three exits with one path — stale from an edit (recording into it, undoing a take), stale from tonic/A4/tempo, and an unfreeze while playing (which only MARKS the entry `drop`: `freezeState` reads `'none'` at once, and the registry entry is retired after the splice by `frzNearDone`, or by any stop). The buffer plays up to T and fades with `FRZ_FADE` (a node already past `endSec`, i.e. playing only the chain's tail, is left to ring); **the chase** — `chasePlay(lo, T, lead, only)`, the same one used for entering the song after beat 0, with a new optional one-layer filter — reopens the track's held chord, bass and solo at T in the live tonic; the scheduler's ordinary pass schedules its events from `lo`. The drums inside the look-ahead window are not lost and nothing is re-laid: that window was the buffer's, and the buffer plays it out; **cursors are not touched at all** (rule #28 holds without a call). **Entering** (`frzEnter`, before arming, only when events owned the track in this run — `f.evRun`: frozen while playing, or fresh again after going stale) releases the track's chord/bass voices at T (`releaseLoopLayersAt(T, layer, 'pool')`; the release's `cancelScheduledValues` also removes attacks queued after T); drum hits queued in the window lie before T, so nothing doubles; `freezeSet` itself only registers the entry. ⛔ Only the TRACK's voices (rule #20). **Only that track is armed** — the old `frzArmAll` restarted every frozen track and is gone. Solo and drone fire "now" through `fireNear`, so the entry carries a splice mark `f.mark = {kind, rep, beat, at}` compared as the PAIR (pass number, song beat) — `fireNear` takes the pass number — because a wall-clock comparison would double or drop a note at the tick crossing T, and under a cycling brace the horizon can already be in the NEXT pass; `FRZ_MARK_GRACE` clears a mark whose time has passed in case the brace changed meanwhile. The drone is sounded live only for audible, NOT-fresh-frozen layers (`droneAudible`/`droneSync`) and switches in 20 ms at a splice (`droneOn`/`droneOff` take an optional time constant, defaults unchanged). A retired entry's bus is disconnected after a short delay (`frzRetire`) so the fade is not cut. ⚠️ **Named limits:** reverb/delay tails of notes before a leave-splice lived in the buffer and are not in the live chain — the track's "room" restarts at the splice; and while tracks fall back to events (e.g. every frozen track after a tonic change, until re-rendered) they play through the LIVE pools (`CHORD_POOL_N` 24, `BASS_POOL_N` 12 since P1 — it was 4, `LEAD_POOL_N` 12), so beyond that polyphony voices are stolen — the very limit freeze exists to lift. ⛳ **STALENESS (slice F5) — editing a frozen track is NEVER refused; the buffer goes STALE instead**, because the whole point of the editor is to move a note and re-freeze. `freezeSig(layer)` is a cheap string in the shape of `fxPlaySignature` (⛳ follow it, do not invent a second mechanism): the track's **event count, first beat, last beat and the SUM of its beats** (the sum is what catches a note *moved* inside the track, where count and edges are unchanged), plus **the track's own edit version `laneEditVer`** (keyed by lane id, bumped by every editor note or automation edit of THAT track — since A2; it replaced the global `takeFxVer`, which staled every frozen track on any edit anywhere: "unfreeze one, all unfreeze"), plus **tonic, A4 and tempo** (they change every track's sound), plus the pinned **fallbacks** — scale, seventh and the three instrument indices — **only when the track has an event that reads them** (an event without `sc`, an `…On` without `a.inst`); otherwise changing the live timbre would stale every frozen track for nothing. ⛳ **Since T0 it also folds the track's own TIMBRES** — `a.inst` of every `leadOn`/`chOn`/`bassOn`, of every solo `leadSet` that carries one (replay plays it), and `a.kit` of every hit, in event order — so a future timbre replacement stales a frozen track by content, not by luck; live indices never enter that fold, so the panel's timbre selector does not stale anything. ⚠️ The timbre fold (`tmix` inside `freezeSig`) packs each id as a small integer (`|0`, "indices < 63"): it is correct for today's built-in indices and must be rewritten when stable timbre ids arrive — a string id would fold to 0 and two different timbres would sign alike (the code comment beside `tmix` now says so). ⚠️ The signature does not fold per-note effect values (`a.fx`, `a.bri`) directly; an edit of them goes through the editor and bumps `laneEditVer`, which is what stales the buffer. ⛳ **Since T5 a timbre replacement in the editor changes this fold AND bumps the lane's edit version**, so a replaced frozen track goes stale. ⛳ **A1 — THE SIGNATURE IS MEMOISED PER TRACK** (`frzSigMemo`: layer → signature), because `freezeState` is called by DRAW for every strip row every frame and the signature walks all events. The whole map is cleared when the NON-per-track part of the key changes — **`frzGlobalKey()`** = event count + **`evGen`** + `takeFxVer` + the pinned fields (tonic, A4, scale, seventh, tempo, the three live instrument indices). `evGen` is a counter bumped ONLY by `schedInvalidate`; it exists because the event count alone misses "removed N and added N" (a backing swapped for one of the same size). `frzGlobalKey` is exported as the cheap "could any signature have changed" signal for the automatic-freeze watcher (A3/A4) — ⚠️ **it has no caller yet**; neither the queue nor the watcher exists in code, and none of the `FRZ_SETTLE_MS`/`FRZ_CALM_MS`/… constants named in HANDOFF's plan exist in `config.js`. ⛔ **Mute and solo are deliberately excluded** — they change whether a track is heard, not what it sounds like, and including them would mark a track stale on every tap of M. ⚠️ Other tracks' events are also excluded, although another take on the same role drives the same chain (limits #1–2): otherwise recording anywhere would stale every frozen track at once. **⛔ The gate is on "frozen AND FRESH", never on "frozen"** — `frzLayer` *is* `freezeState(layer)==='fresh'`, so both replay paths and the chase fall back to the events automatically, with no separate "but if stale" branch; a stale track's sources are stopped in the scheduler rather than left ringing. The control is **one ❄ button in the editor's bar** doing three things by state (freeze / re-freeze / unfreeze) — ⛔ not on the looper row, which already carries three controls and a label in sixteen pixels; the row gets only an **indicator**, drawn from the same `loopView` snapshot (rule #9): blue ❄ fresh, orange ❄ with a dot stale, nothing otherwise. ⚠️ **Progress is real where `OfflineAudioContext.suspend` exists** (twenty stops give a true fraction) and **honestly indeterminate where it does not** — ⛔ never a fabricated percentage. ⚠️ **The render cannot be cancelled** — `startRendering` has no abort, and dropping the promise would not return the CPU — so there is no cancel button; pressing ❄ again during the wait says so. ⛳ The **one-time notice** fires at freeze for a track whose take has no capture (editor-inserted notes): one is created from the live chain and the track stops following the live controls from that moment — a real behaviour change that used to happen silently in two places. Freezing is reached **from inside the editor**, which is not a UI preference: `rollOpen` already suspends camera detection, so the main thread is free for the render.

- `src/scales.js` — the teaching layer: `TRADITIONS` (**6, reorganised by SOUND not mechanism**: `common` «Привычное» / `mideast` «Ближний Восток» / `india` «Индия» / `easia` «Ява и Дальний Восток» / `europe` «Европа историческая» / `exp` «Эксперименты» — see "Menu sections"), `SCALES` (**75 entries, indices 0..74** — the tail adds the three well temperaments; **the array order and every index are UNCHANGED — only each entry's `trad`/`grp` text moved**), `scalesOfTrad`/`tradOfScale`, **the reference-pitch anchor** `a3()=aRef/2` feeding both **`baseF()`** (tonic pitch) and **`cFix(s)`** (the anchor pitch of a `fixedKey` grid — since P1 of "tuned from" it is the equal-tempered pitch of the scale's anchor note `anchorOf(s)`, taken an octave down if the anchor lies above the tonic, and `keyOf(s)` = tonic − anchor is the key offset every `fixedKey` branch reads; today `anchorOf` is C for all six, so every formula is byte-for-byte the old one) — one source, so world and historical scales re-tune together (see "Reference pitch"); **`tonicFreq(s)`** (fixed keynote for `fixedKey`, else `baseF()`, used by the drone), **`periodOf(s)=s.period||2`** (interval of equivalence — octave by default, tritave for BP, fifth for Carlos), `leadFreq`/`bassFreq`/`chordFreqs`/`centsOf` (all generalized from a hardcoded `2` to `P=periodOf`, and all with a `fixedKey` branch — see "fixedKey"), `ruleChordSteps` (untyped chords by the mode's rule; the tag-based `chordSteps` moved to the probe in T4c-2), chord/row labels, **`regWord`** (register noun by period: 2→`окт`, 3→`тритава`, else `рег.`), **`swaraLbl`** (Indian sargam label: `SWARA_OF`+`SHRUTI_OF` cents tables → «свара · имя-шрути» for the full 22-shruti grid, swara-only for ragas; gated by the `swaraNames`/`swaraFull` properties), and the typed-chord tables (`CHORD_FAM_SETS`, `chordFams`, `rootName`). `chordFreqs` has **four branches in a fixed gate order** (see "Chord pricing" below). Smooth automation segments reach it through `REC.fxLaneExpand(REC.fxLaneMerge(), SCHED_TICK_MS/1000/spb)` — the same line law and the same 25 ms steps as the live tick, each value through the effect's setter at its beat (per-note smooth segments need nothing here: they are ordinary change events). It **taps `master`, not `limiter`** (`offlineTapMaster`, guarded by `offline`): a track rendered alone would otherwise be compressed alone and compressed again in the mix. ⛳ **`offlineTapMaster` also sets the copy's `master` gain to 1:** the buffer reaches the live mix through `makeFrozenBus` → the LIVE `master` (×0.8), the same place an event-played track's role sum arrives, so leaving 0.8 in the render too applied master gain twice and a frozen track played ~1.9 dB quieter than itself (fixed for every role). The **tail is computed from the captured chain** (reverb `decay` is RT60; delay is `time · ln1000/ln(1/fb)`; plus the longest release of the instruments the track used) via `fxDenormOf`, before the context is sized — from the **largest** value each address takes over the whole track, not only at its start, so a reverb added or lengthened mid-take still rings out inside the buffer. ⛳ **The render follows chain changes made during a take (by gating, not rewiring).** Before, it took the composition at the track's start and skipped every later change, while playback applied them on time: an effect removed mid-take kept sounding in the frozen track, and one added mid-take was built at layout and sounded from the very start on defaults. Now `mergeOrders` folds every composition the track ever had into one wiring order, `fxRenderPath` wires all of those effects once (the start composition open, the rest gated shut — a closed module is identity), and each later composition point opens or closes gates at its recorded beat through `fxGateAt`; an effect added mid-take has its first recorded values set while still closed, so it enters at its beat already on them. ⛔ The live chain is read nowhere in the render: every owner key of the copy gets its own explicit path (empty for roles not in the track), and a track without a capture renders with an EMPTY chain — which is why `freeze` (console and ❄ alike) first calls `REC.freezePinCaptures`, so every frozen track has a capture. The one thing gating cannot express is a genuine reorder of two already-wired effects (see Known limits); the report flags it (`reordered`). ⛳ The same fix closed an older defect: the copy's `initAudio` builds the solo reverb and delay and the chord reverb OPEN, and nothing used to close an effect that was in neither the capture nor the live chain — a solo take recorded with no reverb or delay froze WITH echo and room; `fxPlayPath` now closes every built effect not in the new composition. Touches no DOM (rule #5). **Tracks do render** (F3), play through the transport as frozen buffers (F4) and are frozen from the editor's ❄ (F5); no whole SONG is rendered yet (that is audio export). **A0** times the synchronous LAYOUT pass on its own (`layoutMs` — the only part that blocks the main thread; the DSP runs off it) and reports pool GROWTH, not pool size. **A2:** `freeze` takes a ticket (`REC.freezeTicket` — signature + lane id) BEFORE rendering and `freezeSet` refuses the buffer if either moved; `unpinLive` restores only fields that still hold the pinned value, so a tonic/scale change made during a render is never reverted behind the menu's back. The plan for automatic freeze, and the user's decisions around it, are in HANDOFF, arc «АВТОЗАМОРОЗКА».

Stale names to ignore if seen: `backing.js`, `playRec`, `toggleRec`, `stopRec`, `recStart`, `drawChordSectors`, `sectHyst`, `S.sect`, `TYPED_CH_VOL`; **and (PC-removal) `uiMode`/`setUiMode`, `drawPC`, `drawBar`, `zoneAt`, `zoneX`, `FXW`/`ZB`, `modeBtn`, `applyMode`, the `.phone` body class**; **and `#modeHint`, `#arrHint`, the panel help/textbook button (`#helpBtn`)**; **and (hand-functions/reference-pitch/metre rounds) `swapHands`/`setSwapHands`, the global `theremin`/`setTheremin` toggle, `thereminBtn`/`applyTheremin`, `swapBtn`/`applySwap`, `drawThereminGrid`, and `BEATS_PER_BAR` as a hard constant (now just the seed for the live `loop.metre`)**; **and `handRole` (deleted — no handedness→role binding is left anywhere), `jamStep`/`applyJam`/`jamTo` (now `backingMode`/`backingStep`/`applyBacking`/`backingTo`), and the `jam.label`/`jam.title.*` dictionary keys (now `backing.*`)**; **and (the recorder arc) `loop.first`, the unconditional loop wrap, `setRegion` (now `setRegionOn` + the brace), the `takeEv` WeakSet (now `ev.tk`), `inPB` as a recording gate; and (effects work) `revDisp`/`setRevDisp`, `chBrightDisp`/`setChBrightDisp`, `drawChordBright`, `verb`/`verbOut`/`revLead`/`revCh`, `leadOwner`; **and (the ownership arc O-0…O-4) `fxAttach`, `fxRoleBus`, `fxRoleOut` and the three attachment kinds (now ONE serial path via `fxChainIO`/`fxResplice`), `roleXDriven` (now `chainXDriven(key)`), role-keyed `fxChains`/`FX_INST` (now keyed by the opaque chain key), the `attach` flag on `reverb:mix`/`dly:mix` (per-note sends are gone) and the `'reverb:mix'`/`'dly:mix'` keys as anything `applyFx` reads**; **and (the voice-modes branch and the freeze fixes) `bassOwner` (now `monoOwner[role]`), `soloNoteHand` (now `noteHandRole`), the per-voice `dlySend`/`revSend`, and `RELEASE_TAILS` as a live rule (the offline allocator now frees a voice at its release)** — all removed/replaced.

## Architecture

The render loop lives in `main.js`. Each frame: draw the video → MediaPipe detects hands → `processHands()` updates the gesture state machine and drives audio → `drawOverlays()` renders. The recorder thins the ~60/sec engine calls into a few intent events per note.

### Screen model — one layout, optional split
- **Single role (default):** one role fills the screen (`phoneInstr` = `'ld'/'ch'/'bs'/'dr'`, cycled by the role button `instrBtn`). What each hand does in a **solo/bass** role comes from the **hand-function table `handFn`** (see "Hand functions"): the default `ld:{L:'fx',R:'note'}` reproduces the old "left=effects, right=notes" without a `swapHands` flag. The chord-type palette is **position-only** here too (same gate as split) — no hand is bound to it.
- **Split (`splitOn`, landscape only):** the screen halves — **left half = `SPLIT_ROLES[0]`, right half = `SPLIT_ROLES[1]`** (each cycled by its own button, `instrBtnL`/`instrBtnR`). **ZONE = INSTRUMENT:** either hand plays whichever half it pinched in. Inside a half everything is by **POSITION** — the chord palette is position-only (thumb+index left of the half's `palSplitX`). **Hand functions apply PER HALF, keyed by that half's role** (`handFnOf(key, h.role)`) — a `ld`/`bs` half behaves exactly like single-role (effects/hold/theremin all available); a `ch`/`dr` half ignores `handFn`. There is **no hardcoded "effects on the left hand in the solo half" special case anymore** — the default `handFn.ld.L='fx'` *derives* it (see hard rule). Each half has its **own** octave/register rectangle writing ITS role's register (`setRectOctReg(S.role,…)`).
- **Frozen at capture:** at pinch the hand's role + X-range are frozen onto `S` (`S.role`/`S.rx0`/`S.rx1`) from the half `px` lands in; play and draw then read that frozen range, so hit-test and render never drift. **Single-source geometry:** halves from `phoneHalves(W)`, the internal palette split from `palSplitX(rx0,rx1)`, bands from `rectBandY`/`rectRows` — each computed **once** and shared by gestures and draw.
- **Skip-in-cycle invariant:** `cycleHalf` never sets a half to the role the other half holds, so the pair is **always two different roles** → duplicate halves are impossible and the mono-voice chains (**solo and bass are single-voice**) can never appear twice. Two solo (or two bass) halves would fight over one voice; the invariant makes that unreachable by construction.
- **Landscape gate:** `canSplit()=innerWidth>innerHeight`. `splitBtn` shows only in landscape; rotating to portrait with split on **auto-disables** it (`softAllOff`, nothing left ringing) and does not auto-re-enable.

### Gesture model
- **Pinch** = thumb (4) near a fingertip (8/12/16/20), normalized by hand size. The pinched finger (`S.oct`) selects the **octave register** (index=I … pinky=IV), switchable mid-pinch to glide — **except in the rect model** (below), where it selects the note-in-rectangle and the octave comes from the octave rectangle.
- **Multi-finger pinch (a melodic role in the POLYPHONIC voice mode — solo by default, bass when switched):** several fingers may touch the thumb at once and **each sounds its own note** — up to four per hand, eight across two, i.e. chords built by the fingers. `touchedFingers()` returns the whole set with the *same* `PINCH_ON`/`PINCH_OFF` hysteresis one finger always had; `S.order` keeps the order of engagement so the **first-pressed finger stays primary** (position, zone, volume and the depth are read from it — a hand has one position, and all its notes live in one rectangle). Per-finger: `S.fing[f] = {deg,oct,slot}` and one pool voice each, via the finger-aware owner key. The ceiling is **`state.pinchFingers`** (1..4, panel «Пальцев в руке»); **`1` restores today exactly**, including the mid-pinch nearest-finger switch. ⚠️ At ceiling 1 (and for the theremin) the owner key carries **no finger number** — otherwise the mid-pinch switch would become note-off + note-on instead of the 20 ms glide it has always been. **In the LEAD voice mode the role sounds one note** however many fingers touch: the nearest finger wins, a finger change glides the one voice, and since V3 the first frame of a multi-finger pinch already takes the nearest finger (it used to attack the lowest-numbered one and slide a frame later). **Chords and drums stay single-finger** (one root, one row). The ceiling is ONE number for solo and bass (the user's decision). **Theremin is one note per hand by design:** pitch there comes from the hand's *vertical position* and the finger selects nothing, so extra fingers would only produce unisons — inventing an offset per finger would be invention, not an instrument. **Hold works per finger** for free: each finger's record freezes on its own first frame and stops when *its* fingers part.
- **The ceiling is settled at 4, and the temporary pinch diagnostic is GONE.** `pinchFingers` defaults to **4** — the intent is that closing all four fingers on each thumb sounds all eight notes. The temporary measuring tool that decided it — an on-canvas readout of every finger's live pinch ratio against the ON/OFF thresholds, plus its panel row and dictionary key — has been **deleted** as this file required; don't reintroduce it. The caution lives in the *control* instead: fingers occlude each other and MediaPipe partly *infers* the far ones, so if the ring or little finger fires falsely, lower the ceiling in «Пальцев в руке».
- **Y** = scale degree (`degHyst`); **X** = volume (0 at the far left = silence on every role, 1 at the far right = the old full level; heard through the one curve `v²`, VOL-2b), mapped over the hand's frozen range — `[palSplitX(rx0,rx1), rx1]` in a typed-chord role, else `[rx0, rx1]` — by default; since VOL-2 volume is the chain's **Volume** entry and can be moved to a finger or set Fixed, and any other parameter placed on `play:x` moves TOGETHER with volume (the old rule "X given to an effect freezes the volume" is gone); **Z** = the playing hand's depth (`dist(lm[0],lm[9])`, calibrated by `config.REV_NEAR`/`REV_RANGE` — the names are historical) — an **address** (`play:z`) that any chain parameter can subscribe to; by default the chord chain's brightness listens to it; since VOL-4 volume can too (per hand; nearer = quieter, `inv` flips it), and two parameters on depth move together. A held note follows depth while the hand pinches, exactly as it follows Horizontal; a latched chord with open fingers does not. The reverb no longer follows the playing hand (effects Plast 3.1).

### Camera frame margin — COVER fit + two coordinate roles (RAW vs REMAPPED)
The camera frame has its own aspect (usually 4:3); the canvas has the window's. Painting one onto the other without matching aspects **stretched** the picture (horizontally on a wide desktop). **`config.coverView(vw,vh,W,H)` fixes it:** it returns the centered sub-rectangle of the frame `{ax0,ax1,ay0,ay1}` whose **pixel aspect equals the canvas** (COVER — fills, no bars, crops the overflow, no distortion), then insets it by `CAM_MARGIN` on both axes. `drawVideoBackground` computes it **once per frame**, uses it as the `drawImage` source rect, AND writes it to `state.viewRect` — so the SAME sub-rectangle drives the picture and the coordinate remap. If the two diverged the drawn hand would sit where the finger is not. We still **display and play only the inner region**, while MediaPipe keeps receiving the **FULL** frame (`detectForVideo(video)` is never cropped) — a hand at the outermost rectangles travels off the visible edge while the camera still sees it. `remapAxis(v)=(v-M)/(1-2M)` stays exported as the **aspect-equal special case** (the default `viewRect` before video is ready is exactly `[M,1-M]²`, so pre-video `sx`/`sy` are byte-for-byte the old formula). **Two coordinate roles are kept strictly separate (hard rule):**
- **RAW full-frame coords** (untouched `lm.x`/`lm.y`, 0..1) drive **all gesture math** — pinch distance (`pinchRatios`), hand size (`dist(lm[0],lm[9])`), the Z-reverb depth, the FX vertical drag, every threshold — so a pinch still registers when the hand is partly off-screen.
- **REMAPPED coords** — `sx(nx,W)`/`sy(ny,H)` (state.js, single source for gestures hit-test AND draw) remap `flipX(nx)`/`ny` through `viewRect`'s per-axis ranges — drive **only** on-screen position and hit-testing (which half/rectangle/zone, the volume X, the drawn hand). `viewRect` is symmetric in X about 0.5 so it commutes with `flipX`.
- **Coordinates and rendering are never clamped** — a hand in the margin runs off the visible edge (that's the point). Only the resulting **selection** saturates (there is no rectangle beyond the outermost; a margin pinch's half is clamped to the nearest edge so it can't fall into the wrong half). The video crop and the remap read the same `viewRect`, so picture and hand stay aligned.
- **Margin outcome (cover eats into the safety margin — measured, not raised):** the inset is applied on top of cover, so the canvas's **long axis keeps a full `CAM_MARGIN` (~12%)** and the cover-cropped axis gains **more** (e.g. wide 16:9 desktop with a 4:3 sensor: ~12% X, ~21% Y). No axis drops below 12%, so `CAM_MARGIN` was NOT raised. The real cost is on a **portrait phone with a landscape sensor**, where cover shows only the central vertical strip of the frame (inherent to cover — the alternative is letterbox bars).

### Camera switching & mirroring
`camFacing` + `mirrored()` + `flipX` (state.js) are the **single source** of "do we mirror". Front camera (`'user'`) is mirrored (you see yourself as in a mirror); back camera (`'environment'`) is not. Both the video draw (`drawVideoBackground`) and every landmark→screen conversion read `flipX`/`sx`, so picture and hit-test flip together. `🔄` re-acquires the stream on the SAME `<video>` (landmarker not recreated); a failure rolls back to the previous camera and shows a Russian toast.

### Which hand is the playing hand for depth (formerly "the solo note hand", before that "Reverb aim under split")
The reverb preview `revDisp` is **DELETED** — the reverb left the playing hand in effects Plast 3.1, and there is nothing to aim before a pinch any more. What survives is the rule for WHICH hand's depth drives the chain parameters subscribed to `play:z`: **`noteHandRole(key,S,W)`** (gestures) — it replaced `soloNoteHand` when brightness reached every role — returns the hand's role when that role is solo, bass or drums AND the hand plays notes (`playsNotes(handFnOf(…))`), else null; the depth then writes into THAT role's chain. Chords are excluded on purpose: their depth is driven inside the chord branch, under the pinch, as it always was. ⛳ **Depth is smoothed exactly ONCE per hand per frame (VOL-4):** the only `emaS(S,'hs',…)` call in `gestures.js` is inside **`depthOf(S,lm)`**, which memoises the frame's value in `S.hsF`; that field is cleared in ONE place — where `processHands` begins a hand (beside `S.seen=now`), and a hand is processed once per frame. All four readers — the effects hand's own `z` axis, the chord branch, this depth block and volume on depth (`noteVolOf`) — go through it (`depthN` = the normalised `0` near … `1` far), so whoever asks first takes the one step and the rest read the same value. Volume on Horizontal never asks, so with defaults the smoothing sequence is unchanged. Both depth loops skip the Volume entry: volume on depth is per hand, like volume on Horizontal, and never written into the role's shared value. The role comes from `handHalfRole`: single-role `phoneInstr`; split — the hand's frozen `S.role` when pinched, else the live half under `lm[8]` via `phoneHalves`. With no playing hand in frame nothing is written — the parameter holds its last value, because this is sound, not a display, and a snap to zero would be heard. (Before this, the menu offered «playing hand → depth» to bass and drums and nothing drove it.)

### Rect model — "4 notes per rectangle" (SOLO, BASS, CHORDS; now a SWITCHABLE layout, not a scale property)
The note grid is either N narrow rows or **fat rectangles**: `rects` note rectangles + a register rectangle **only where one is needed** = `bands` in total. Band pixel geometry is single-sourced in `rectBandY` (config) and **every count in `rectLayout` (scales)**; gestures' hit-test (`degHyst` on `bands`) and draw partition H the same way, so finger and screen never drift. **Y selects the rectangle** (band); the pinched **finger = 1 of `k` notes/roots** inside it (slot `g = rect*k + finger`, then `rectNoteAt(g,base)`), and where several periods are on screen the band also carries the octave.

**The layout is STATE the person switches** (`state.rectPref`: `'auto' | 'rect' | 'rows'`, default `'auto'`), and the scale's `rectGrid` property is now only its **DEFAULT** ("what the scale opens as"). One resolver decides, `scales.rectGrid(s) = rectEligible(s) && (rectPref==='auto' ? !!s.rectGrid : rectPref==='rect')` — eligibility is folded in, so a data typo can no longer produce a fractional grid. `'auto'` **must stay the default**: a plain boolean seeded from the first scale would carry Partch's rectangles onto major at the next scale change.

**The arithmetic — ONE function, `rectLayout(s)`** (memoised on the scale reference). Two things are variable, not fixed:
- **`k` = notes per rectangle**, the first of `[4,3,2]` that divides; within each `k`, `dup=0` is tried before `dup=1`. Fingers beyond `k` are **idle** — they play nothing (never a substitute note) and are drawn as a dim `—` line.
- **`dup` = 0|1**, whether the tonic is **repeated at the period boundary**. Its purpose is **alignment**, not equivalence: with `dup=1` a period occupies a whole number of rectangles, so the hand always knows where it is. ⚠️ **The old `periodOf===2` gate on `dup` is deliberately GONE** — without it Bohlen–Pierce (13, prime) and Carlos beta (11, prime) could not be laid out at all. `periodOf`'s pitch meaning is untouched. Honest caveat recorded in the code: the duplicated slot is labelled `Т`, which is **true for BP** (the tritave is its equivalence) and an **overstatement for Carlos** (her fifth is a generator, no equivalence exists); accepted for now, an `equiv:false` property later if it grates.

Derived, all from the one object: `block=iv.length+dup`, `perOct=block/k`, **`octaves=clamp(floor(RECT_MAX/perOct),1,REG_N)`**, `rects=perOct*octaves`, **`hasReg=octaves<REG_N`**, `regBands=hasReg?1:0`, `bands`, `notes=rects*k`. **`REG_N=OCT_ROMAN.length`** is not an arbitrary 4 — it is the register count, which is *why* a grid showing all `REG_N` periods loses no pitch. `RECT_MAX=12`. Wrappers keep the old names (`rectRows`→`rects` — **meaning changed: all octaves, not one**; `rectRowsFull`→`bands`; `rectNotes`→`notes`).

**Every scale is now eligible** (even counts divide at `k=2`; odd ones at `k=2,dup=1`), so `rectEligible` can never fail and the panel's "unavailable, because…" branch and its two dictionary keys were **removed** — a dead explanation is worse than none. The predicate survives only as the resolver's guard.

**Slot ↔ note, the two inverse formulas** (nothing may re-derive them): `rectNoteAt(g,base)` → `{deg: g%block, oct: base+floor(g/block)}` where `g = rect*k + finger`, and `rectSlotOf(deg,oct,base)` → `g` (or `-1` outside the window) for the **highlight**. Ranges out are exactly today's — `deg ∈ [0,iv.length]`, `oct ∈ [0,REG_N-1]` — so **the event format is untouched and old loops replay identically**. For a 4-octave scale the pitch set is precisely the one narrow rows already offer (4 registers × the octave), only rearranged.

**Octave/register rectangle** (band 0, bottom) — **exists only when `hasReg`**, i.e. when the grid does *not* already show all `REG_N` registers. That single predicate is the one place the band is decided (gestures' `'oct'` capture, draw's band offset via `regBands`, and `thereminSpan` all read it). Where it exists it now shifts a **window of `octaves` periods**, not one octave: the base is clamped by `rectBase()` (same clamp on read and on write) and `drawRectOctBand` lists `rectBaseMax()+1` selectable bases (4 at one octave — as today; 3 at two, labelled «окт II–III»), the rest dim. Pinching it is by **position**, any hand (`'oct'` zone, overrides role; in chords kept right of the palette **only when `typedChords`**). The `'oct'` hand is silent. ⚠️ Bands are **equal**, and that cost is accepted deliberately: do not special-case band heights, it would move Partch and 19/31-TET.

**Chords**: rect applies to the ROOT grid — right of the palette `[palSplitX,rx1]` for a `typedChords` scale, the **full role range** otherwise. The type still rides the sticky palette; latch logic unchanged; only the root degree + octave source changed.

⚠️ **The rect chord branch must NEVER live inside the `chTyped` branch of `drawRole` again** (see hard rule #26): `gestures` decides rect by ROLE, so a non-typed chord scale in rectangles would take input by rectangle and draw narrow rows. It was invisible for as long as every rect scale was either `typedChords` or `noChords`.

- **The rectangle's finger legend runs LOW AT THE BOTTOM, high at the top** — the same direction as the grid around it. It used to list top-to-bottom, so pitch rose *downwards* inside a block while rising *upwards* everywhere else. ⚠️ **Visual only:** the row is drawn at `(NF-1-n)`, while finger `n` still takes slot `rect*k + n` (index = the rectangle's first note, little finger = its last) and the highlight still looks up that same slot. Never "fix" the order by touching the mapping.
**Labels depend on the SCALE, not the layout** — one function, `draw.noteLbl` (see hard rule #26). Under rectangles a 7-note scale shows **real note names** per row, a raga shows swaras, Werckmeister shows names + its true cents, 19/31-TET keep ordinals. When `octaves>1` the legend drops the cents suffix (identical in every block, 48 slots of noise — the live tag still shows them) and gains a **per-band register marker** at the right edge. That marker is **load-bearing, not decoration**: four identical-looking blocks otherwise give no way to tell which octave you are aiming at. It is derived from `rectNoteAt`, the same formula that makes the sound, so it cannot lie.

Scales left in narrow rows keep the narrow-row model byte-for-byte, and an untouched app (`'auto'`) reproduces today on **every** scale. ⚠️ **19-TET and Carlos gamma deliberately changed** with the multi-octave step (2 octaves, 10+1 bands, the band now shifting a 2-octave window): the previous round's "all four legacy rect scales are byte-for-byte" guarantee now holds for **31-TET and Partch only** (plus the newly eligible 22-shruti and BP, which land single-octave and behave like them).

### Hand functions (replaced the theremin toggle + the swap-hands control)
Each hand is assigned a **function per role**, held in `state.handFn` (`{ld:{L,R}, bs:{L,R}, ch:{L,R}, dr:{L,R}}`, defaults `ld:{fx,note}`/`bs:{note,note}`/`ch:{latch,latch}`/`dr:{hit,hit}`). Solo/bass functions:
- **`'fx'` (Эффекты)** — the effects hand; **available on all four roles** (effects goal (б)). Its fingers drive the parameters of the role's effect CHAIN that are addressed to them (see HANDOFF «КОНСТРУКТОР ЭФФЕКТОВ» for the address model). A chain also sounds with no effects hand at all — fixed values, or the playing hand's `play:z`/`play:x` addresses. The effect bars (`drawFxBars`) draw the role's CHAIN at its right edge with **no gate on the hand** — an empty chain (bass and drums by default) simply draws nothing. The separate REV bar and the reverb-from-the-playing-hand path (`S.rev` → `payload.rev` → `revLead.gain`) are gone (effects Plast 3.1; `rev` left the payload in 3.7.2).
- **`'note'` (Ноты непрерывно)** — normal play: degree follows the hand while pinched.
- **`'hold'` (Ноты с удержанием)** — the note captured on the first pinch frame is **frozen** (`S.deg`/`S.oct`, and the finger→octave change is gated off) while the hand roams; **volume keeps following X** (swell); it stops only on finger-release. It records as an ordinary long note — no new event format.
- **`'therm'` (Терменвокс)** — continuous pitch, **solo AND bass**. `thereminSpan`/`thereminHz` (scales) map y→a fractional note position over the SAME partition draw uses, then interpolate **linear-in-cents** (`log2` of the neighbours' `leadFreq`); bass Hz = `thereminHz/4`. Drawn as an **additive centre-line overlay** (`drawThereminLines`) on top of the normal grid, shown only when a hand of that role is `'therm'` (`roleHasTherm`). Live-only: the continuous Hz rides the **named live-only option `live` of `ENG.leadOn`/`ENG.bassOn`** (`ENG.x(a, ctx, {when, live, own})`, passed only by `WleadOn`/`WbassOn`; never recorded); the recorder stores the nearest step, and for solo the glide as a cents curve `a.bend` relative to that step.

**Chord functions** (`ch` role — the chord role joined `handFn`; besides `'fx'` and `'loop'` it has two note functions, and no `therm`):
- **`'latch'` (Аккорды (защёлка))** — today's default and behaviour: a pinch sets the chord, it keeps ringing after the fingers open; same-degree re-pinch turns it off, a different degree glides. **Jam and split depend on this** — a half or a hand must be able to leave a chord ringing while the other plays.
- **`'hold'` (Аккорды (с удержанием))** — the chord is frozen while the fingers stay together and **stops on release** (`endPinch` → `WchOff('latch')`), reusing the **same solo-hold mechanism** (`S.fn==='hold'` freezes root+octave; the type still rides the palette; volume swells with X).

**Drum functions** (`dr`, effects slice б.4 — the list was created from nothing): **`'hit'`** (default, both hands — a hit per pinch on the row under the hand), `'fx'`, `'loop'`. Drums are genuinely two-handed (rolls are played between the hands), so a hand given to effects or the looper costs half the drummer — unlike chords (one chord per role) and bass in its default lead mode (one voice per role), where the second hand is free by construction (see the comment on `ui.HANDFN_OPTS`).

**`'loop'` (Лупер (управление))** — available on **all four roles**: the hand plays nothing and drives the recorder (see "Looper hand").

**`'expr'` (Выразительность)** — **solo only** (first pass): the hand plays nothing and breathes into the sound (see "The expression hand").

Option lists live in `ui.HANDFN_OPTS` — `ld`: fx/note/hold/therm/**expr**/loop · `bs`: fx/note/hold/therm/loop · `ch`: fx/latch/hold/loop · `dr`: fx/hit/loop.

**UI:** the «Функции рук» section (`renderHandFn`) shows a select per hand for each role in play — options come from `HANDFN_OPTS`, rows group under the role heading `INSTR_LBL[role]` (🎸 Соло / 🎹 Аккорды / 🎚 Бас) over `Левая рука`/`Правая рука` rows, so a split with two roles makes clear the assignment is per **hand within a role**. `noteRolesInPlay()` picks the role(s) in play (single-role, or the unique split halves; since б.4 drums have an entry too — `ui.HAS_HANDFN` covers all four). A change fires `setHandFn`+`softAllOff`. Solo/bass/chords keep **separate** assignments (persisted across role switches). In split it's consulted **per half by the half's role**.

### Voice modes — solo and bass are one melodic instrument, played two ways (V1–V4b; the melodic-instrument branch is closed)
**The user's decision:** solo and bass differ only in their timbre list and register; every other difference is a POLICY that will become timbre data. One such policy is the **voice mode**, which every synthesiser has: **POLYPHONIC** (as many notes as are pressed) and **LEAD** (mono, legato — one note sounds; a new one does not add to the old, the one voice glides to the new pitch). Both modes existed before this branch but were welded to the roles (solo polyphonic, bass mono); now each melodic role has its own `state.voiceMode` entry, switched from the «🎛 Звук» panel. **Defaults reproduce the old behaviour exactly** — solo polyphonic, bass lead — and an untouched app sounds as before.
- **Gestures branch on the MODE, never on the role** (V2): `polyZone`/`leadZone` (zone = the hand's role). POLYPHONIC — each hand, and with a ceiling of 2+ each finger, owns its own pool voice under `liveKey(role,hand,finger)` (`'lead:L[:f]'`, `'bass:L[:f]'`); `S.snd` holds the keys sounding now and `endPinch` releases exactly those; there is no hand-over, because each hand's note is its own. LEAD — ONE voice per role under `monoKey(role)` (`'bass'`, and `'lead:M'` for solo — it starts with `'lead:'`, so every live-solo prefix test still catches it, and it carries no hand letter, so the per-hand multi-note tag leaves it alone), owned by `monoOwner[role]`: the LAST pinch takes it, `endPinch` hands it to a still-pinched hand of the role (`otherPinched`), the watchdog releases it when its hand has gone. This is the mechanism bass always had (`bassOwner`), generalised — ⛔ not deleted: the old plan to delete it was withdrawn when the user asked for both modes. Sound and recording go through `wOn`/`wOff(role, own, …)`.
- **Switching mode** (`ui.pickVoiceMode`) calls `softAllOff` (while recording that first closes every open note into the take) and then `gestures.voiceModeReset(role)`, which clears that role's per-hand poly state and, into lead, gives the voice to a hand already pinched — so a held pinch sounds in the new mode from the next frame, in both directions. **A mode change mid-take stays in the SAME track:** the recorder's source key is role + timbre (`noteSource`), and the mode is a way of PLAYING that source (like hold or theremin), not a source; a lead line records as one note with pitch changes, polyphonic notes as notes with distinct `a.v`, and replay, the chase and the editor already key by owner. When the mode moves into the timbre format, a timbre with another mode will be another source and the track will split by itself.
- **Recording and the engine were made owner-ready first** (P1, P2): the bass pool is lazy up to `BASS_POOL_N`=12 with solo's stealing order, each bass voice records the `deg`/`oct` it plays, and bass recording is a Map owner → open note with a slot `a.v` (written only when non-zero), exactly mirroring solo. The lead mode is simply the one-owner case. ⚠️ **The code MIRRORS, it does not merge:** bass keeps its own voice builder (two saws and a filter) and its own register (`bassFreq`, two octaves below solo); merging waits for the timbre format, where the policies become data. Chords and drums stay genuinely different families — they store different kinds of note (degree+type; row).
- **Glide is a declared parameter (V1, V4).** The glide time is an ENGINE ARGUMENT (`setFreq(f,tc,t)` on every lead bank; `glide` before `when` in `leadOn`/`leadSet`/`bassOn`/`bassSet`), and the `glide` voice module (4–800 ms, log) makes it assignable to a finger or axis, captured and replayed like any parameter; a note carries its value in `a.fx['glide:time']`. A freshly added Glide equals the role's current value (20 ms solo, 12 ms bass — `defBy`), so adding it changes nothing until it is moved. It is not in any default chain (every chain entry draws a bar). ⛔ Glide applies only to a legato move of an already-sounding voice: a fresh attack SETS its pitch, and theremin frames and bend points never receive it (their 20 ms is tracking smoothing) — and a theremin note does not even carry it into the recording, or replay would turn its recorded nearest steps into a portamento the hand never made. Glide is allowed in the polyphonic mode too (each finger's own moves), by the user's decision. **Retrigger in lead mode is DEFERRED** (the app is legato everywhere; a retriggering lead is a later small slice).
- **One accepted cost:** in the polyphonic bass mode the live hands (up to 8 notes) and recorded bass tracks share one pool of 12, so eight live notes over dense bass tracks begin stealing from the tracks, released voices first.
- **Split:** each half follows its role's mode for free (the zone is the half's role). Hard rule #10 still holds — the two halves never share a role.

### Typed chords — the palette
Scales with a `typedChords` property split the chord role: **left = a palette of chord types** (columns = families, rows = variants; counts from `chordFams()`/`types.length`, geometry in `palColX`/`palRowY`), **right = note rows**. The palette selects a cell by POSITION on a thumb+**index** pinch inside it (`S.oct===0 && S.x<palSplitX`); sticky, default first family/type. **Position-only in BOTH single-role and split** (one gate, one law): either hand picks a type by being left of the split with thumb+index, either hand plays roots on the right, and the SAME hand can do both in turn (the chord keeps sounding after the fingers open). The cost, accepted on both paths: a playing hand that pinches thumb+index left of the split picks a type instead of sounding a root — but no roots are drawn there (the grid lives in `[palSplitX,rx1]`) and volume there measured as the minimum, so nothing playable is lost. Play: Y=root, X=volume, and the octave — **on non-rect typed scales (chrom12, BP, Pythagorean, both Naturals, meantone)** the finger picks it, **on the rect typed scales (19-TET/31-TET/Partch)** the finger picks the root-in-rectangle and the octave comes from the octave rectangle (`chordOctReg`). `ty` is a live reference into `CHORD_FAM_SETS`; latch identity = (degree + type). Two-axis hysteresis `cellHyst`.

`typedChords` keys → sets in `CHORD_FAM_SETS` (**7 keys** — `'pyth'` was deleted in P2 of the "tuned from" arc):
- `'chrom12'`, `'edo19'`, `'edo31'` — **integer steps** in that scale's own edo (priced by the integer equal fallback of `chordNotes`).
- `'partch'` — 11-limit **ratios** (4 columns × 6: О otonal / У utonal / Диез 7-11 / Станд.); priced by the pure-ratio cents branch.
- `'bp'` — Bohlen–Pierce 3.5.7-subgroup **ratios** (15 chords: 3:5:7 major / 5:7:9 minor / characteristic); priced by the **period branch**.
- `'nat'` — the same 24-type vocabulary as chrom12 but as **pure 5-limit ratios** (mobile Natural); priced by the pure-ratio cents branch (root × ratio, so every chord is pure from its own root). (The Pythagorean 3-limit ratio set `'pyth'` is GONE since P2: Pythagorean chords are read from its own grid, `'natfix'` + `gridChords`.)
- `'natfix'` — the same 24 types as **integer semitone offsets**, but used by the **fixed-grid** scales (Pythagorean since P2, Natural-fixed, meantone, the three well temperaments) whose `gridChords:true` reads each note out of the frozen cents grid → some chords pure, others wolf.

### Behaviour properties (prefer these over `tag`/index checks)
- `noChords` → chord role builds nothing (`supportsChords()` false). Maqams; the **gamelan** cents-scales and **pelog patets** (monophonic by choice); the **Carlos** scales (stage 1). Partch/Pythagorean/Natural are **not** `noChords` — they have typed chords.
- `typedChords: '<key>'` → palette mode; keys a set in `CHORD_FAM_SETS`. Keys: `'chrom12'`, `'edo19'`, `'edo31'`, `'partch'`, `'bp'`, `'nat'`, `'natfix'`.
- `tunable: true` → the scale has a **"tuned from"** choice (P3; only Pythagorean): the live scale is a memoised VARIANT per anchor (`scales.scaleView` behind `CUR()`), so every event's frozen `sc` freezes its anchor too. See "fixedKey".
- `cents: [...]` → non-equal tuning; pitch from `2^(cents[i]/1200)` instead of the equal step (see "Music theory & pitch").
- `period: <n>` → **interval of equivalence ≠ octave** (BP `3` = tritave, Carlos `3/2` = fifth). `periodOf()=s.period||2`. Absent ⇒ `2` ⇒ every octave scale byte-for-byte. Drives register/step (`P^oct`, `P^(step/edo)`), the `centsOf` period (`pc=1200*log2(P)`), `regWord` and `noteLbl`. It no longer gates the rect grid's `dup` (see "Rect model"): layout alignment is not a claim about equivalence. **Never hardcode `2` on any pitch/label path** — use `periodOf`.
- `gridChords: true` → (cents scale only) typed chords read their notes **out of the fixed cents grid** by integer semitone offset (fixed-keyboard model), instead of pure ratios from the root. Selects the first `chordFreqs` branch. Today: Natural-fixed, meantone, and the three well temperaments. **Distinct from `fixedKey`** (chord CONSTRUCTION vs the tonic being a key) — memberships overlap but differ.
- `fixedKey: true` → the tonic is a KEY within a grid nailed to an ANCHOR note, not a multiplier (see "fixedKey") — absolute C for five of the six; for Pythagorean (`tunable`) its «tuned from» choice, following the tonic by default. The six historical fixed tunings. Drives the `fixedKey` branch of `leadFreq`/`bassFreq`/`chordFreqs`/`centsOf` and real-note-name row labels. **NOT** on mobile Natural or any world/EDO/BP/Carlos/Partch/raga/maqam scale.
- `rectGrid: true` → the scale **opens** in the rectangle layout. It is a **DEFAULT, not the layout** — the live answer is `scales.rectGrid()`, which resolves `state.rectPref`. The geometry (how many notes per rectangle, whether the tonic is duplicated, how many octaves fit, whether a register band exists) is **entirely** `rectLayout(s)`; every scale can be laid out. Never re-derive that arithmetic anywhere else.
- `supportsProgressions()` = 7 degrees. Note: a 7-note `noChords` scale (maqams, pelog) is still gated out of progressions because `refreshProgAvail` uses `supportsProgressions() && supportsChords()`. (Partch/12-note tunings/BP/Carlos aren't 7-note, so progressions stay gated regardless.)

### Music theory & pitch
`SCALES` is the source of truth: each has `edo`, `iv` (degrees in those steps), `tag`, `trad` (tradition/menu section), optional `grp` (submenu), optional behaviour properties. **75 scales (indices 0..74).**

**Menu sections — organised by SOUND, not mechanism (`TRADITIONS`, 6).** The reorg moved each entry's `trad`/`grp` **text only — the `SCALES` array order and every index are UNCHANGED** (so the tail index map below still holds; `scaleIdx`, `state`, `sameDegrees` all depend on it):
- **`common` «Привычное»** — ordinary 12-TET where a newcomer lands: diatonic (majors/minors), modes, ethnic, pentatonics/blues, **the symmetric scales (whole-tone / octatonics / Messiaen)**, exotics, world pentatonics, Japanese.
- **`mideast` «Ближний Восток»** — Arabic maqamat (24-TET), `grp:'Макамы'` (Turkish maqams later).
- **`india` «Индия»** — the 22-shruti grid + ragas (two groups: the grid, then the ragas that pick swaras out of it).
- **`easia` «Ява и Дальний Восток»** — Javanese gamelan (Слендро/Пелог + pelog patets) + Japanese and Far-Eastern pentatonics.
- **`europe` «Европа историческая»** — now its OWN top-level section (was a `grp` shelf inside the old Ладовая), flat and reading **chronologically**: Pythagorean → Natural (mobile) → Natural (fixed) → meantone → the three well temperaments (Веркмайстер III / Валлотти / Кирнбергер III). A temperament and a mode are different things, so they no longer share a bucket. All `fixedKey` except mobile Natural.
- **`exp` «Эксперименты»** — bounded by **TUNING, not mode**: the equal microtonal EDOs (19/31-TET), Partch, Bohlen–Pierce, Carlos α/β/γ. Whole-tone/octatonic/Messiaen are NOT here — they are ordinary 12-TET, so they stay in Привычное.

**Placement rule (for future scales):** a new scale goes to the section matching its **culture or sonic character**; never invent a generic "прочее" bucket.

**Indian tradition (`indian`):** a 22-shruti just-intonation grid (`cents:[0,90,112,182,204,…,1110]`, min step 22¢, the syntonic comma — same cents mechanism as gamelan/Partch, octave, no `period`) plus **10 ragas** that each pick 7 swaras out of that grid. All are `noChords` (Indian classical is melodic — a deliberate model choice, not a limitation). Labelling uses the `swaraNames`/`swaraFull` properties → `swaraLbl`: the full grid shows **«свара · имя-шрути»** (`SWARA_OF`+`SHRUTI_OF`, both keyed on real cents so they can't drift), ragas show swaras only (Са Ре Га Ма Па Дха Ни). The swara sits on the **LAST shruti of its group** (Sangita-Ratnakara: Са=Чхандовати, Па=Алапини), so the tonic reads «Са · Чхандовати», not «Са · Тивра»; the modern positional convention (Са=Тивра) is documented in the source as the rejected alternative. Honesty notes in the code: a raga is **more than a scale** (aroha/avaroha, vadi/samvadi, pakad, time-of-day — none modelled); Кафи and Мальхар share the same scale by design (they differ in movement, which we don't model).

**Tail index map:** 50 = Bohlen–Pierce · 51/52/53 = Carlos alpha/beta/gamma · 54/55/56 = Pelog patets Lima/Nem/Barang · 57 = Pythagorean · 58 = Natural (mobile/choir) · 59 = Natural (fixed/harpsichord) · 60 = quarter-comma meantone · 61 = 22-shruti grid · 62..71 = ragas (Бхайрав, Йаман, Кафи, Бхайрави, Тоди, Кхамадж, Асавари, Мальхар, Пурви, Мармари) · **72 = Веркмайстер III (1691) · 73 = Валлотти (1754) · 74 = Кирнбергер III (1779)** (the well temperaments — see "fixedKey"). **75 scales, 0..74.**

**Three ways to define pitch — equal steps, cents overlay, or non-octave period:**
- **Equal (default):** within-period ratio = `P^(iv[i]/edo)` where `P=periodOf(s)` (`2` unless `period` set). All EDO scales (12/19/24/31-TET) and the non-octave equal scales (BP `P=3`, Carlos `P=3/2`).
- **Cents overlay:** an optional `cents:[...]` array (`length === iv.length`) gives each degree's exact cents above the tonic — for **non-equal** tunings (gamelan, Partch, the historical temperaments). When present, `leadFreq`/`bassFreq`/`centsOf` use `2^(cents[i]/1200)` with the appended top = 1200¢. `edo`/`iv` stay as **nominal structure** (degree count, row layout, hysteresis). Cents scales are octave (`period` absent).
- **Non-octave period:** `period:<n>` replaces the hardcoded `2` in register (`P^oct`), equal step (`P^(step/edo)`), and the cents period (`pc=1200*log2(P)`). Register shifts by the period (BP tritave, Carlos fifth), not the octave. `period` and `cents` are mutually exclusive in practice (BP/Carlos are equal; the temperaments are cents+octave).

**Chord pricing — `chordFreqs` has four branches, checked in this exact gate order** (order decides which scale gets which — do not reorder). Since U1 the branches live in **`chordNotes`**, which returns `{f, iv}` per note (`iv` in the branch's own terms: semitone offset / ratio / step from the root); `chordFreqs` is exactly its frequencies, so the engine and the editor read one source. Since U4, **`chordUnit(s)`** beside it names, per branch below, the one-note type whose price is the root itself (`[0]` for branches 1 and 4, `[1]` for 2 and 3) — the canonical form of a note on a row; a new pricing branch must add its line there:
1. **`s.cents && ty && s.gridChords`** → **fixed-grid**: `ty` is integer semitone offsets; each note = grid pitch `корень+off` read from `s.cents` (octave carry for off≥12). Natural-fixed, meantone. Produces the pure/wolf spread of a fixed keyboard.
2. **`s.cents && ty`** → **pure-ratio cents**: `ty` is ratios; note = `baseF()/2·2^(o)·2^(rootCents/1200)·ratio` — root from the cents overlay, each interval a pure ratio. Partch, Natural-mobile (Pythagorean left this branch in P2). Every chord pure from its own root. Its `fixedKey` sub-branch (root on a fixed grid) has no user today and is kept only for the formula.
3. **`periodOf(s)!==2 && ty`** → **period-equal**: `ty` is ratios; root by `P^(iv/edo)` (period register `P^o`), note = root·ratio. Bohlen–Pierce.
4. **fallback** → integer path (since T4c-2 written inline in `chordNotes`: a typed `ty` adds its steps to the root; an untyped chord goes to `untypedNotes` by the mode's rule — the tag-based `chordSteps` that used to decide this lives in the probe as `legacyChordSteps`). Typed `ty` adds its step array to the root; else by the mode's `chordRule`: tertian modes stack thirds, the pentatonic/blues/Japanese modes stack every other MODE degree (rule `stack`, which replaced their old power chord for good), 19/31-TET by rounded interval ratios (rule `ratios`); chromatic never reaches the untyped path (it has a palette). chrom12/edo19/edo31 and every non-typed scale. **Byte-for-byte unchanged** — a scale reaches here only when the three gates above all fail.
- `CHORD_FAM_SETS` `iv` are **integer steps** for `chrom12`/`edo19`/`edo31`/`natfix`, and **plain-number ratios** for `partch`/`bp`/`nat`. Never give a step-set to a scale with a different `edo`, and never give a ratio-set to a non-cents/non-period scale.

### Reference pitch (`aRef`) — ONE source
`aRef` (A4 in Hz, default 440, adjustable 380–480 in the scale panel) lives in `state.js` beside the tonic. `scales.js` derives **both** `baseF()` (the mobile tonic pitch) **and** `cFix()` (the anchor pitch for `fixedKey` scales — C for the five historical temperaments, the «tuned from» note for Pythagorean) from the single `a3()=aRef/2`. There must be **exactly one** reference — a second copy would move world scales to 415 while the historical fixed tunings stayed at 440, surfacing much later as a "detuned instrument". Changing `aRef` re-tunes everything live (solo/bass/chords via `baseF`, drone via `tonicFreq()`, theremin, and every loop layer on its next replay); the UI clamps and falls back to the last valid value on bad input.

### fixedKey — the tonic is a KEY, not a multiplier (historical fixed tunings)
Scales with the **`fixedKey`** property (the six: Пифагоров, Натуральный фиксированный, Мезотон, Веркмайстер, Валлотти, Кирнбергер) nail their grid to **absolute pitches anchored at an ANCHOR note** — C for five of them, historically; Pythagorean CHOOSES it (P3). Since P1 of the "tuned from" arc the anchor is a named helper — `anchorOf(s)` gives the note the grid is tuned from, `cFix(s)` its equal-tempered pitch from A4 (taken an octave down when the anchor is above the tonic, so the tonic keeps its register), `keyOf(s)` the tonic's offset from it — and every `fixedKey` path in `fixedSlot`/`leadFreq`/`bassFreq`/`chordNotes`/`centsOf`/`tonicFreq` goes through them. ⛳ **"Tuned from" (P3):** `state.tunedFrom` (`'T'` = follows the tonic, the DEFAULT, or a pitch class 0..11; `setTunedFrom`) applies only to a `tunable` scale. `anchorOf` reads the anchor from the SCALE OBJECT (`s.tunedFrom`), never from state: `CUR()` returns `scales.scaleView(SCALES[scaleIdx])`, a memoised copy `{...s, tunedFrom}` per anchor (at most 13, stable references), and every event stores `sc: CUR()` — so each recorded event freezes its own anchor (rule #7) with no change to the recorder, the chase, the render or the editor, and moving the selector retunes nothing recorded. `'T'` gives `keyOf=0` and `cFix=baseF()` — the ordinary mobile path: every key sounds alike. A fixed anchor gives the key colours of a historically tuned harpsichord. The bare `SCALES[57]` object (no `tunedFrom`) is tuned from C — the start-screen demo builds its scene from it. The state value enters the freeze key's pinned fields and the render's pin list (`frzPinned`, `render.pinLive`), and a track signature only for an event without `sc` (none are produced) — so a frozen track does NOT go stale when the selector moves. Changing it is the tonic's seam (`setTunedFrom` + `softAllOff` + `updScaleBtn`). ⚠️ Two takes recorded with different anchors are different views — since routing by tuning they land in different tracks (honest: different tunings). ⚠️ The TONIC is still live (it moves recorded tracks); freezing it per event is decided and has its own plan (HANDOFF). **The Scale panel says so:** under the tonic, the five C-tuned `fixedKey` scales show the static line «Tuned from C (historical practice)» (P0; `#tunedFromNote`, key `panel.scale.tunedFromC`), and a `tunable` scale shows the selector row instead (`#tunedFromRow`/`#selTunedFrom`, first option «the tonic (follows it)», plus `#tunedFromHint`, which changes with the state; the scale button gains «· from X» when the anchor is fixed) — all set by `ui.updScaleBtn`/`renderTunedFrom` from the PROPERTIES, never from a name; the tonic then selects **which key** you play within that fixed grid, instead of transposing the whole tuning. That is why Веркмайстер's major third reads **≈390¢ in C and ≈408¢ in F#** — the whole lesson. `leadFreq`/`bassFreq`/`chordFreqs`/`centsOf` each have a `fixedKey` branch (via `fixedSlot`); row labels show **real note names** (`rowLabel`) because the grid is absolute, so the names are true again — all other cents scales keep ordinals. **`fixedKey` is a SEPARATE property from `gridChords`** — the memberships differ: «Натуральный (подвижный, хор)» deliberately stays **mobile** (the pair's contrast is the lesson), and since P2 Пифагоров IS `gridChords` (`natfix`): «The Pythagorean tuning must sound like the Pythagorean tuning. We do not want chords from other tunings in it» (the user's decision) — its chords are read from its own grid like every fixed temperament's, a tone on the wolf sounds as the instrument has it, and in the editor its chord tones sit on rows (no off-row marks; mobile Natural, Partch, BP and power chords keep theirs). The three well temperaments (Веркмайстер III / Валлотти / Кирнбергер III) sit in the **`europe` «Европа историческая»** section, `natfix`+`gridChords`+`fixedKey`, each with its own comma recipe; A/B them to hear near vs far keys.

### Scheduler — look-ahead is a hard invariant
Track events of the prepared roles (`isLayer`: chords/bass/drums) are scheduled at their **exact** times `loop.t0 + (ev.t + off)*spb` inside a `SCHED_AHEAD`(≈300 ms) window (`scheduleLayers` → `ENG[fn](ev.a, ev, {when})`). `off` is 0 without repeat; with the brace cycling, the window is cut at each pass boundary and `off` is the whole-pass offset that maps the MONOTONIC beat onto the song beat. Live `W*` calls pass no `when` → `AC.currentTime`. Every voice function takes an optional `when` defaulting to now — **do NOT "simplify" that away.** Solo and drone also accept `when` since slice S2, but they still fire "almost now" through `fireNear` over the song-position interval `(loop.pos, p]`; moving them into the window is a separate, audible change that nobody has made. **Cost is bounded by the window, not the song** (slice S3.2): both loops walk a sorted prefix of `events` from a cursor (`curSched`/`curNear`, positioned by binary search `cursLowerBound`) instead of the whole array — see "Time, tracks and the recorder → cursors". Why it exists: layers used to fire "now" at whatever instant the poll ran, and a blocked main thread (synchronous MediaPipe + three synthesis paths on one thread) bunched them; the metronome was already scheduled ahead, and that asymmetry was the audible drift. The window **masks** blocking, it does not remove it (root cause = vision on the main thread — see BACKLOG). Known bounded costs (accepted): drum hits already scheduled inside the window still play after stop, panic, mute, delete or a brace jump (one-shot oscillators can't be cancelled), and surviving tracks can drop out for up to one window after undo/`clearJam` (rewinding `loop.sched` would double-fire drums).

### Metre & accent grouping (variable time signatures)
`loop.metre` (default from `config.BEATS_PER_BAR`, set via `setLoopMetre`, clamped to `METRES=[2,3,4,5,6,7,8,9,10,12,16]`, changeable **only while the song is empty and the transport stopped** — `setLoopMetre` refuses otherwise and `ui.refreshMetreCtl` disables the control) replaced the old `BEATS_PER_BAR` constant. **No denominator by design:** the engine counts beats at BPM, so 7/8 and 7/4 differ only by tempo — which fits talas (counted in matras) and Balkan pulses honestly; quantisation was already beat-relative. **Accent grouping:** `METRE_GROUPS` (`7=3+2+2`, `9=2+2+2+3`, `16=4×4`) + `METRE_KHALI` (`16→[2]`, the empty third vibhag) feed `beatLevel(metre,b)` → four metronome accent strengths (2 bar-head / 1 group-head / 0 beat / −1 khali) AND the `drawLooper` tick grid, so grouping is seen and heard; **khali is a weakened head, not silence** (a tala's structural feature). **Subdivision is orthogonal to metre:** `loop.sub` only sets the live drum quantise grid (and its faint ticks in `drawLooper`, drawn **only when `sub!==4`** so the 4/4 view is byte-for-byte); a pattern's own `sub` lives in the pattern. `arrange.js` patterns declare their own `beats` (`Вальс`/`Дадра`/`Балканский 7`/`Кехерва`/`Балканский 9`/`Тинтал`, …); a pattern whose `beats ≠ loop.metre` is skipped. Count-in is always ONE bar (`loop.metre` beats) at any metre, and it counts in to the **start point** (`loop.lead` — the brace start when recording from stop), not to beat 0; clicks before `lead` are the count, and nothing is recorded or fired there. A brace is quantised to whole bars, so under repeat the monotonic and song beats differ by whole bars and the accents never drift.

### Chord readout — live Hz from the sounding voices
While a chord SOUNDS, its highlighted root rectangle lists each note's **Hz** with the interval **above the root** in cents (`drawChordReadout` in draw.js). The numbers are read from the **sounding voices** (`chordHold['latch']` → `latchChordFreqs`), **not recomputed** — so the display can never disagree with what's heard, and it works for all four `chordFreqs` branches for free. It shows only **live latched** chords; loop-played chords (owner `'loop:N'`) keep the plain highlight.

### Chord brightness — hand depth → expression, and the TWO-FILTER invariant
The chord role gets a Z-axis like solo's reverb: hand depth (`dist(lm[0],lm[9])`, the SAME size that drives the solo reverb) → a brightness value `bd` (0 near/bright … 1 far/dark) that rides into `WchOn`/`WchSet` **beside `ty`** and is **recorded on the event as `a.bri`, exactly as `a.rev` rides the lead event** — so a replayed layer keeps its own brightness curve (`recChSet` pushes a `chSet` on a `|Δbri|>REC_REV_EPS` change alone). **Two-filter topology is an INVARIANT, not redundancy** (`buildChordPool`: `o1/o2 → f → fb → g`): `f` bakes the **attack envelope** (timbre — `fo/ft/fv`, set once at attack, never touched per-frame); `fb` carries the **continuous brightness** (expression — `briToHz(bri)` via `setTargetAtTime` all note). On a single node a brightness change would fight the scheduled attack ramp (within `ft`) and permanently couple timbre to expression — **a future session must not merge `f` and `fb`.** Per-layer isolation is by **owner key** (`'latch'` live vs `'loop:'+layer`, plus `':'+k` for merged takes and later repeat passes): each owner holds its own pool voices → its own `fb`, so the live hand physically cannot change a replayed track's brightness — which is why brightness left the old shared bus (a global filter) for a per-voice `fb`. **Since effects goal (а) brightness is an ordinary CHAIN EFFECT:** `bright` (`kind:'voice'`, no nodes) in the chord chain, seeded on the `play:z` address, so the old built-in behaviour is now a default setting that can be removed, fixed to a number or moved to another axis. The recorded value comes from that parameter (`fxChordBri()`). ⚠️ An ABSENT `a.bri` means **"not set"** (the filter opens at attack, a glide leaves it alone) — NOT "take the live value": arrangement and jam chords never carried brightness, and reading the live hand would repaint every backing chord. **Bass and drums follow this same rule** (an absent `a.fx` map, or an absent key in it, = "not set" — V4 glide, brightness on every role); **solo alone** keeps the opposite rule for an absent MAP ("sound with the live solo chain", `applyFx` R2), while an absent brightness key inside a present solo map is still "not set". The separate ЯРК indicator (`chBrightDisp`/`drawChordBright`) is deleted; the chain's own bar shows the value.

### Brightness on every role — a voice module for solo, bass and drums too
`bright` is declared for all four roles (`FX_FACTORY.bright.roles`). Chords keep their two-filter voice unchanged (hard rule #19) and their `a.bri` field; solo, bass and drums carry the value in the event's `a.fx` map under `'bright:amt'` (the declaration's `note` field is limited to `roles:['ch']`, and `fxNoteField` takes the role).
- **What it acts on.** Solo and bass get a **brightness stage** built with each pooled voice (`audio.makeBriStage`): a lowpass beside the voice's ORIGINAL output connection, which stays untouched — output = x + w·(LP(x) − x). One stage per voice serves every solo synthesis path (subtractive, organ, FM, Karplus–Strong — it filters the finished voice; on KS it darkens the whole pluck but does not change the string's own loop damping). The timbres' own filters (attack envelopes, the bass `lp`) are not touched. Drums: `drumHit` routes the hit through a per-hit lowpass ONLY when the hit carries a value (`hitBus`); otherwise every connection is the old one.
- **Unset is exact, not "inaudible".** w = 0 when the note has no value OR the value is fully open (v = 1): both extra branches output exactly zero, and x + 0 is exact in IEEE — no colour, level or phase change. Added and untouched (default = open) therefore changes nothing. Absent in a bass/drum event = "not set" (the bass rule); a solo event's map follows the solo rule.
- **One meaning.** v = 0 is as dark as the role reasonably gets, v = 1 is open, on one log curve; the Hz range is per role (`audio.BRI_HZ`: solo 700 Hz–18 kHz as chords, bass 100 Hz–4 kHz, drums 300 Hz–18 kHz), because bass has almost no energy above ~1.5 kHz and a shared 700 Hz–18 kHz range would leave 90 % of its slider dead.
- **When it is read.** Solo and bass: set at the attack, followed while the note is held (every change event carries its own value, so the V4b lane edits what sounds). Drums: at the hit.
- **Axes.** A newly added brightness takes a free effects-hand finger or is fixed (`fxChainAdd`) — it never takes the playing hand's depth by itself. Depth (`play:z`) is now driven for the playing hand of solo, bass and drums (`gestures.noteHandRole`; chords keep their own branch), so it can be assigned on any role. Two parameters on one address both follow it (the menu's share chip shows it); nothing is taken away.
- **Cost.** One biquad and two gains per solo and bass voice, always processing: with both pools full (12 + 12) that is 24 biquads; a drum hit adds one only when brightness is set.

### Looper hand — commands by finger, single-fire by construction
Assign a hand of any role the **`'loop'`** function and it plays nothing; instead it drives the recorder by finger on a pinch: **index = record** (`onRec` — not recording → start a take into the armed track or a new one; recording → stop), **middle = play/pause**, **ring = undo the last take**, **pinky = clear-all** — clear-all needs a `CLEAR_HOLD_MS`(3 s) hold with a **visible countdown** (`setLooperClear`), and **releasing early cancels** (`endPinch` clears the countdown). **Single-fire is STRUCTURAL:** `fireLooperCmd` runs inside the **pinch-capture block** (the `false→true` edge), which by construction runs once per pinch; held frames take a different branch and do NOT repeat the command (only the pinky countdown lives in the hold branch, itself gated by `S.clearFired`). The pinched finger is **frozen** for loop (and hold) hands — the `S.fn!=='hold'&&S.fn!=='loop'` gate on mid-pinch finger-change — so drift can't slide onto another finger and fire a second command. `doLooper` **confirms each command on screen by name** (`setLooperMsg` → «● Запись»/«Запись стоп»/«▶ Пуск»/«⏸ Пауза»/«↶ Отмена дубля»/«✕ Очищено») and **impossible ones say why** («Нечего играть»/«Нечего отменять»/«Уже пусто»). The transport buttons in the UI still work — the looper hand is ONE more input, not a replacement.

### Audio engine (`initAudio`) — five chains into one master
`master → limiter → destination`. **FDN reverb** networks (`buildFDN`, constants in `REV_A`), one instance per role whose chain holds a reverb — solo and chords by default, so two networks run out of the box. Chains: (1) **solo pool** (see below); (2) chord pool (`CHORD_POOL_N` always-on 2-osc voices, gain-gated); (3) bass pool (**one voice per owner key**, built LAZILY up to `BASS_POOL_N`=12 since P1 — mirroring solo's pool; allocation mirrors `leadAlloc`: a free voice, then a new one below the ceiling, then steal released-first by oldest `tOn`; each voice records the `deg`/`oct` it plays via `bassOn`/`bassSet`, cleared by `bassOff`, which is what the bass highlight reads; timbre baked on attack; live owners are `'bass'` in the lead mode and `'bass:L[:f]'` in the polyphonic mode — see "Voice modes"); (4) drums (synth per hit, kit from `a.kit`); (5) drone (detuned saw pair, LFO-swept LP, root `tonicFreq()/2`; the second string is the TUNING's own pitch chosen from the live MODE — `scales.droneDegree`: the degree nearest 3/2 within 17¢, else (octave tunings) 4/3, else a seventh 15/8·9/5·16/9, else the tonic one period up; Bohlen–Pierce: the 5:3 degree (878¢) by default — the user's choice by ear — or the tritave, ear switch `R.droneBP` — priced by `pitchHz` (`droneSecondHz`); `audio.droneRetune` re-pitches it, never its level, on every tonic/scale/anchor/A4 change). Plus the metronome.

**Reverb is an FDN (feedback delay network), NOT a convolver** (`buildFDN`; `makeIR` and the `ConvolverNode` are gone). Signal: `verb` (input `GainNode`) → 80 Hz highpass → pre-delay → **3 input allpass diffusers** (`apStage`) → **4 delay lines**, each `delay → damping lowpass → feedback gain`, mixed by a **Householder matrix** (`in_i = src + x_i − (2/N)·Σx`, built from one Σ node + one `−2/N` node instead of 16 connections) → **stereo taps** (different sign patterns per line into L/R) → merger → `outTrim` → `verbOut` → `master`. ~49 nodes per network, no oscillators and no worklet. The send is **not part of the network's own code**: each owner's instance owns its `send` (the chord chain's reverb mix starts at the historical 0.12, `CH_REV_SEND`) and processes the SUM of that owner's voices; since O-1 there are no per-note sends (a recorded `'reverb:mix'` key in an old event is ignored). Numbers live in **`REV_A`** beside `EXPR_A` (sound-side numbers belong in audio, not `config`). **Three real-time params:** *mix* = the sends, *decay* = `setRevDecay(sec)` (RT60 → per-line `g_i = 10^(−3·d_i/RT60)`, which is why one number gives one tail across four different delay lengths), *tone* = `setRevTone(hz)` (the in-loop lowpass cutoff). Decay and tone are genuine `AudioParam`s written via `setTargetAtTime` and are now parameters of the reverb module (`REV_PARAMS`, reachable from the effects constructor) — the frozen convolution buffer could only ever offer *mix*, and that is the whole point of the swap.
- **Reverb was the first EFFECT MODULE** (`makeReverbFx`, Plast 1 of the effects-constructor work), and the shape has grown since: a factory entry `{id, labelKey, kind, params, make}` in `FX_FACTORY`; a per-role instance built by `make()` and kept in `FX_INST[role][fxId]`; param descriptors `{key, labelKey, short, unit, def, min, max, curve, attach?}` that `fxWrapParam` gives a `set` and a `cur` (ranges are advisory — the setter's own clamp is the authority). A network is a **real instance, not a singleton**: `buildFDN` returns its lines and they live inside the object. `attach:true` marks a **per-note** parameter — since O-1 only VOICE modules have one (`bright:amt`, `glide:time`; the reverb and delay mixes lost the flag with the per-note sends) — whose value rides in each note's event (`a.fx`, or its own field per `note`); every other parameter is a **network** parameter of the instance, shared by everything that owner plays. ⚠️ The original warning still holds, narrowed: attachment kinds really differ (bus / insert / voice — see the module map), and the per-voice modulation effects — drive and vibrato, plus the per-voice solo tremolo — are **still not modules** and must not be forced into this shape; see HANDOFF «КОНСТРУКТОР ЭФФЕКТОВ».
- ⚠️ **The in-loop lowpass MUST stay at Butterworth Q (`REV_A.toneQ = −3.0103`), and this is load-bearing, not tidiness.** Web Audio interprets `Q` **in decibels** for `lowpass`/`highpass` (`α = sin ω₀/(2·10^(Q/20))`), so the **default `Q = 1` is a quality factor of 1.122 — a +1.96 dB resonant peak (|LP| ≈ 1.25) just below cutoff.** Outside a loop that is a harmless colouration; inside one it is fatal: `g·|LP| = 0.886 × 1.25 = 1.11 > 1` on all four lines at once, and the reverb **self-oscillated into a whistle at ~3.9 kHz**. `−3.0103` dB = quality factor exactly `1/√2`, monotonic, max magnitude 1 at DC — which makes `loop gain = radius(M)·g·|LP| ≤ g < 1` true for *every* reachable `decay`/`tone`, not just today's constants. Note what did **not** save it: `gMax` clamps `g`, and the runaway came from the filter; the master limiter caught it but is a backstop, never a design guarantee. **Compute the loop gain — never assume "a lowpass reduces gain".**

**Solo is a POOL with owner keys, like chords** (`lv[]` / `leadHold`, **`LEAD_POOL_N=12`, `LEAD_POOL_KS=8`**) — polyphonic by default, and one voice per role in the lead mode (see "Voice modes"). Owners: live hand `'lead:L'`/`'lead:R'` (+`:finger` when several fingers sound), or `'lead:M'` in the lead mode, built by `gestures.liveKey`/`monoKey`; replayed layer `'leadloop:'+layer+':'+v`. Live play and a replayed solo layer therefore **no longer fight** — the same separation `'latch'`/`'loop:N'` gives chords.
- **A voice builds ONLY its own bank, lazily.** `buildLeadBanks(preBus, ksOk, only)` now builds one instrument (each block gated by `sel(i++)`, bodies untouched; `banks` is a scratch array the caller drains). ⛔ **Never rebuild "all banks"** — the old design kept all 23 alive permanently (40 oscillators + 7 KS worklet nodes on every device), and replicating that per voice would be 6× that. Because of this the pool is **cheaper than the status quo**: one instrument in play = 1–5 oscillators, and KS costs at most `LEAD_POOL_KS` worklet nodes instead of a permanent 7.
- **Per voice:** bank → `satDry/satWet` (drive) → `env` → `vol` → `trem` (the per-voice tremolo) → `leadSum`, with the brightness stage beside that last connection (`makeBriStage(trem,leadSum)`), a per-voice vibrato depth, and its own humanisation `ConstantSource`; the per-voice `dlySend`/`revSend` are gone since O-1 (the voice's only output is the sum). All of them take the note's OWN values at attack (`applyFx(a.fx)` → `pendFx` → `applyVoiceFx`), which is what lets a recorded solo note replay with the effects it was played with (effects Plast 3.7.1/3.7.2). **Drive is per-voice on purpose:** saturation sits *before* the envelope and `tanh` is non-linear, so moving it to the bus would change how a **single** note sounds at `drv>0` (and the default `drv` is 0.12, not zero).
- **Glide time is an argument (V1, voice modes).** Every lead bank's setter is `setFreq(f, tc, t)` — `tc` the pitch time constant, `undefined` → `LEAD_GLIDE_TC` (0.02 s, today's value), time LAST. `leadOn`/`leadSet`/`bassOn`/`bassSet` take `glide` BEFORE `when` (rule #15). Since V2 `tie` is before `when` too — `leadOn(owner,freq,vol,ins,deg,oct,glide,tie,when)` and `leadOff(owner,tie,when)` — so rule #15 holds with no exception; every positional caller that passes a time (the dispatch table, the render probe, `recorder` `leadOff(k, undefined, at)`, `render` `leadOff(own, undefined, endSec)`) fills the new slots explicitly.
- **Voice modes in gestures (V2; the panel switch arrived in V3 — full model in "Voice modes").** `state.voiceMode` (`{ld:'poly', bs:'lead'}` — the defaults are the old behaviour; `setVoiceMode`, `isLeadMode`) decides the path, not the role: POLYPHONIC = the per-finger list `act`, `S.fing`, the sounding-key set `S.snd`, live keys `liveKey(role,hand,finger)` (`'lead:L[:f]'`, `'bass:L[:f]'`); LEAD (mono, legato) = `monoOwner[role]` (last pinch wins), `otherPinched` hand-back on release, the watchdog, one key per role `monoKey(role)` (`'bass'`, and `'lead:M'` for solo — it starts with `'lead:'`, so every live-solo prefix test still catches it, but carries no hand letter, so the per-hand multi-note tag doesn't claim it). The finger-switch law is skipped only for `multi && poly`. Sound and recording go through `wOn`/`wOff(role, own, …)`. The bass highlight now comes from the engine's `bassHold` live keys (`'bass'`, `'bass:…'`) as a set, like solo's (rule #26); the multi-note tag (`handLeadNotes(key, role)`) serves either role in poly mode. ⛔ Glide applies ONLY to a legato pitch move of a voice that is already sounding: a fresh attack SETS its pitch (time constant 0 — `leadOn`/`bassOn` when the voice was not sounding; fixed after ear-testing, see "Ear-testing a render" — until then a fresh attack silently took the bank's default 20/12 ms and slid in from the voice's previous pitch, or from 220/440 Hz on a brand-new voice, which was the "scoop" on the first note of every frozen track), and theremin frames after the attack and bend points (`scheduleBend`) never receive it — their 20 ms is tracking smoothing, not portamento. Bass uses one constant, `BASS_GLIDE_TC` (0.012 s), for live `bassOn` AND replayed `bassSet` (the replay used 0.03 s until V1, so recorded bass slid more slowly than it was played). ⛳ **Since V4 a glide time IS passed**: `ENG.leadOn`/`leadSet`/`bassOn`/`bassSet` read it from the event's own map (`applyFx(a.fx)` returns it for solo, `fxGlideOf(a.fx)` for bass) and pass it in the `glide` slot; no `glide:time` in the map → `undefined` → the constants above. A live theremin frame is passed no glide at all. ⚠️ An ABSENT map means different things by role: for solo, "sound with the live solo chain" (rule R2 in `applyFx`, unchanged — solo events without a map are practically nonexistent); for bass, "not set" — otherwise a backing's bass line would glide the way the hand is set now.
- **On the bus (shared):** the expression stage (amplitude shimmer on `exprGain`, the soft/hard shaper morph, the wah) → `leadOut`, which is the head of the solo chain (`fxChainIO(CHAIN_SOLO, leadOut)`) → the serial chain → master — so two notes still intermodulate through one expression shaper. Accepted.
- **Allocation:** same owner → same voice (per-frame calls lead the note, they do not reallocate); else a free voice **that already has that instrument built** (affinity, or a Sitar layer and an Organ hand would rebuild a bank per attack); else any free voice; else a new one up to the cap; else **steal, released voices first** (a cut melodic note is far more audible than a cut chord tail).
- **Three latent defects were fixed with it, all invisible while solo was mono:** the humanisation `ConstantSource` was **global** and re-randomised per attack (a second attack would have re-detuned the first, still-sounding note — it is now per voice, wired via `mkOsc`'s `bldHum`); the recorder's open-note state was **single** (`recLead`/`recLeadBend`/`noteStartBeat`/`bendLastC` — two hands recording at once would have interleaved into one corrupt stream; now a `Map` per owner); and `ENG.leadOn` called **`setLeadInstr(a.inst)` globally**, so a replayed layer hijacked the live instrument and the panel button — baking the timbre per voice removes it.
- **Sizing the pool is sizing the ceiling, not the cost.** The live maximum is **8** (2 hands × 4 fingers), so `LEAD_POOL_N=12` = 8 live + 4 for replayed layers and stealing headroom; below that the eighth note would steal the first. Voices are **lazy** and each carries only its own bank, so playing two notes costs two voices no matter how big the pool is. **`LEAD_POOL_KS=8`** is deliberately tighter — the live maximum with *no* layer headroom: a KS voice is an `AudioWorkletNode` (a JS callback every 128-sample quantum) and **Sitar adds 5 tarab bandpasses per voice**, so eight Sitar notes are 8 worklets + 40 biquads — the heaviest thing the app can be asked to do. Worst subtractive case is ~5 oscillators per voice (Organ full, SuperSaw) plus one 2× waveshaper each. If a phone crackles, that is the audio thread, not MediaPipe — lower these two numbers, not the frame rate.
- **⛳ THE OFFLINE ALLOCATOR (freeze slice F2) — `setOffline(true)`, and it is a different law, not a tuning.** Allocation live asks "is this voice free **now**", which is a wall-clock question. An offline render schedules a whole track in **one synchronous pass**, so every release frees its voice immediately and by the second note the pool looks empty: **every note lands in voice 0** — one oscillator retuned a thousand times, silence everywhere else. Total failure, not degradation, and it hits solo, chords and bass alike. Under `offline` each voice carries **`freeAt`** — the time before which it may not be reused. An attack sets `Infinity`; a release sets **the release moment itself** (`freeAfter(t) = t`) — the voice is free from its release, exactly as live, where a released voice loses its owner and is the FIRST candidate for the next note, whose attack cuts the old tail. ⚠️ **Corrected after ear-testing:** F2 originally set `t + rel·RELEASE_TAILS` (7 time constants, "until the tail has decayed"); offline every next note then took a NEW voice and the previous note's tail rang under it in full, and because each voice has its own humanisation the two beat slowly — a swirling "phaser" colour on frozen tracks, with or without effects. The buffer must sound like the events, not "fuller". (`RELEASE_TAILS` survives only in comments.) The law that still holds: a note begun BEFORE a voice's release moment never gets that voice, so "everything in voice 0" cannot return. ⛳ **Stealing is ABOLISHED offline, not reimplemented:** the pool ceilings exist because that is what a phone carries at 60 fps, and a render has no deadline, so the pool **grows on demand** and converges on the track's real simultaneity. ⚠️ **This is a musical decision, not a technical one — stealing offline would silently discard notes the player actually played. A frozen track must keep everything, and may legitimately sound FULLER than the live performance did — but ONLY where the live pool OVERFLOWED (notes stolen from sounding voices), never through tails a live voice would have cut; what was lost live to the ceiling was lost to hardware, not to intent.** ⛔ No second note-pairing formula exists here and none may be added — growth-on-demand needs no precomputed spans, and `songNotes` (recorder.js) remains the only place `…On` is paired with its `…Off`. ⛳ **Hard rule #3 is untouched:** `freeAt` is pure bookkeeping — nothing is stopped or disassembled, voices are still only gated and still live until the context dies. ⛳ **Hard rule #15 is what makes it possible at all**, and this slice needed **no new signature**: every voice function has taken an explicit `when` since slice S2. ⛔ At `offline === false` every branch is the previous code verbatim — same stealing preference, same affinity for a voice whose bank is built, same 20 ms glide when a finger changes note mid-pinch; only `render.js` sets the flag, and only on its own module copy.
- **One behavioural delta, later made a choice:** when solo went polyphonic its mono hand-over was removed; since the voice modes (V2/V3) it is back as the LEAD mode, available to solo and bass alike (see "Voice modes"). ⚠️ **Corrected (T0-fix): an instrument change STILL MORPHS a sounding SOLO note** — the live path calls `leadOn` every frame with the live index and `leadVoiceBank` crossfades the voice's banks over 20 ms; the user considers this right. Since T3 it is recorded as a tied close-and-continue across two tracks (the old timbre's and the new one's), and replay reproduces the 20 ms crossfade from the `a.tie` pair (see the event format). **Bass and chords really do bake the timbre at the attack** (`bassOn` sets it only when `!v.on`; `chordGlide` takes no instrument). An earlier note here said solo baked too — it was wrong.

**Three synthesis paths for the lead banks (not one) — a bank is just `{gain, setFreq, cancel, strike?}`, so all three ride the SAME solo chain and effects:**
1. **Subtractive** (most banks): oscillators via `mkOsc` (which wires `vibGain`+`humDetune` into `.detune`) → optional filter → gate. Velocity→brightness (`fstrike`/`strike`) fires at ATTACK, not per-frame (a per-frame cutoff would stomp the filter envelope; `setFreq` deliberately never touches the filter). Humanisation (`HUM_CENTS=4`, in `humDetune`) is fresh at each attack and **never recorded** — a replayed loop gets new variation. **Pads and organs are pitch-clean** (`hum:0`, `det:0`): the beating you hear is the TUNING, not the timbre. **Bass is not pitch-humanised** (low-frequency detune muddies).
2. **FM** (`buildFMBank({ratio,peak,sus,tau})`): carrier via `mkOsc` (so it flows through the shared chain), modulator is a bare osc → `modGain` → `carrier.frequency` only (not the output). The modulation-index envelope (`strike`) decays FASTER than amplitude (`rel` > `tau`) — that struck-metal read. **Non-integer `ratio` gives inharmonic spectra the subtractive path physically cannot produce.** Banks: «Колокол (глубокий)» (ratio 1.41), «Металлофон» (3.51).
3. **Karplus–Strong** (`buildKSBank`, wraps the `ks-string` worklet): `node → [body resonator] → gain → chain`; `setFreq` is the a-rate `freq` param (same `setTargetAtTime` as every bank → glissando/bend/theremin free), `strike` fires the `pluck` param edge. `KS_BANKS` params: `fb` (decay), `damp` (loop filter), `exBase`/`exSpan` (pluck brightness), `nl` (loop nonlinearity = **jawari** on Ситар / metal edge on Сантур), `symp` (bandpass resonators following `baseF()` = **tarab** on Ситар, retuned like the drone), `body`. KS has no `oscillator.detune` (`hum:0`). Banks: «Струна», «Ситар», «Уд», «Кото», «Сантур», «Гитара», «Пиццикато». If the worklet fails to load, `buildKSFallback` fills those slots so indices never desync.

Drum kits are per-hit synths (`drumHit(row,vol,kit,when)`): Стандарт, Дарбука (`dDum`/`dTek`), Табла (`tabBaya` with the signature downward pitch bend + `tabNa`), Гамелан (inline FM `gmlFM` → inharmonic bronze), Тайко (`taikoDrum`/`taikoKa`) — same 6 rows/indices across kits.

### Time, tracks and the recorder (replaced the loop model — slices S1…S3.5)
The app **stopped being a looper** in slice S3.3. There is no loop length and no unconditional wrap; the song is a linear sequence of events in absolute beats, and looping came back later as an OPTIONAL marked span (the brace). Most names still say `loop` (`loop`, `loopPos`, `drawLooper`, `'loop:N'`, `setLoopBars`) — they are history, not the model.

**The event** — created in exactly TWO places, `push` (every recorded event) and `loadArrangement` (every backing event):

`{t, layer, fn, a, sc, sev, tk}` (+ `jam:true` on backing events)
- **`t` — ABSOLUTE song beats, `t ≥ 0`.** Quantised at record time by `gridFor` (chords 1 beat, bass ½, drums `1/loop.sub`, solo never). While the brace cycles, `push` records the FOLDED song beat (`songAt`), so each pass accumulates into the brace; a quantise that would round past the brace end is folded onto its start.
- **`layer`** — the track's layer number: the address of its SOUND (owner keys), not its identity (see lanes).
- **`fn`** — `leadOn`/`leadSet`/`leadOff`, `chOn`/`chSet`/`chOff`, `bassOn`/`bassSet`/`bassOff`, `drum`, `drone` (drone only from arrangements).
- **`a`** — intent, never frequency. All pitched roles: `oct`, `vol` and **`ti`** — ⛳ **since T4c-2 NO EVENT CARRIES A MODE DEGREE (`deg`)**: gestures and backings still produce mode degrees, and the two recording funnels (`push`, `loadArrangement`, through `recorder.storeTi`) convert them to the tuning index on the way in and do not store them; editor edits write the index directly (the row decodes to `{ti, oct}`). Before T4c-2 the degree was stored beside `ti`. `ti` (since T4a of the universal tuning model) — the TUNING INDEX of the note (solo/bass) or of the chord's ROOT, in the event's frozen view, from `scales.tuningIndexOf` (each role's wrap rule; the live tonic's key is NOT included). Written by `push` and `loadArrangement` (converted from the gesture/backing degree) and by the editor's edits (the index itself); the stamping audit `tiAudit`, the restamp `tiRestamp` and `P.checkTi()` were removed in T4c-2 (there is no degree to check against); `P.checkSong()` checks that every pitched event carries a whole `ti` and `oct` and no `deg`. In T4a the DEGREE was still the truth everywhere. ⛳ **Since T4b1 SOUND reads `ti`:** the dispatch table (`makeENG` — live notes, replay, the chase, the freeze render) prices solo and bass with `scales.leadFreqTi`/`bassFreqTi` and chords with `scales.chordNotesAt` (typed chords from the root's index — fixed grid, ratio roots, Bohlen–Pierce roots, equal typed steps; UNTYPED tertian/power/rounded-ratio chords stay on the degree until T6). Live calls (no `ti` in the gesture payload) convert the degree with `tuningIndexOf`; a replayed event without `ti` is NOT played since T4c-1 (one warning per case; before, it fell back to its degree). Proof: the probe's `P.checkSound()`. ⛳ **Since T4b2 the recorder's LOGIC reads `ti` too:** `songSegs` tests a pitch change on the stored pair (`ti`, `oct`) — never an absolute pitch: the duplicate tonic at the top of register r and the root of register r+1 sound alike but stay different notes — and segments carry `ti` beside `deg`; the chase builds each re-opened payload in the pure `chaseNote(s,x)` (a held theremin note takes the ATTACK's index with its degree — this fixed a T4b1 defect where it kept the held change's live index); dissolve/one-note edits get chord notes via `chordNotesAt`; the bend's reference cents use `leadFreqTi`. Readers of LIVE gesture payloads (open-note recording state, seam re-open, latch open) stay on the degree. Proof: `P.checkLogic()` (segments and chase vs `legacySongSegs`/`legacyChaseNote`, kept for the probe until T4c). ⛳ **Since T4b3 the EDITOR'S ROWS read `ti`:** the axis has `rowOfTi(ti, oct)` beside `rowOf(deg, oct)` (offset over the mode's root, reduced by whole periods into the register; `j = E` is the duplicate tonic at the top of a register; in «All» the row IS the tuning pitch, in «Mode» it is the degree whose pitch that is), and blocks, the hit-test's root row, the chord axis height and the drag ghost (`draw.rollGhostSeg` — with the index the edit's commit will stamp) read it through `rollSegRoot`/`rollSegNotes`; a typed chord's notes and root-row frequency come from the index (`chordNotesAt`, `chordRowFreqAt`) behind ONE gate shared with the sound, `scales.chordReadsTi`; UNTYPED chords stay on the degree until T6. Since T4c-1 a tapped row decodes to a TUNING INDEX (`axis.pitchOf` → `{ti, oct}`), and the edit functions write that pair (`recorder.slotPt`); since T5 the row may be a DIMMED one — an edit stores any pitch of the tuning (see the editor's T5 paragraph). Proof: `P.checkRows()` (every segment in both views, hit-tests, ghosts on every bright row, plus a sweep; legacy copies in draw for the probe until T4c). ⛳ **Since T4b4 the REPLAYED and CHASED chord highlight reads `ti`** (`recorder.setLoopChordHl` → `hlOf` → `scales.modeSlotOfTi`, the inverse of the mode's selection; a pitch outside the mode has no slot — no highlight, nothing thrown); LIVE highlights (the `leadHold`/`bassHold` registries, the latch, hand tags) keep the gesture's mode degree, and the registries deliberately carry no index (no reader). Proof: `P.checkHl()`. The editor's default scroll reads rows-per-register from the axis and chord rows no longer depend on cache history (`P.checkRowFix()`). ⛳ **T4c-1: every reader reads `ti`; the degree is still WRITTEN but no longer READ** — `chordNotesAt`/`chordRowFreqAt`/`chordFreqsAt` take no degree (`(ti, oct, s, sev, ty)`; where pricing needs a mode degree, `modeSlotOfTi` gives it; no index or off-mode → no notes); the ENG prices through `recorder.evHz` and fills the voice registries through `evReg` (replayed: the index's mode slot; live: the gesture degree); segments carry no `deg`; the chase's theremin copy takes the attack's `ti`/`oct` and drops `deg`; editor rows, hit-tests, ghosts and edits work on `{ti, oct}`. Proof by stripping: `P.checkStrip()` deletes `a.deg` from every event of a clone of the song (`recorder.probeWithEvents` swaps it in and back) and compares every derived path with `===`. T4c-2 stops writing the degree and removes the legacy copies, `tiAudit` and `R.powerOld`. Solo: `inst` (on `leadOn`; a `leadSet` carries the same value — since T3 an open note never changes timbre, see below), **`tie`** (T3: this `leadOn`/`leadOff` pair is a note continued across a timbre switch — replay makes it the live 20 ms crossfade, not a release and a new attack), **`v`** (the note's slot among notes open at once in that track — pairs `leadOn` with its `leadOff`; absent reads as 0), **`fx`** (the note's effect map `'fxId:paramKey' → 0..1`, COPIED by `push` so later hand movement can't rewrite the past), `bend` (theremin cents curve), `hold` (a set that must not re-pitch a bend). Chords: `inst` (on `chOn` only, as always), `ty`, `bri`, **`k`**. Bass: `inst` (on `bassOn` only since T0), **`k`**, **`v`** (P2 — the note's slot among bass notes open at once in the track; written only when non-zero, so one-owner material is byte-for-byte as before), and **`fx`** (V4 — the note's per-note map, e.g. `'glide:time'`, `'bright:amt'`; present ONLY when the bass chain holds a per-note parameter, otherwise the field is not written at all; absent = "not set"). ⛳ **A timbre switch is recorded as it was HEARD, per role (T3):** solo morphs mid-note, so the held note is CLOSED in the old timbre's track and CONTINUED as a new note in the new timbre's track at the same instant, both marked `a.tie` — replay turns the pair into the same 20 ms crossfade (`leadOff(…, when, tie)` = fast release, `leadOn(…, when, tie)` = 20 ms entry, no attack jitter, no strike); a theremin note continues with a FRESH bend from the nearest step, so the old "mid-bend switch is not replayed" limit is gone. Bass and chords bake at the attack, so a held note — and a latch gliding through any number of changes — stays in its old track until released, and the next note of the new timbre starts the new track (`recChOn` closes the chord left open in the other layer). The T0-fix bank crossfade in `audio.leadSet` (`ins`) no longer fires for new material. Drums: `row`, `vol`, `kit`, and **`fx`** only when the drum chain gives a per-note value (today brightness, `'bright:amt'`, read at the hit); otherwise not written. Drone: `lvl`. **`k`** is the owner suffix that keeps takes and repeat passes of one track apart; absent reads as 0 = no suffix. **`sh`/`gen`** (smooth automation, written ONLY by the editor's per-note lane — `pnPlan`): maps keyed by address `'fxId:pKey'`; `sh[addr]` is `'s'` on a point the value glides into and `'r'` on an event inside a smooth segment, `gen[addr]=1` marks an event the editor generated for that address (an anchor or a ramp step, always a `…Set`). The engine never reads them; absent on everything recorded, so recorded material is unchanged.
- **`sc`/`sev`** — the frozen scale REFERENCE and seventh (hard rule #7). `push` takes an explicit frozen context `fz` for exactly one caller: the chord re-open at a repeat seam.
- **`tk`** — the TAKE number, on every event. `takeSeq` is monotonic for the session: `onRec` assigns `curTake=++takeSeq` and `push` stamps it; `loadArrangement` gives each backing layer its own number. An event without `tk` cannot arise today (nothing is saved); it would read as 0, the oldest.
- ⚠️ **Anything that creates events later — the piano roll inserting notes nobody played — is a THIRD creation site** and must stamp `tk`, keep `t` absolute, pick `v`/`k` that don't collide with what the track already stores (`layerSlotTop`/`layerTakeTop` compute exactly that), and call `schedInvalidate` once afterwards.

Frequency is derived at play time via `leadFreq/chordFreqs/bassFreq(..., ev.sc)`, so a track re-tunes to the live tonic while keeping its frozen scale (**and its `cents` tuning**, for free). Replay goes through `ENG` directly and is never re-recorded. This is polymodality — don't "simplify" replay to the current scale.

**Two kinds of beat — every consumer must pick the right one** (the comment on `loopPos` is the canonical statement):
- **MONOTONIC** `m = (now − loop.t0)·bpm/60` — the CLOCK, never goes back. Used only for time arithmetic: `loop.t0` rebases (tempo change, brace edits), the scheduler window (`loop.sched`, the horizon), counting repeat passes (`rgnReps`), the count-in (`m < loop.lead`), metronome click numbering (`loop.clickBeat`).
- **SONG** `p = songAt(m)` — the place in the MATERIAL; identical to `m` unless the brace cycles. Used by everything that points at events or at song length: recording (`push`, `curBeat`), lead/drone replay (`fireNear`, `loop.pos`), the resume point, end of song, and everything the person sees (the strip's playhead and width).
Mixing them was a real bug: the strip once used the monotonic beat, so under repeat the playhead ran off the end and new bars kept appearing.

**Transport.** `startTransport(countIn, from)` is the ONE way playback starts (play, record from stop, arrangement, `seekTo`): it rebases the cursors, sets `lead=from`, puts `t0` so the song beat is `from` after the count-in (one bar) or a 60 ms lead-in, and CHASES held state if `from > 0`. The tick is silent until `m ≥ loop.lead`. `setLoopBpm` keeps the current beat by moving `t0`. `stopAtEnd` stops at the end of the material — never while recording, never while cycling. `seekTo(beat)` exists (refused while recording) but has no UI caller yet.

**The brace — repeat as a marked span** (`loop.rgn = {on, from, to, user}`):
- **ONE control, TWO jobs** (like a DAW loop brace): its bounds are WHAT cycles when ⟳ is on, and its START is WHERE RECORDING BEGINS when ● is pressed from stop. There is deliberately no second "record start" ruler.
- **Two states.** `user:false` — it FOLLOWS the material (`[0, end of material rounded up to a bar]`; drawn dashed with «auto»). `user:true` — the person set it; it stays put, recording past it does not move it, and only a song that shrinks below its end pulls it in. ✕ returns it to following.
- **Quantised to the bar, minimum one bar, clamped to the material** (`braceClamp`). Bar resolution is honesty about pixel density, not an unfinished feature; do not "improve" it to sub-bar without timeline zoom. Whole bars also keep `m − p` a whole number of bars, so accents never drift and rebases are exact.
- **Edited by tap/drag** on its own band in the strip: a tap snaps to the nearest bar line and moves the NEARER edge (a tie is broken by the side of the brace midpoint). Edits are refused while recording.
- **`rgnApply` is the single writer** of bounds and on/off (the one exception, `braceFollowGrow` in `push`, writes only while NOT cycling). While playing it **rebases** `t0`/`sched`/`lead`/`clickBeat` by whole bars so the song beat does not jump; if the playhead ends up past the new end it jumps to the brace start (a seek, with a seek's cost). A playhead BEFORE the brace plays into it linearly. `rgnSync` (called from `schedInvalidate`) keeps the bounds in step with the material.
- **Region-only machinery** — all of this is inert without the brace cycling: the `songAt`/`rgnReps` fold; the pass split and seam release in `scheduleLayers` (`releaseLoopLayersAt(when)`) plus the chord/bass chase at each seam; the wrap branch in `tick` (sweep the pass tail, `liveWrapRelease`, the solo chase, then fire from the brace start); the quantise fold in `push`; the per-pass closing in `recFoldRoll` (which fires when recorder time goes backwards — only a cycling brace or a ⟳ jump can cause that); and the `stopAtEnd` suppression. **Unconditional:** absolute time, the chase at `startTransport(from>0)`, the stops, lanes, arming, undo and delete.

**The chase — why entering the song after beat 0 needs one.** Chords and bass have ONE voice per track (`'loop:N'`, `'bassloop:N'`), and a chord change GLIDES that voice instead of re-attacking: a latched progression is one `chOn` followed by `chSet`s, and a sustained bass line is one `bassOn` followed by `bassSet`s. `chordGlide`/`bassSet`/`leadSet` do nothing when no voice is open. So entering after the `on` — resume from pause, a pass that starts at a brace not at bar 1, recording from the brace, a jump — would leave the whole role silent until its next `on`. `chaseFor(x)` folds the sorted events before `x` into "the last `on` per owner plus the latest `set` after it, minus owners an `off` closed" (skipping owners whose own on/off sits exactly on `x`, and events of the take being recorded); `chasePlay(x, when, lead)` starts those voices through the ordinary `ENG.chOn`/`bassOn`/`leadOn` at the entry time, with the event's own frozen scale, its effect map and, for a theremin note, the REMAINING part of its bend. Muted/silenced tracks are skipped at play time. Called from `startTransport` (from>0), the brace jump in `rgnApply`, each seam in `scheduleLayers` (chords/bass), the wrap in `tick` (solo), and — for ONE track, via the optional `only` layer argument — the splice out of a frozen buffer (`frzLeave`, A2b), and — for all event-played tracks — `trackResplice` when `softAllOff` runs while the transport plays (A2c). It skips a track whose frozen buffer still owns it (`frzBufOwns`). Cost: the fold is one pass over the prefix, cached per entry beat and reset by `schedInvalidate`, so a seam that repeats costs O(open owners). Entry at beat 0 costs nothing.

**Tracks (lanes).** A track is a layer number plus a generated **lane id**. The id is the identity — mute, solo, the arm and a pending delete are keyed on it — because layer numbers are REUSED (a new track takes `maxLayer()+1`, so after undo it gets the freed number) and can have holes (`clearJam` removes by flag). `laneNew` is the ONLY writer of `laneId` and always issues a fresh id, overwriting whatever that number carried (hard rule #27). Mute/solo: `laneAudible(layer)` — solo overrides mute — gates both replay loops and the chase; `laneGated()` is computed once per scheduler call so an untouched mixer costs nothing per event; `laneHush()` releases newly inaudible tracks immediately through `releaseLoopLayersAt(undefined, layer)` and keeps the drone's level in step.
- **⛳ A TRACK HOLDS EXACTLY ONE ROLE (slice T2 — this replaced "a track is NOT typed by role").** A take routes each note START by its **source** — ONE function `noteSource(fn,a)`, which today returns the role (T3 will add the timbre, later the timbre assigned to a finger; claim, minting and `takeSrc` compare its answers only, so extending the key changes nothing else) — (`takeRoute`, called inside `push` only AFTER the count-in refusal, so a refused note mints nothing): to the take's track of that role; else to the track born at ● while it is still unclaimed (the first note to land claims it — so recording in one role without switching is exactly as before: same number, same lane id, same row from the moment of ●); else a NEW track is born (`takeMint` → `laneNew` — the one minting function, hard rule #27; its number comes from `nextFreeLayer()`, which also counts the take's still-empty tracks, because `maxLayer()+1` only sees layers that have events). Changes and releases never route — they follow their own note's `layer`. Switching role mid-take therefore starts a new track (the role controls call `softAllOff`, which while recording closes every open note into the take first); split records two roles, so two tracks are born together; an ARMED track accepts only its own role (`laneRoleOf`) and any other role goes to a new track. One ● is still one take: every track it created carries its `tk`, so ⤺ removes them all, plus its part of an armed track. A still-open chord is closed EXPLICITLY when a new chord lands in another layer (`recChOn`). ⚠️ Material recorded before T2 may still mix roles in one track; nothing is saved, so after a reload none exists. **Since T3 the source is role PLUS timbre** (`noteSource` → `'role:inst'`, drums `'dr:kit'`), so a track also holds ONE timbre: switching timbre mid-take starts a new track, and an ARMED track receives only its own role and timbre — another timbre goes to a new track and the header says «L{n} takes only its own sound» (`looper.armedOwn`); arming never switches the live timbre, and a recorded track's timbre changes only in the editor (T5). ⛳ **Since the stack slice the 14 pentatonic/blues/Japanese modes carry `{kind:'stack'}`** — a stack of every other MODE degree (the tertian arithmetic, its own kind because such a stack is not always thirds), named by `scales.stackLabel` (a known chord from the pitch set, slash for an inversion, else the notes), every tone inside the mode (`P.checkStack()`); `power` remains only as the shape of the unreachable untyped chord of a palette scale; the temporary `R.powerOld` switch was removed in T4c-2 (the user's decision: the stack replaces the power chord for good). ⛳ **T6a:** every mode carries a `chordRule` literal (`tertian`/`power`/`ratios` with `triad`/`seventh` — 19/31-TET's old `chord`/`chord7` moved there/`palette`/`none`), equal to today's tag-based choice; ⛳ **since T6b untyped chords PRICE from the rule** — the ENG passes the root's index, `chordReadsTi` is true for an untyped chord whose rule builds one, and `chordNotesAt` finds the root's mode degree by the inverse selection (`modeSlotOfTi`) and prices `ruleChordSteps` with the old expression (`P.checkUntyped()`); rule `'none'` means NO chord (zero notes, empty label; the editor refuses to insert one); ⛳ **since T6c chord LABELS read the rule** — `chordLabel`/`chordNotesStr` take their notes from `scales.ruleChordSteps` (the one rule-based step function pricing will share in T6b), identical strings on every mode where a chord label is shown (`P.checkLabels()`, a row of `P.all()`). ⛳ **Since «routing by tuning» the source also holds the TUNING VIEW** (the user's decision: a change of scale, tuning or «tuned from» starts a new track even with the same instrument): `noteSource(fn, a, sc)` → `'role:inst|viewId'` for solo, bass and chords (`scales.viewIdOf` — the mode id, plus `'@'`+«tuned from» for a `tunable` mode; equal strings ⇔ the same memoised view), drums unchanged (`'dr:kit'`); the tonic is NOT part of it. The view rides on the EVENT, not the payload, so `push` passes the view it will stamp and `laneSourceOf` the event's own; a scale/anchor change goes through `softAllOff`, which closes every open note while recording, so no note spans two views. A track therefore holds ONE view; the editor's scale groups (`rollGroups`, the `#rollScale` chip, ghost strips) were removed in T4c-2: the editor reads the track's ONE view (`draw.rollGroup`/`rollTrackView`), and a segment of another view (no path writes one; `recorder.viewAudit`/`viewWarn` report it) is neither drawn nor hittable. `P.tracks()` lists every track's role, timbre and view(s). The one change T3 needed outside `noteSource`: `laneSourceOf` reads only note-start events (`isNoteStart`), because change events carry no timbre.
- **Arming** (`toggleArm` — tap a row outside its buttons; `armLane` holds a lane id or null): ● records into the armed track instead of a new one, without calling `laneNew` (the track keeps its id, mutes and arm). Arming is frozen while recording. A muted armed track is allowed (a punch-in) and the header says «(not heard)». Undo/delete/clear of the armed track clears the arm.
- **Owner keys keep merged material apart.** Replay owners are `'leadloop:N:v'`, `'loop:N[:k]'`, `'bassloop:N[:k]'` — since P2 `'bassloop:N:k:v'` when a bass note's slot `a.v` is non-zero (with `v=0` the key is byte-identical to before, and `a.v` is then not written at all); live owners are `'lead:L'`/`'lead:R'` (+finger), `'latch'`, `'bass'`. ⛳ **P2: bass recording is per owner like solo** — `recBass` is a Map owner → `{deg,oct,vol,inst,q,layer,v}`, the slot comes from `bassSlot` (the lowest free among open bass notes of that layer, from 0 — takes and passes are already separated by `k`) through the same `lowestFree` rule as solo's `freeSlot`, the bass order guard is per slot (`takeSt` `bsLast`: slot → t), and the repeat seam, `recAllOff` and `liveWrapRelease` loop over every owner. `WbassOn(p,live,own='bass')`/`WbassOff(own='bass')` take an owner; since V2 gestures pass the key through `wOn`/`wOff` — `'bass'` in the lead mode (one owner), `'bass:L[:f]'` per hand/finger in the polyphonic mode (see "Voice modes"). At each ● the recorder joins the take's layer (`takeJoin`) and computes that layer's `vBase = layerSlotTop(layer)` and `k = layerTakeTop(layer)` — above everything the track already stores — and both RISE at every repeat seam (`recFoldRoll`), so no new note can share a voice with a stored or earlier-pass note. ⛳ **Since T1 this per-take state is keyed BY LAYER** (`takeSt`: layer → `{vBase, vTop, k, chLastT, bsLast}`; its keys ARE the take's layers, read through `recLayers()`/`isRecLayer()` by the strip and the prune/delete guards), each open note remembers its `layer`, and `push(…, ly)` takes the layer explicitly — a change or release passes its own note's layer, a note start passes `undefined` and is routed by role (T2, above); `pushLy` reports where it landed. `releaseLoopLayersAt(when, layer)` matches a track by the key tail `N` or `N:…`, so suffixes never make track 1 catch track 12.
- **Replay skips only what sounds live:** `recording && ev.tk === curTake`, in `scheduleLayers`, `fireNear` and the chase fold. For a take into a new track that is the whole track (the old behaviour); for a merge the track's earlier material keeps playing.

**Undo, delete, clear.** **⤺ removes the LAST TAKE** (the highest `tk` still present), repeatable back through the history: a take that created a track removes the track, a merged take removes only its events. Each backing layer is its own take, so a backing is undone layer by layer, rhythm first. Undo never resurrects anything a row delete removed. **✕ on a row deletes that track** — two taps within `DEL_CONFIRM_MS` (3 s; the button fills red and the header asks), any other strip tap cancels; it is **NOT undoable**; it releases only that track's voices (the mute path, not `softAllOff`); the track being recorded into cannot be deleted. **✕ in the transport clears everything:** events, lanes, arm, brace (back to following), repeat off.

**The three stops mean three things.** **Pause** (▶ while playing, `onLoop`) HOLDS the position and closes held notes in the recording first. **Panic** (■) RESETS: `recStop()` if recording (the same close-and-stop path as ●, without the tutorial hooks), then halt the transport, then `softAllOff`, then rewind to the brace start — keeping the song, the brace, mutes/solos and the arm. **Clear** (✕) resets everything, brace included.

**Closing notes — nothing may stay open in the recording.** Every stop that ends a recording closes what is held (`recAllOff`: every solo owner, the chord, the bass): ●, pause, panic. At every repeat seam (`recFoldRoll`): open solo notes get `leadOff` at the pass end and the slot base rises; a held bass gets `bassOff` at the pass end (the hand re-attacks next frame); a latched or held chord gets `chOff` at the pass end and a **written** `chOn` at the pass start carrying its current state and its own frozen scale — the live chord voice itself is untouched (hard rule #20; only the RECORDING changed). `clearJam`, and undo of a take other than the current one, close held notes before `softAllOff` throws the recording state away. **Notes already sounding when recording begins are opened at its first beat.** `push` refuses during the count-in, so nothing begun there is written then; a note still held after it is opened by its hand — solo and bass hands call the recorder every frame while pinched (`recLeadEv`/`recBassEv`), a held chord's pinch sends a change every frame (`recChSet` opens it) — and a **LATCHED chord with open fingers, which sends nothing at all, is opened by `recLatchOpen`**: `onRec` marks the take's start beat (`latchOpenAt` — the launch beat from stop, the ● moment while playing), and the first `tick` after the count-in writes a `chOn` at exactly that beat from the recorder's mirror of the live chord (`liveCh`, kept by `WchOn`/`WchSet`/`WchOff`, cleared by `softAllOff`; timbre from the attack), routed by source like any chord — so in split it births the chord track. It opens only if the live latch voice still sounds (`chordHold['latch']`) and the hand has not already opened one (`recCh`): a latch struck and released during the count-in is gone by then; one struck and still ringing is opened. The live voice is never touched (rule #20).

**Cursors — one rebase point.** Both replay loops walk the sorted prefix `events[0..cursN)`; `push` appends the take being recorded UNSORTED after it, which is safe because replay skips that take. `schedInvalidate()` is the single reset: it re-reads `cursN = events.length`, drops both cursors and the chase cache, recomputes `songLen` and re-syncs the brace. Every path that changes the events or jumps the time base calls it (start/resume, record start/stop, arrangement, undo, delete, clearJam, clear, panic, tempo, brace edits). ⚠️ Because it declares the whole array sorted, any call made **while recording** must sort first (`setRegionOn`, undo, delete, clearJam, panic all do). Removal uses `compactEvents(drop)` — one in-place pass that keeps the array reference draw holds (hard rule #28).

**Known limits the next work has to design around — FREEZE INHERITS EVERY ONE OF THEM:**
- **A CHAIN REORDERED DURING A TAKE RENDERS IN ITS EARLIER ORDER.** The render follows chain changes made during a take at their recorded beats: an effect added mid-take is wired from the start but gated shut (a closed effect is identity) and opens at its beat already set to its captured values; a removed one closes at its beat and its tail rings out (`render.mergeOrders`, `audio.fxRenderPath`/`fxGateAt`). Only ORDER cannot be scheduled — the render's graph is wired once — so when two effects that were both already wired swap places, the earlier order is kept for the rest of the track (gates and values stay right; e.g. "delay into reverb" instead of "reverb into delay"). The render's console report says so (`reordered`). Two small differences from live playback remain and are accepted: live gates fade (τ 0.08) and the live path dips ~40 ms on each composition change, while the render switches instantly with no dip; and a live effect that is re-opened may still hold a tail from before ▶ in its reverb/delay, while the render's copy opens it empty.
- **ONE NETWORK PER CHAIN OWNER.** There is exactly one instance per (owner, effect) pair — `FX_INST[key][fxId]`. A recorded track drives that instance through `fxPlaySet`, and the player's LIVE playing of the same role goes through the same nodes: while a recorded bass line drives the bass reverb, live bass is in that reverb too. ⛳ **For NETWORK parameters this is not hidden, it is impossible:** playing live with different reverb/delay/bus-tremolo settings than the recording cannot be done today, and only freeze — giving a track its own instances — makes it possible. The bars say so on screen (`fxIsDriven` marks a parameter the recording governs), and on stop the sound is pulled back to the hand's aim (`fxRestoreAim`). ⛳ **PER-NOTE parameters escape this limit since V4b** (glide, brightness, the old solo scalars vib/drv/trm): each recorded note carries its own value, `fxLaneMerge` skips their lane points, so playback never drives the live instance — recorded notes sound with their values while the hand plays with its own, and those bars are never drawn hollow.
- **A LATCHED CHORD WITH OPEN FINGERS RECEIVES NO UPDATES.** Its voice is re-sent (`WchSet`) only while the chord hand is pinched, so a change of a per-note value coming from anywhere else — volume or brightness on a finger of the effects hand, volume on the chord hand's depth, or a new Fixed value in the panel — does not reach the ringing chord, live or in the recording, until the next pinch. Named in the Volume row's hint (VOL-2); planned as **VOL-6**, a per-frame latch follower that carries such changes to the ringing chord AND records them as `chSet` — a new event writer that must respect quantise, the per-key order guard (`chLastT`), the count-in refusal and seam closing (HANDOFF, volume plan). Per-note PAN is planned as VOL-7 (its own plan; not the mixer's per-track pan).
- **SEVERAL TAKES THROUGH ONE CHAIN: LAST WRITER WINS.** `fxPlayBuild` merges every take's snapshot and lane into ONE list sorted by `(t, tk)`, and `fxPlayDrive` folds it up to the current beat — so at any point in the song the value is the last one written at or before that beat, ties broken by the higher take number. ⚠️ A take governs ONLY the owners whose roles it actually played (`meta.keys`, built from `evRole` over its own events): a bass take never touches the chord chain. ⚠️ This applies to NETWORK parameters, compositions and the expression channels only — a per-note value is not merged at all: every note plays its own.
- **⛳ THE ENGINE VARIES AT EVERY ATTACK — NINE `Math.random()` CALL SITES IN TOTAL, AND SINCE SLICE F1 EIGHT OF THEM ARE SEEDABLE.** The exact arithmetic, because two partitions of "eight" were being used and they are not the same eight: **`src/audio.js` has 8 call sites** — 7 at attacks (chord: humanisation cents, −0..5% level, ±10% attack time, `chordOn`; solo: the same three, `leadOn`; bass: ±10% attack time, `bassOn`) **plus 1 that fills `noiseBuf`** in `initAudio`, read by every drum with a noise component — **and `src/ks-worklet.js` has a 9th**, the pluck excitation inside `excite()`. **All 8 in `audio.js` now go through `rnd()`**, a module-level indirection defaulting to `Math.random` with a `setRnd(fn)` setter (exported; only `render.js` calls it, and only on its own `'./audio.js?render…'` copy). ⛔ **Never seed by patching `Math.random` globally** — the two engine copies share the global object, so that would make LIVE play deterministic and audibly kill humanisation; `render.js`'s probe asserts against it (`liveRandomIntact`). ⚠️ **The 9th cannot be reached from the main thread and is deliberately left unseeded:** `AudioWorkletGlobalScope` is a separate JS realm and `addModule` re-instantiates it per context, so seeding it means passing a seed through `processorOptions` — a real edit to `ks-worklet.js` and `buildKSBank`. Consequence, which the probe reports rather than hides: **a Karplus–Strong instrument still differs between two renders of the same material.** (`demo.js:196` is a 10th call site in the codebase but belongs to the start-screen demo's own mini-engine and its own `noiseBuf`; it is never rendered and is correctly untouched.) ⛔ **None of this is recorded** (hard rule #11 names humanisation explicitly) — a seed is not an event and does not change that; it will ride on the frozen track's own record. Freeze's answer, decided: **"the same performance" is the requirement, and the cheap half of "the same samples" was taken anyway.**
- **⛳ A REPRODUCIBLE RE-RENDER MEANS THE SAME *PERFORMANCE*, NEVER THE SAME SAMPLES — BIT-IDENTITY IS NOT ACHIEVABLE AND IS NOT REQUIRED. MEASURED, NOT ASSUMED.** Slice F1's seeding works (see below), and two seeded renders of the same material **still differ by one to three float32 last-bits**. ⛳ **The whole explanation is the summand rule:** float addition is not associative, so a node fed **two** non-zero inputs has only one possible order, `(a+b)`, and reproduces **bit-for-bit** — while a node fed **three or more** can have its inputs reduced in a different order between runs and moves by about one last bit. ⛔ **This is the platform's arithmetic, not ours:** we build connections in a fixed order; how a node folds its inputs is not reachable from JS. It is why **bass is exactly identical every time** — its busiest summing node takes `g1+g2` ([audio.js:2314](src/audio.js#L2314)) and the pool's other voices contribute exact zeros, which do not change an order — while **chords** (3 pool voices into `chordBus`), **solo** (5 SuperSaw oscillators into `ig`, [audio.js:371](src/audio.js#L371)) and **three overlapping drum hits** all drift by a last bit. **The numbers, so nobody derives them again** (every probe material peaks in the binade `[0.0625, 0.125)`, so one ULP is `2⁻²⁷ = 7.4506e-9` for all of them): same seed → **1–3 ULP**; different seed → **~15 600 000 ULP** (1.16e-1); same seed **with a reverb in the path** → **~10⁶ ULP** (≈8 % of peak), because a feedback network with RT60 1.7 s amplifies last-bit rounding into a **decorrelated tail — the same room played twice**, identical in density, decay and colour, different in micro-structure. ⚠️ That amplification factor (~3·10⁵) is *not* derivable from a linear error model and is recorded as measured-but-unexplained rather than fitted. ⛳ Consequence for the freeze arc: **a refreeze after no edit gives the same performance and a different waveform, and that is correct behaviour, not a defect to chase.** Any future test must compare against a threshold relative to the material's own peak, never `===`.
- **A TRACK'S CHAIN IN THE EDITOR IS THE SNAPSHOTS OF ALL ITS CAPTURED TAKES (S1 of solo and chord editing).** Each take's snapshot governs from that take's first beat (`fxLaneMerge`), so a chain edit written into ONE take would sound only from its start. `autChainAdd`/`autChainRemove`/`autChainMove` therefore act on EVERY captured take of the track as one history entry, `autChainOf` lists their union (the same order law as `autAddrs`), and a new bus point goes to the latest captured take (`autCaps`). ⛳ **A take with no capture inside a captured track never gets one of its own.** Today the only such takes are the editor's insertions (`editInsertHit`/`editInsertBass` open an `editTake` and never call `takeCapStart`; backings DO get one — `loadArrangement` captures each layer). Such a take plays under the track's chain; if it starts BEFORE the track's earliest captured take, `fxLaneMerge` gives it that take's snapshot from its own first beat, so the chain starts at the track's first note. ⚠️ **Fixed defect:** before S1 the first chain edit or bus point after an insert gave the editor take a snapshot of the LIVE chain, and from the inserted note's beat the whole role — on every track of that role — played through the live controls; freezing pinned the same way. ⛔ **The live chain is read only for a track with no capture in ANY take** (it was following the live chain): a chain edit or freeze then snapshots it into ONE take — the earliest — and NAILS it, which keeps it sounding exactly as it did a second ago but stops the live knobs from reaching it again. A chain edit records that snapshot as the first move of its own history entry (`'autcap'`), so ↶ returns the track to following the live chain; a freeze does not (it is not an edit), and says so once (`frz.pinned`). Adding a VOICE module goes the same way (it is listed in the snapshots), but its values live in the notes and a lane point on it edits notes, never the capture. ⚠️ Effects added MID-take (a composition entry in a take's lane, not in its snapshot) are still not moved or removed by ▲▼⊘; and an effect that is in one take's snapshot but was added mid-take in another is removed only from the snapshots — the mid-take entry brings it back from its beat.
- **Chains belong to the OWNER, not the track** — the same fact as the first limit, seen from the freeze side: freezing ONE track through the live graph would pick up other tracks' tails out of the shared network and bake the owner's current network settings. A clean freeze needs its own instances per track (since T2 a track holds exactly one role, so one chain per track).
- **NOTHING CAN BE SAVED.** A layer's scale is an OBJECT REFERENCE (hard rule #7) and no scale carries an id; the chord type `a.ty` is a reference into `CHORD_FAM_SETS` as well. The capture itself is plain serialisable data (strings and numbers only) — but it is keyed by take number to events that cannot be written down, so it inherits the same wall. For a five-minute multitrack song that is the feature failing, not a convenience missing — see BACKLOG §1.

### The track editor — a piano roll over the song (slices S4.0…S5.6, plus the automation lane O-4)
**A NOTE IS NOT AN EVENT, AND A "NOTE" IS NOT WHAT THE MUSICIAN MEANS.** Two passes, both read-only, both lazily memoised on `songNotes`' own identity (invalidated by `schedInvalidate` — no second reset point, hard rule #28):
- **`songNotes()`** groups events into notes by **the engine's own owner key** (`chaseRole`/`chaseKind`/`chaseKey` → `ldKey`/`chOwnerKey`/`bassOwnerKey`). ⛔ Never write a second pairing formula: if it diverged from the engine's key the editor would show one note while another sounded. The reading rules follow the ENGINE, not taste: an `…On` while a note of the same key is open closes the previous one (`endBy:'next'`); a `…Set`/`…Off` with nothing open is an **orphan**; an `on` with no `off` inside the sorted prefix is an OPEN note (`end=null`) and no ending is invented; a drum is a note of zero length; the drone is a LEVEL, not a note.
- **`songSegs()`** is what the editor actually edits: **a note groups a VOICE'S LIFETIME, not what a musician calls a note.** A bass line played in one movement is ONE note across a dozen pitches (`bassSet` glides), and drawn as a note it would be one bar at the FIRST degree with every other pitch gone. A **pitch segment** — the event that sets a pitch plus the span to the next change — is the musician's note. ⛳ **The boundary is a PITCH change only:** a `set` that moves volume or effects stays INSIDE the segment, or one crescendo would shatter into ten "notes" at the same pitch. Each segment carries **its own frozen scale** (`sc`/`sev` off its own event), and `byEv` maps event → segment. ⛳ **A solo theremin note is ONE segment** (S0 of solo and chord editing): its pitch lives in the head's `a.bend`, while its `hold:true` sets carry the LIVE nearest step (read only by the highlight, never by the sound), so comparing their degrees would cut one bent note into fake segments. The test is `ldTherm(n)` (the head carries a non-empty bend) — the same one `pnPlan` uses to give a generated set `hold` — and a `hold` set is never a pitch change.

**ORPHANS CAN NO LONGER BE PRODUCED, AND THE EDITOR IS DESIGNED ON THAT SENTENCE.** Three recording slices closed every path by which a release could sort before its own note: **S4.1** — recording state follows what actually LANDED in the array (`push` returns a boolean; a note refused during the count-in sets no state, so its `set`s and `off` cannot reference a note that is not in the song); **S4.2** — at a repeat seam only the DRUM hit folds, while everything belonging to a note (`on`/`set`/`off`) is held at the pass END; **S4.3** — the quantise rule is FROZEN ON THE NOTE (`q` in `recCh`/`recBass`, so switching the button mid-note cannot split it across two grids) and a per-key ORDER GUARD (`chLastT`/`bsLastT`) never lets a chord/bass event land earlier than the previous event of the same owner key. `songNotes` still reports `orphans` — for material recorded before those slices, and as a permanent honesty channel — but the recorder no longer creates them.

**THE SHELL.** `openRoll` swaps the top bar for `#rollBar` and puts the transport into its `.roll` state (▶ plus ⏮). `main.loop` takes a different branch entirely: **the camera stream stays OPEN but is neither read nor drawn** (returning to play is instant and asks for no permission again) — and detection, the most expensive thing on the thread, is skipped. ⚠️ `processHands(null)` is still called EVERY frame on purpose: "no hands in frame" is what closes a held pinch through the ordinary watchdog and walks expression back to neutral; `latest`/`lastTs` are cleared each frame so leaving the editor cannot replay a stale detection as a pinch nobody made.

**REFUSALS GO BOTH WAYS, AND BOTH LIVE IN THE RECORDER.** `editOpen` refuses while recording or while a clip records; `onRec` refuses while the editor is open — ONE refusal covering every input, the ● button and the looper hand alike. ui only names the reason in words. A BACKING track (`ev.jam`) is **read-only for its NOTES** (`editBackingOpen`): a note edit inside it would survive `clearJam` as an orphaned fragment. The one exception is **timbre replacement** (below), which rewrites every event of the track and leaves nothing orphaned — `editGuard(backingOk)` admits it, and ↶/↷ on a backing track admit only a `'timbre'` history entry.

**ONE ROLE, NO TABS (T4).** Since T2 a track holds exactly one role, so the editor has **no role selector**: it opens straight onto the track's role, read by `recorder.laneRoleOf(layer)` in exactly two places (`ui.rollEnterTrack` — on open and on track switch) and kept in `state.rollRole` between them, because a track emptied by deletes has no events left to read a role from and ✚/↶ must keep working on the same axis. `rollRole===null` means the track had no notes when opened (the drone's layer, an armed track emptied and reopened): no axis, the grid is not a target, one line «No notes in this track» — ⛔ never a role the track never had. ⚠️ **Three of the four roles are editable today** — `ROLL_EDITABLE=['dr','bs','ch']` (chords since S2 of solo and chord editing); a solo track opens onto one line saying its notes cannot be edited in the roll yet (`roll.roleLater`, until S4) — freezing and the automation lane still work there.

**TIMBRE REPLACEMENT (T5).** The `#rollTimbre` select replaces the track's timbre — the ONLY way to change a recorded track's timbre (arming never switches it). **Within the role**: `a.inst` for solo/chords/bass, `a.kit` for drums, because roles store different kinds of note. `editSetTimbre` rewrites every note start and every solo `leadSet` that carries a timbre, each with a **fresh payload object** (as a move does); time and the frozen scale are untouched. It is **ONE history entry** (`kind:'timbre'`), goes through the normal `editCommit`, and a frozen track goes STALE (the freeze signature folds every event's timbre, T0) and plays its events in the new timbre. **The track's effects do not change** — the chain key follows the ROLE, and after recording the chain and its automation belong to the track. The picker lists entries only through **`audio.timbresOf(role)`** → `[{id, name}]` (see HANDOFF, «ХРАНЕНИЕ ТЕМБРОВ» — user-made timbres will live on the device in browser storage with stable ids, export/import by file, and a deleted timbre must not break a track that uses it; the same foundation as saving songs): today the built-ins with the index as id. A drone layer has no role and gets no picker. **⌫ / Delete** deletes the selection through the same function as 🗑 (`rollDeleteSel`), never while focus is in a text or number field.

**EDITING, WITH ITS OWN UNDO AND REDO.** `editGuard` is the single door (editor open, track alive, not a backing, transport PAUSED — it pauses by itself rather than editing under the look-ahead window). Every edit is a third event-creation site and obeys the same law as the other two: absolute time, `tk` on every event, `compactEvents` for removal, ONE `editCommit` (sort THEN `schedInvalidate`, plus `takeFxTouch`). ⛳ **↶ is not a second ⤺**: ⤺ removes a whole TAKE and is off-screen while the editor is open; ↶ removes ONE edit and exists only here. **Redo is not a mirror of undo** — a move carries BOTH states (`from`/`to`) while an insert and a delete are symmetric through one object reference — and **a new edit discards the redo branch** in the single history writer `editPush`, because an undone move describes a song that no longer exists. ⛳ **A compound edit is ONE entry (`kind:'batch'`, E1):** `editBatch(list)` takes sub-entries of the existing kinds (`move`/`ins`/`del`/`timbre`/automation), applies them forward through `editApply` in order, pushes once and commits once; undo walks them in reverse. Anything that changes several events at once (moving a whole note; E2's detach; solo and chord editing) is built from it — no new history kind per feature. **Dragging a bass note (E1):** a ONE-SEGMENT note (its head segment ends at its own note-off) moved in time moves WHOLE — start, inner volume changes and end together, as the ghost shows; if it would land on another note of the same owner key it takes a fresh `k` (as `editInsertBass` does). ⛳ **Independent notes (E2):** an edit that would touch a neighbour first DETACHES the edited segment of a glide (`detachPlan` → `commitDetach`, one batch): a note-off closes the left part at the segment's start, the segment's own events move to a FRESH `k` (a pitch-change event becomes a note start with the head's timbre, rebuilt as a new object), it gets its own note-off, and the pitch change that ended it becomes a note start under the old key. Then the edit applies to the detached note alone — a time move shifts all its events, a resize moves its own note-off, a delete leaves SILENCE — and overlaps are allowed (two keys, two voices). The price, paid only where edited: the slide into and out of that note becomes a release and a new attack. A PITCH-ONLY change never detaches: the new pitch goes on EVERY pitch-carrying event of the segment (the defining event and its inner volume changes), so the glide is kept. Resizing a segment that ends at its own note-off moves that note-off, drops inner volume changes past the new end, and takes a fresh `k` if it would grow over another note of the same key. The editor selects the event these functions return (the detached note's head can be a new object). `editKeyGap` (the old clamp between same-key neighbours) is gone — independence replaced it. ⛳ **Since S0 of solo and chord editing this machinery is role-general:** `recorder.EDIT_ROLE` holds, per pitched role, the note's start/end events, how a fresh identity is made (`k` above every `k` in the layer for bass and chords; for solo a note slot `v` above every slot in the layer — the solo key has no `k`), which key fields a note keeps (bass keeps `v`) and what a note-off under the old key carries; `keyClash`, `editMoveNote`, `detachPlan`, `commitDetach` and the three segment edits read it. ⛳ **Chords are editable since S2** with this same machinery (fresh `k` on detach, the chord-off under the old key, a chord change becoming a chord start): the axis is the bass axis (degree × register), and the chord's ROOT is its stored (degree, register). ⛳ **Since U1 ("a chord shown as its notes") a chord is drawn as EVERY note it sounds**, computed by the engine's own function: `scales.chordNotes(deg,oct,sc,sev,ty)` returns each note's frequency and interval, and `chordFreqs` (what `ENG.chOn/chSet` play) is defined as its frequencies — the arithmetic is untouched, the sound byte-identical. `draw.rollSegRows` places each note on a row when it is within 1 cent of the row's frequency (`scales.chordRowFreq` — the engine's root price on that row), otherwise BETWEEN rows at its true pitch: pure-ratio tunings (mobile Natural, Partch, Bohlen–Pierce — Pythagorean left this list in P2, its chords are read from its own grid) and pentatonic power chords put chord tones off the scale's rows, and the editor shows a just third sitting below the tempered row. ⛳ **Since U2 the chord axis is sized FROM THE TRACK** (`draw.rollChordTotal`, memoised on the shown group's segments + scale + tonic + A4): its top is the highest note the track sounds (by `chordNotes`) plus drag headroom (the track's widest chord stood on the top root row); its bottom is row 0, and no chord note can sound below it by construction (every type of all eight sets starts at its root and rises; untyped chords too; a one-note type is one of those notes). `ROLL_CH_EXTRA_REG` is gone. ⛳ **An off-row note is marked against THE SCALE ITSELF** (never equal temperament): `draw.chRowOfFreq` returns `{r, dev}`, `dev` = signed cents from the NEAREST row of the axis — the axis rows are the segment's own scale degrees in the chord register — and `draw.rollSegNotes` gives `[{r, dev}]` per note in `chordNotes` order (`rollSegRows` is its row-only view). The block is lighter with an outline in the role colour, and `rollDevLbl` writes the deviation («−22», U+2212) on it when it fits, else beside it while selected. The root is recognised BY FREQUENCY (equal to `chordRowFreq`), not by index, and stays on its recorded (degree, register) row — a one-note chord's only note may not be the root. The chord-name label is gone (the user's decision; S3, the type selector, is dropped). ⛳ **Selection has TWO LEVELS on a chord (U2):** the first tap selects the WHOLE chord (`state.rollSel` = its defining event; all notes white); a second tap without movement on one of its notes selects THAT note (`state.rollSelNote` = its index in `chordNotes`, the same order as the blocks; the other notes get a thin white outline); a tap elsewhere clears both; `setRollSel` always resets the note level, and every edit, ↶/↷ and track switch go through it. A one-note chord, bass and drums have one level. Dragging acts on the selection: the whole chord drags as before (root moves by the rows dragged — `rollGrab.grabRow`/`rootRow`, where `rollHit` returns the ROOT's pair row, not note 0's; the ghost draws the whole stack); with one note selected, a drag moves THAT note in TIME and a drag of its end (the length handle is drawn on the selected note) RESIZES it alone (U3) — the finger takes the note under it, of the same chord; the ghost shows only that note. ⛳ **U4: the same drag moves it to another ROW** — the target row is the row under the finger once the finger has LEFT the row it grabbed at (`ui.rollNoteTarget`); time and pitch together are ONE edit (`editMoveChordNote(ev, idx, t, deg, oct)`), and the ghost stands on the target row. After the dissolve the edited copy takes the row's CANONICAL FORM: the row's (degree, register) by `rollRowPitch` in the axis scale, and the one-note type **`scales.chordUnit(s)`** — the ROOT UNIT, the one-element type whose price is the root itself: `[0]` for the grid branch (semitone offset) and the equal branch (typed step sets and every untyped scale), `[1]` for the pure-ratio and period branches (ratios). It sits beside `chordNotes`, follows its gate order and holds no pricing; `chordRowFreq` (the row pitch the editor places notes by) is computed through it, so a moved note sounds exactly its row's pitch, read from the scale's own degrees. ⚠️ Rows here are the MODE's degrees: the user has since decided that TUNING and MODE are two layers — notes and chords are built from the tuning's pitches and the mode is a highlight (HANDOFF, «УНИВЕРСАЛЬНАЯ МОДЕЛЬ СТРОЯ»); dimmed tuning rows in the editor are planned, not built. An OFF-ROW note brought onto a row SNAPS to it; released without leaving its row it stays as it was and no edit is recorded; an on-row note returned to its own row changes nothing. A ONE-NOTE chord takes the same path (it is the note) and lands in the same canonical form (`editMoveSeg`/`editMoveNote` take an optional `ty`) — the whole-chord path moved its root while keeping its old `[iv]`, which in an untyped scale left it off the row the ghost showed. 🗑 and ⌫ act on the level: one note → `recorder.editDeleteChordNote` (the chord DISSOLVES — `dissolvePlan`: the segment is first detached exactly as E2 does when it sits inside a latched glide, then copied once per REMAINING note, each copy with the same root and register, the same frozen scale, a one-element type `a.ty=[that note's iv from chordNotes]`, its own fresh `k`, and copies of every inner volume/brightness event; the deleted note gets no copy; one `editBatch`, one ↶ restores it). ⛳ **U3 reuses the same dissolve for time:** `editMoveChordNote`/`editResizeChordNote` (through `chordNoteEdit`) call `dissolvePlan(seg, N, -1)` — every note gets its one-note copy, none dropped; each plan item carries `note` (its index in `chordNotes`) — then shift ALL the chosen copy's events by one delta (move), or move its note-off and drop its own inner changes past the new end (resize). Each copy has its own fresh `k`, so nothing can clash and no clamp is needed; `commitDetach` returns the chosen copy's head (`it.sel`), which the editor selects. A one-note chord falls back to `editMoveSeg`/`editResizeSeg`. The remaining notes sound exactly as before (voice level, filters and glide in `chordOn`/`chordGlide` do not depend on the note count or index); the price, only for a segment inside a glide, is E2's: its edges re-articulate. A one-note chord's delete is the whole-segment delete; a whole-chord delete is unchanged. A first-time-per-session toast (`roll.tapAgainNote`) teaches the second tap. Moving to another degree: in an untyped scale the quality follows the degree (C moved up a step in major becomes Dm — nothing is stored); in a typed scale the stored type stays and transposes. The segment pass compares chord types BY VALUE (`tyEq`), which changes nothing for recorded chords and is what one-note chords (U2) rely on. A degree-or-register-only change goes onto every event of the segment, so a latched progression keeps gliding into and out of it. `editInsertChord` takes the type of the chord selected before the tap (kept on the pan record — the tap itself clears the selection), else the nearest chord in the same scale group (⚠️ after a dissolve that can be a ONE-NOTE type — insert is unchanged until U5, where the user's insert rules land), else null (untyped) or the palette's first type; timbre from the nearest chord start (else the live `chIdx`), volume from the nearest chord event (else `editDefVol('ch')`), no brightness (absent = not set), a fresh `k`, the axis group's scale and seventh. Insertion is routed by role through `ui.ROLL_INSERT`. Solo is still NOT editable (S4) — the plan S1–S7 is in HANDOFF. History and future both die with the session (open, close, track switch): a reference to an event that outlived the session would one day point at nothing.

**THE SCALE IS THREADED THROUGH THE LABEL FUNCTIONS (S5.4), AND THAT IS THE POINT.** `noteLbl(deg, s=CUR())` — the single label function of hard rule #26 — now takes the scale explicitly and passes the same `s` to `swaraLbl`/`rowLabel`/`centsOf`. A track's rows must be drawn in the scale its events were FROZEN in, never the live one: open a raga track while the live scale is chromatic and the rows would otherwise read as chromatic names over raga pitches. The slice is invisible by construction — every existing caller gets the default.

**THE PITCH AXIS (S5.5; since T3 of the universal tuning model, ONE AXIS OBJECT).** ⛳ Since T3 every reader of rows — drawing, chord-row frequencies, chord-tone placement and deviation, axis height, the label gutter, hit-test, ghost and ui — goes through `draw.rollAxis(view, all)`, memoised per (view, All/Mode) and stored in the snapshot as `rollView.axis` (hard rule #9): `{ rpp, ents[{deg, j, bright, dup}], rowOf, pitchOf, snap }`. **All** (default, `state.rollRowsAll`): each register holds EVERY pitch of the TUNING above the mode's root — the mode's pitches BRIGHT, the rest DIMMED (only scales whose mode is smaller than its tuning have dimmed rows: 12-tone modes, maqams, ragas, Pelog patets). **Mode**: today's compact axis exactly — the rest of this paragraph. A thumb-sized «All / Mode» button in the editor bar (`#rollRows`) shows only when there are dimmed rows. Dimmed rows are named by the tuning's naming scheme (note/quarter-tone names via `stepName`, «swara · shruti» via `swaraOfCents`, else the tuning-pitch number in parentheses, «(4)»), bright rows by `noteLbl` — one naming function (rule #26). Chord tones are placed against the tuning's rows (`scales.chordPitchHz` prices a dimmed row in the chord register), so only ratio tones fall between rows in All. ⛳ **Since T5 a dimmed row is an edit target like a bright one** (the user's decision: the tuning gives every pitch, the mode highlights; EDITING may leave the mode, live play by hand may not): `axis.pitchOf` decodes any whole row to `{ti, oct}`, `recorder.slotPt` no longer asks the mode, and a bass note, one chord note (U4) or a whole chord dragged onto a dimmed row stores that tuning index — no alteration field, a pitch outside the mode is simply another tuning pitch. Ghost and drop share `draw.rollDragTarget(d, seg)` → `{row, pit}` (no snap; the finger has not left its row → the segment's own pitch). A whole UNTYPED chord moved onto a dimmed root keeps its shape — **option (a)**: `recorder.chordMoveTy(seg, ti, oct)` gives it its current intervals as a type (`segChordNotes(seg).map(iv)`), written by `editMoveSeg` and drawn by the ghost through the same function; it stays typed if moved back onto a bright row; typed chords move rigidly as before; on a bright row an untyped chord stays untyped. In the **Mode** view (no dimmed rows) an out-of-mode note is drawn BETWEEN its neighbouring degrees at its true pitch, with the off-row mark of U2 (lighter fill, role-colour outline, deviation in cents from the nearest degree, e.g. «+100») — `axis.placeTi(ti, oct)` → `{r, dev}`, read by `rollSegRoot`/`rollSegNotes`, so it is drawn, hit and dragged in time without falling onto a degree. Out-of-mode notes replay, chase and freeze from their index; the replayed chord highlight gives no slot (`hlOf` → null) and the voice registry records no degree. **Insert still snaps** to the nearest bright row (insert rules are U5); its one-time notice is `roll.dimInsert`. Rows are degrees × registers: `rollDegPerOct(s)=IVX(s).length`, `rollRowOf(deg,oct,s)`, `rollRowsTotal=REG_N*dpo`. ⛳ `IVX` closes the list with a **DUPLICATE TONIC** on top, so the top row of one register and the bottom row of the next are the SAME pitch — and that is not a bug: the recording stores the played `(deg,oct)` pair, and both spellings are playable. The roll lays out BOTH rows and rewrites no event; the duplicate is merely dimmed so the player can see why two rows sound alike. **A track holds ONE tuning view** (routing by tuning; since T4c-2 the editor relies on it): `draw.rollGroup()` takes the track's segments of its role in the view of its first segment, **by REFERENCE** (hard rule #25 — a name is not an identifier). The old multi-group machinery (ghost strips, the `#rollScale` chip) was removed in T4c-2.

**FITTING, LENGTH AND THE GUTTER (S5.6).** Rows FILL the height when they fit (stretched up to `ROLL_PITCH_ROW_MAX=30`, so a pentatonic no longer leaves half the screen empty) and fall back to the minimum `ROLL_PITCH_ROW_H=18` with scrolling when they do not — one deterministic rule, so nothing flickers at the boundary. A note's LENGTH is edited through **the segment's own ending event** (`endEv`): an open segment, or one closed by the `on` of a NEIGHBOURING note, has no handle at all — dragging it would move somebody else's beginning. The label gutter is **MEASURED, not guessed** (`rollGutterW`: the widest real label of the axis scale plus the widest register suffix, capped at 42% of the canvas, cached on (scale, tonic)) — it used to be a constant 58 px, and «Са · Чхандовати» simply ran off the left edge; the measured width goes into `x0` of the SNAPSHOT, so the drawing and `laneBeatAt` move together (hard rule #9).

**THE AUTOMATION LANE** under the note grid is part of the effects arc — see the next section.

### Effect ownership, capture and playback (slices O-0…O-4) — the arc that makes a track sound as it was played
**O-0 — THE CHAIN-OWNER KEY.** Everything in the effects layer is addressed by an opaque key (`chainKeyOf(role)` → `'role:ld'`), whose only value today is the role. ⛔ **The key is never parsed back** — equality and object indexing only — and its KIND travels beside it (`chainOwners()` → `[{key, kind}]`) rather than being read out of the string. That single field is why chains owned by a TIMBRE will later MERGE into the same tables instead of migrating: `chainOwners` is the one place that will name a second kind, and every walk over owners (capture, playback, the future render, freeze) stays as it is.

**O-1 — THE CHAIN IS SERIAL, AND THAT DELIBERATELY CHANGED THE SOUND.** Effects are applied AFTER the voices of an owner sum, in chain order, each module carrying its own wet/dry. ⛔ **Solo's per-note send amounts are GONE — deliberately, permanently, and irreversibly for material recorded before the change.** The `attach` flag was dropped from `reverb:mix` and `dly:mix` and `applyFx` no longer reads those two keys: an event recorded earlier still carries five keys, three are read (`vib`/`drv`/`trm`) and two are ignored — no error, no silence, no doubling; the layer's drive, vibrato and per-voice tremolo replay exactly as before, while its reverb and delay sound as the LIVE chain stands. **Why this is right:** there is one network per owner, a reverb is a model of a ROOM and a room is one for everyone in it, and every synthesiser and DAW sums voices and then processes them. Freeze will give back "this part in a different room" as a separate track with its own chain — the honest form of that wish.

⛳ **THE BOUNDARY IS THE SUMMING OF VOICES.** Everything below it is untouched and must stay untouched: volume (baked into the voice envelope), pitch, the theremin's live Hz, the recorded bend curve, DRIVE (a `tanh` shaper before the envelope — `env·tanh(x) ≠ tanh(env·x)`, so it can never move to the bus), per-voice VIBRATO (an LFO into `.detune`, with no audio input or output at all), per-voice tremolo, BRIGHTNESS (`kind:'voice'` on every role — `a.bri` on chords, `a.fx['bright:amt']` elsewhere) and GLIDE (`kind:'voice'`, solo and bass, `a.fx['glide:time']`) — each read by the voice from its own note. Above the boundary everything belongs to the chain.

**O-2 — THE LAW THAT REPLACED PER-NOTE VALUES: EVERYTHING PLAYED IS CAPTURED, PER TAKE.** `takeFx` holds, for each take: the **chain snapshot** at its start (composition and values, in chain order — `takeCapStart`), an **automation lane** of everything that then moved (`takeCapSample`, through the fine-recording automaton `fineStep` — see "Fine recording" under Part 5), and **composition changes with their times** (the reserved `FX_CHAIN='#chain'` entry carrying the id list — because values alone cannot express a removal or a reorder, and since O-1 a reorder is audible). ⛳ **The lane is sampled from the RECORDER'S HEARTBEAT** (`tick`, every `SCHED_TICK_MS`=25 ms, in SONG beats, after the count-in guard and after the look-ahead window has been served) and not from the gesture loop — which is the whole point of the shape: the heartbeat beats whether or not a hand is in frame, whether or not a pinch is held, whether or not a note is sounding, so "turned a knob while a LATCHED chord rang with the fingers open" stops being a case that cannot be recorded at all.

⛳ **CAPTURE WALKS THE PARAMETER DECLARATIONS — THIS IS THE RULE THAT KEEPS WORKING AS THE APP GROWS.** `fxCaptureChain`/`fxCaptureWalk` iterate the chain and, for each entry, `inst.params` — the descriptors built from `FX_FACTORY`'s `params` spec — emitting `(fxId, paramKey, v01)`. **A new effect is therefore recorded the day it is written, and its author has to remember nothing**: declare the parameters, and capture, playback, the editor's lane, its labels and its defaults all work. The two exceptions are declared just as explicitly: the old scalars (`vib`/`drv`/`trm`, no descriptor — one parameter named `FX_AMT`) and the expression hand's five channels (`EXPR_CH`, emitted under `EXPR_FX='expr'` for the solo chain). This is hard rule #29.

**⚠️ HARD RULE #23 IS CLARIFIED, NOT WEAKENED.** It says the expression hand never writes to an EVENT, and that is still literally true — there is no `a.expr`, and its pitch shimmer stays a live-only couple of cents. Its five OUTPUT scalars (`live`/`wah`/`text`/`space`/`engage`, snapshotted by `applyExpr` into `exprCur`) ARE captured, in the LANE, which is not an event and lives beside `events` with its own cursor and its own staleness point. The parallel is exact: the theremin's live Hz is never recorded either, while its audible RESULT is (as the recorded step plus the bend curve).

**O-3 — PLAYBACK READS THE CAPTURE.** `fxPlayBuild` merges the takes into one sorted list; `fxPlayDrive(x)` folds it up to the current song beat with a forward cursor (a backward jump refolds from zero — the same shape as the chase) and applies each value through the effect's own `setNorm`, so the setter's time constant IS the ramp and no second smoothing model exists. The COMPOSITION is honoured too: `fxPlayPath(key, ids)` makes `fxPathOf` read the recorded id list INSTEAD of the live chain while playing, opening and closing gates so tails still ring out. ⛔ **The live chain is never rewritten** — a person's chain and their finger layout are theirs, and a ▶ that overwrote them would be theft. On stop, `fxPlayStop` returns the path and pulls the sound back to the hand's aim.

⛔ **AUTOMATION DOES NOT DRIVE WHILE RECORDING, AND THE REASON IS NOT SIMPLIFICATION.** Capture and drive hang off the SAME heartbeat, two lines apart in `tick`. Were both live at once, the capture would read back the values playback had just written and record its own output in a loop. A value has exactly one owner at a time: the HAND while the transport is stopped, the RECORDING while it plays.

**O-3.1 — AIM AND SOUND ARE TWO VALUES.** `p.cur` is WHAT SOUNDS (written by the hand and by playback); `FX_AIM` is WHERE THE HAND IS POINTING (written ONLY by the hand, through the single door `fxParamsOf`). The bars draw the aim, so a player can set up a new sound while the loop plays what was already recorded — and a parameter currently governed by the recording is drawn hollow with a dimmed label (`fxIsDriven`). The pinch's relative drag reads the aim too, so the first frame of a pinch cannot jump. ⚠️ This changed only what is SHOWN: while the transport plays, the recorded material is still untouchable. ⛳ **Per-note parameters (V4b) are never hollow:** playback does not drive their live instance at all (their lane points are skipped by `fxLaneMerge`), so while the transport plays the hand's value sounds on live notes and each recorded note sounds its own — no hand-over of ownership happens for them.

**O-4 — THE AUTOMATION LANE IN THE EDITOR.** A strip under the note grid, opened by choosing an address in one select (whose first item closes it again). ⛳ **The time axis is not "kept in sync" with the note grid — it is the SAME axis**, read out of the same `rollView` snapshot (hard rule #9). **Part 1 — view and edit what was played:** the lane shows one address (owner, effect, parameter) across the WHOLE track, merged over its takes exactly as playback merges them; the left shelf is the take's chain snapshot (the level before the first point, which has no handle — moving "the state at the start" would be editing the snapshot, not the automation). ⛳ **The line is drawn as a STEP unless the segment is SMOOTH, and that is honesty, not style:** `fxPlayDrive` holds the last point's value until the next one arrives, so a diagonal where nothing interpolates would promise a glide that does not exist. A segment that is smooth — by the person's shape or because it leads into a recorded point (Part 5; recorded pauses are explicit hold points) — really is interpolated, and only that segment is drawn as a diagonal. Points are dragged with **one axis per gesture** — the axis latches on the first movement (vertical = value, horizontal = time) — the value snaps to **tenths near the point and single units once the finger pulls aside** (distance-dependent precision, which costs no screen space), the number rides beside the finger, and **TIME IS FREE: the lane ignores quantise on purpose**, because a note must land on a beat or the rhythm collapses, while an effect curve belongs to no beat at all. **Part 2 — add effects that were never played:** the editor can add, remove and reorder effects for one track. ⛔ They live in the TRACK'S CAPTURE (`rec.chains[key]`), never in the live chain — and playback picks them up for free, because `fxPlayBuild` already emits the snapshot as a composition entry. The add list offers the voice modules the track's role declared (`fxVoiceIdsFor`) as well as bus modules, minus every effect the track already has.
**Part 3 — PER-NOTE ADDRESSES ARE EDITED IN THE NOTES (V4b).** Before V4b, editing glide, vibrato, drive, per-voice tremolo or chord brightness in the lane changed nothing audible: each note carried its own value and replay read that, while the lane drove only the live setting — the lane showed one thing and another sounded. Now, for an address `fxIsPerNote` says is per-note (a module parameter with `attach:true`, or an old solo scalar), the lane is built FROM THE NOTES (`pnView`): consecutive note-carrying events (`pnCarrier` — `…On`/`…Set` and drum hits) with the same value form a run, and a point sits at each run's start (`pnPoints`; events marked as the inside of a smooth segment are not points). Since smooth automation every edit — value drag, time drag (clamped between the neighbours; dragged onto one it replaces it), delete, add, shape switch — edits the POINT LIST and hands it to ONE rebuild, `pnPlan`, which rewrites every event of the address from it; all through `editBatch` (one history entry, one commit, a frozen track goes stale). "Not set" is drawn at the role's default level with a hollow dot; between notes the line is dimmed (nothing sounds there; drums have no such gaps). Where the value lives is read from the declaration (`fxNoteField`: brightness is `a.bri` on chords, the `a.fx` map elsewhere). Removing a voice module from a track also strips its values from every note, in the same history entry. The capture's own points for these addresses are still WRITTEN (rule #29 — declared means captured; they are the only record of hand movement BETWEEN notes) but read by nothing that sounds. A point placed in the middle of a held note, where the track has no event, now gets an ANCHOR — a change event at its beat in every note held there (the old limit "an edit mid-note creates no new event" is lifted; glide is the exception, see Part 5). ⚠️ Named limit: editing glide over a recorded bass THEREMIN smooths its recorded steps, since those events are indistinguishable from ordinary bass notes.
**Part 3b — THE VOLUME LANE (VOL-3).** `autAddrs` lists **Volume first on every track with a role** — not from the capture snapshot, because every note carries `a.vol` (tracks without a capture have it too). It is a per-note address like any other (`pnView`, 0..100 axis = `a.vol`), with the rule #30 guards: never unset, the first point's delete takes the next value, and the shelf before the first point sits at the first note's volume rather than a default. ▲▼⊘ stay disabled on it (it is not in `autChainOf`, and `autChainMove`/`autChainRemove` refuse it). ⚠️ A continuous swell is dense: every recorded volume change (one unit apart since fine recording — ~100 points for a full sweep) is its own run and so its own point; the lane only draws the visible window, so it stays drawable, but reshaping a whole swell means moving points one by one — lowering a stretch in one gesture needs multi-select or a range-scale tool (the editor essentials).
**Part 4 — EFFECTS ADDED MID-TAKE ARE LISTED.** `autAddrs` appends the addresses of effects that entered the chain during a take (composition entries in the lane) after the snapshot's own, in order of appearance; their line starts at the effect's first point, with no shelf before it — the effect did not exist then. The editor will not add such an effect again (that would put it in the start snapshot and make it sound from the beginning), and ▲▼⊘ do not act on it yet (it is not in the snapshot they edit).
**Part 5 — SMOOTH AUTOMATION: A SEGMENT CAN GLIDE.** Every segment has a SHAPE, step or smooth, and the shape lives on the segment's END point ("how the value arrives here"). The line is straight in the NORMALISED 0..1 scale the lane draws in (on log parameters that is an even move to the ear, like the knob). ⛳ **A bus point's `sh` has THREE states** (slice "recorded automation smooth within a movement"): `'s'` smooth and `'h'` step are the person's shapes (a hand-placed point always gets one — `'s'` when a point precedes it, `'h'` after the shelf — and so does the ╱/⌐ toggle); **absent = a RECORDED point, and the segment into it is SMOOTH** (`recorder.autSmoothOf(prev, pt)`; slice "slow movement is movement" replaced the earlier gap/jump law, which drew slow movement — a unit per second and slower — as steps, because two points cannot tell slow movement from a pause). A pause is no longer a shape but DATA: fine recording finds it from ALL the samples between two points (`fineKnee`, below) and writes a HOLD point at the previous value where the hand moved, so the pause is flat and the rise starts exactly there. Every consumer calls the same function — `fxLaneSmooth` (so `fxPlayDrive`, `fxLaneExpand`, freeze and `R.live`) and `autPointsCalc`, which puts the answer in the lane view as `smooth` for draw and the ╱/⌐ glyph (draw never reads `sh` itself). ⛳ **An edited point keeps the shape you saw:** moving or deleting a point, or inserting one before it, first FREEZES the derived shape of the two segments it touches (into it, and into the next point) as `'s'`/`'h'` in the same history entry (`autFreeze`); other recorded segments stay derived. **Per-note values (volume, brightness, vibrato, drive, glide) follow the same law** (slice "recorded automation reflects the hand"): `pnPoints` gives each point `g0`, the beat of the LAST event of the previous run (the moment the value was last confirmed — after a pause, the recorder's hold event), `pnEffSh` → `autSmoothOf` gives the shape, and the view carries `smooth` and `g0` so draw starts the diagonal at `g0` (flat until then — the recorded pause). No events are added for a derived smooth segment: fine recording already writes the movement one unit at a time, which is exactly the density the editor gives a hand-drawn smooth segment's ramp events (`AUT_RAMP_EPS` 0.01), and the voice glides each step with its own τ (40–50 ms) — so a recorded glide sounds the way a hand-drawn one does. Hand-placed per-note points carry `'s'`/`'h'` (stored in `a.sh[addr]`); an edit freezes shapes as on the bus (`pnFreeze`; a frozen glide that began after a hold gets a flat point at `g0` in front of it, because the person's shape glides from the previous point). ⛳ **Fine recording** (`config` `REC_FINE_EPS` 0.01, `REC_AVG_S` 2 s, `REC_JUMP_EPS` 0.03, `REC_HIST_S` 20 s, `REC_PAUSE_S` 0.5 s, `REC_KNEE_F` 50; `recorder.fineStep`/`fineKnee`, ONE automaton for the bus capture and for per-note values — a payload is a vector of volume, brightness and effect-map keys): jitter and slow movement differ in CHARACTER, not size — jitter averages to zero, movement accumulates. Each value keeps 20 s of samples and records one-unit steps of its AVERAGE over a 2 s window (jitter, estimated at σ ≈ 0.002–0.006 depending on the path, shrinks by √N; a still hand moves the average by far less than a unit — the arithmetic is in config). Each unit is placed at the window's mean sample time — for steady movement exactly when the hand crossed it — and never before a raw sample reached it. A sample more than 0.03 from the window's average restarts the window, so fast moves are neither smoothed nor late. There is NO rest gate: movement as slow as a unit per five seconds (or slower) records as one continuous line. A PAUSE is found by shape: before writing a unit after a gap longer than 0.5 s, a "flat, then rising" fit to the raw samples since the last point is compared with a straight line from it; when the break explains the data F > 50 times better than jitter could, a HOLD point at the previous value is written at the break. Honest limits: a very gentle restart after a pause may not be detected (the first unit is weak evidence), and then the value may creep by at most one unit across the pause; at the beginning of a take (or after a brace seam) a hold is always written, at the break or at the earliest sample. The recording is slightly smoother than the live sound, which carried sub-unit jitter — the jitter is the camera's, not the hand's. Per-note value-only changes are written with their own explicit beat and are therefore NOT quantised any more (a chord or bass swell used to land on the quantise grid); pitch and chord changes still are, and push's per-key order guard keeps time monotone. The A/B switch for the bus law is `R.recSteps(true|false)` (see "Ear-testing a render"). The player switches the selected point with the **╱/⌐ button** in the editor bar (automation group; the glyph shows the current shape, a toast names the new one; one history entry, ↶/↷ cover it). It is a button, not a lane gesture, because a tap on the lane already means select/insert/deselect and a drag means move. **Bus parameters:** the shape is `pt.sh` on the capture's lane entry (`'s'`/`'h'`, or absent → the movement law); `fxLaneMerge` links each entry to the next one at the same address (`nx`) and marks snapshot entries (`snap` — a glide never starts from the shelf); ONE law, `fxLaneAt`, gives the point on the line, used by `fxPlayDrive` on every 25 ms tick and by `fxLaneExpand`, which unrolls smooth segments into points at the SAME tick step for the freeze render and the `R.live` ear test. Each value still goes through the effect's own setter (`fxPlaySet` → `setNorm`), whose time constant smooths the 25 ms steps into a ramp. ⛔ A native `linearRampToValueAtTime` was rejected: the setters are the single door (rule #29) and they are nonlinear (reverb decay becomes four line gains, tremolo depth writes two nodes), so a ramp on one AudioParam would move a different quantity than the lane draws. **Per-note parameters** keep their value in the note, so a glide inside a held note is written as CHANGE EVENTS (`pnPlan`): every event of the address gets its value from the point list (on the line inside smooth segments), and inside every held note overlapping a smooth segment the editor adds `…Set` events every `AUT_RAMP_BEAT` (1/16 beat) where the value moved at least `AUT_RAMP_EPS` (0.01) — at most ~100 per note for a full 0→1 sweep. Chosen over a ramp inside the voice because change events are already understood by replay, the chase, the freeze seams and the render: zero new sound paths, and freeze reproduces them by construction. Marks live in the payload, keyed `'fxId:pKey'`: `a.sh[addr]='s'` on a point entered smoothly, `'r'` on an event inside a smooth segment (not a point), `a.gen[addr]=1` on an event the editor generated for that address (anchor or ramp step; rebuilt on every edit of the address, kept while another address still needs it). The engine never reads them. A generated solo change carries `hold:true` only for a theremin note (the chase reads `hold` as "theremin" and would re-pitch an ordinary note to its attack degree). Glide (`readAt:'pitch'`, `fxNoteFollows` false) gets no ramp events and no anchors: the voice reads it only at a pitch change, and there it already sits on the line. ⚠️ Named limits: a NOTE edit (move, length, detach) carries the note's ramp events with it and does not rebuild the ramp — the next edit of that lane address does; anchors are placed only for a point with no event under it (a point on an event reaches other held notes at their next event, which protects per-hand values in polyphonic recordings); with several takes on one bus address, the lane draws a diagonal across another take's snapshot entry where playback steps (the same pre-existing gap as the shelf, which ignores later takes' snapshots).

### Ear-testing a render (`R.aud` / `R.live` / `R.stop`) — start HERE when a frozen track sounds wrong
Frozen tracks once had a phaser-like swirl (worst on SuperSaw) and a "scoop" into the first note. Two fixes made from reading the code (silencing effects absent from the recorded chain; freeing offline voices at release) were real defects but did not cure it. **The ear found the causes with this console tool, after code-reading had missed them twice** — so when a frozen track sounds unlike its events, use it before theorising:

    const R = await import(new URL('src/render.js', location.href).href);
    R.live(1)                        // the track's notes through the LIVE engine (transport must be stopped) — the reference
    await R.aud(1)                   // render exactly as a freeze would (same seed), play it at once — does NOT freeze anything
    await R.aud(1,{noHum:true})      // pitch humanisation ×0 (the random draw is still taken, so nothing else shifts)
    await R.aud(1,{expr:'neutral'})  // expression stage forced to live-neutral
    await R.aud(1,{expr:'bypass'})   // expression stage bypassed entirely
    await R.aud(1,{mono:true})       // mono sum of the output
    await R.aud(1,{recSteps:true})   // recorded bus automation as STEPS (the law before "smooth within a movement"), this render only
    R.recSteps(true)                 // recorded bus automation as steps EVERYWHERE (▶, the lane, R.live, R.aud, ❄); per-note lanes: drawing only (their sound is the events); R.recSteps(false) back
    R.stop()                         // stop whatever aud/live is playing; the chain goes back to the hand

`1` is the track's LAYER index, counted from zero (the strip's L2); since the stack slice the log prints the strip's L-number. Open the app with `?probe` in the address and `R` (and the probe `P`) are already on `window`. Each call prints ONE line naming what it changed. `aud` plays through the live frozen-track bus (`makeFrozenBus`), so it is heard exactly as a freeze would be. Nothing in the app changes: nothing is registered as frozen, events are only read, and the switches live in the render's engine copy (`audio.setDbg`) and are reset by every render. A new hypothesis = one more switch in `DBG` (off by default, changing exactly one thing) plus a line in `render.audDesc`. `live` follows the track's chain like the transport: the composition at its start, then every later composition change and automation point applied as its beat arrives (as `fxPlayDrive` does), smooth segments unrolled by `fxLaneExpand` at the same 25 ms step. So a smooth segment is ear-tested by comparing `R.live(n)` (the live engine) with `await R.aud(n)` (the render a freeze would make): the glide must be heard in both, at the same place and speed. Limit: `mono` exists only for `aud`.
**What the tool found, now the engine's behaviour (live AND render):**
- **A — a fresh attack sets its pitch** instead of gliding to it (see the V1 note in the solo-pool section).
- **B — a freshly built voice's oscillators start with scattered phases** (`audio.voiceStart`). They used to start together, in phase; SuperSaw's five near-evenly detuned saws then realign again and again — the swirl — and in the render every voice is built at second 0. Now each voice's first oscillator starts at once and the others start within ONE PERIOD of their build frequency, **with native waveforms untouched** (⛔ the user's decision: the fix must not change how any timbre sounds — an attempt with custom phase-rotated `PeriodicWave`s was reverted). Render: exact — voices are built while the offline clock is at 0 and the first note is ≥0.5 s later, so every oscillator is running, phase-scattered, before its attack; delays come from `rnd()`, i.e. the render's seed, so a refreeze repeats. Live: a voice is built at its first note, so on that ONE note per voice per session the other oscillators enter up to 4.5 ms (solo, 220 Hz), 1.3 ms (FM modulator) or 2.3 ms (chords/bass, 440 Hz default) after the attack, inside the rising envelope; the scatter is full for notes above the build frequency and partial below it. Covered: solo banks (via `mkOsc`) and both FM modulators. ⛔ **Chord and bass voices start their PAIR together** (`audio.voiceStartPair` — one random delay per voice, both oscillators at it): their two oscillators are built at one frequency and always glide together, so a scattered start FREEZES a phase offset forever, and where a timbre gives both the same frequency without detune (Sub sine sine+sine, Acid, Synth bass soft, Organ bass) that offset is a fixed cancellation of the fundamental, from full level to silence — one random draw per voice (the 'very quiet recorded bass' found after T4c-2: the frozen raga bass rendered 23× quieter on an unlucky draw, live voices drew their own). Voices stay scattered relative to each other, and the draw count is unchanged. Hard rule #3 holds — one start, at build.

⛳ **THE PRINCIPLE ALL THESE FIXES SHARE — keep it when touching the engine or the render.** A render is a **re-performance on a FRESH engine copy**, not a recording of the live one. The live engine carries history — voices already sounding near the right pitch, oscillators whose phases minutes of play have scattered, voices whose tails the next note cuts, effects a person switched off long ago — and the copy has none of it. That history is incidental and exists nowhere (even two live playbacks differ), so it cannot be reproduced; **the only fix is to remove the dependence: a note's sound must never depend on the engine's past.** Four dependences were found and removed, each now the behaviour live AND offline: the **attack pitch** (a fresh attack sets its pitch, A); **oscillator phase** (scattered at build, B); **voice reuse** (an offline voice is free from its release, as live — see the offline allocator); and **effect gates** (after a composition is applied, exactly that composition is open — `fxPlayPath` closes every built effect not in it, and the render opens and closes gates at the recorded beats). A fifth mismatch was plain arithmetic (master gain applied twice — `offlineTapMaster`). ⛳ **And the method: when a render sounds wrong, EAR-TEST before reading code** — code-reading produced plausible fixes that did not cure what was heard; the ear, with one switch at a time, found the causes.

### Backing (`🎵`) — two paths from one button: Jam, or Drums only
A tap on the **resting** button opens a tiny two-item menu (`#backingMenu`): **«Джем (вся подложка)»** (harmony + bass + drums, as before) or **«🥁 Только ударные»**. Picking one starts it immediately, so starting costs 2 taps; **every later tap switches the variant WITHIN the chosen path in one tap**, as before, and the cycle ends with OFF (back to rest → the next tap asks again). A **long-press / right-click** re-opens the menu without cycling to the end. The menu counts as "open" for the auto-hiding bar (`armBarHide` checks `backingMenuOpen()`) — it is anchored to `🎵`, which the collapsed bar hides, so it would otherwise drop out from under itself.

It's a **shortcut, not a mode**: both paths are ordinary looper layers, so the ⚙ panel, undo, and record all work as usual. Jam variants are keyed on **scale properties** (`supportsProgressions`/`supportsChords`, `edo===24` for maqam rhythm), selecting only from existing `HARMONIES`/`RHYTHMS`/`BASS_MODES`. The drums-only variants are `rhythmsForMetre(loop.metre)` — **filtered by metre**, so a person in 7 is offered only «Балканский 7», never rock; a metre with no patterns (5/10/12) **disables** the menu item with the reason instead of opening an empty cycle.

⚠️ **Known inconsistency between the two halves of this one button:** the jam path has a *cultural* gate (it picks by scale properties, so it won't put a backbeat under a raga); the drums-only path has **only** the metre filter, so under a raga in 4/4 it will happily offer rock, disco and hip-hop. That is a defect to resolve, not a design choice — one button should not have two standards of appropriateness. Fix belongs in BACKLOG §3.33 item 1, and must be **property-driven, never name- or index-driven**.

**Both paths go through `loadJam`, so there is ONE flag:** their layers carry `ev.jam` and `clearJam` removes exactly the backing, never player recordings (hard rule #14 unchanged — do NOT add a second flag). Honest consequence: a jam and a drums-only backing cannot coexist — switching paths clears the previous backing, exactly as switching variants does.

### The expression hand — few inputs, a RICH MIDDLE LAYER
Assign a solo hand the **`'expr'`** function («Выразительность») and it plays **no notes at all** — no owner, no pinch meaning, zone `'expr'` short-circuits everything. Instead it feeds a small dynamical system whose output breathes into the solo chain. **The liveness comes from the middle layer, not from the number of inputs** — this is the whole design and must not be "simplified" into direct parameter mapping:

- **Four features off RAW landmarks** (`exprFeatures`, hard rule #12 — `sx`/`sy` are never used here): **energy** (palm-centre speed in palm-sizes/s: position EMA'd *before* differentiating, then the *velocity* smoothed `tauV` *after*), **openness** (mean centre→5 fingertips / palm size), **tilt** (|vertical component| of the palm normal from landmarks 0/5/17, using MediaPipe `.z`), **finger spread** (mean *pairwise* tip distance — deliberately different from openness: a hand can be open-but-pinched or closed-but-fanned).
- **A rich middle layer** (`tickExpr` → `EXPR`): a **pump-and-decay resonator** on energy (`kPump`/`tauE` — moving pumps liveness, standing still lets the tone die), **an inertia spring** (`springF0`/`springZeta`, semi-implicit Euler) on **each** of the four channels giving overshoot-and-settle = "body", and an `engage` crossfade to neutral over `tauEngage` so a hand appearing or leaving never clicks.
- **Four channels → FOUR DIFFERENT AXES** (`applyExpr`, depths in `EXPR_A`): energy → **liveness** (a pitch+amplitude shimmer, `vibHz`), openness → **wah** (a high-Q peaking peak sweeping `wahLo..wahHi` logarithmically), spread → **texture** (morph between a SOFT and a HARD waveshaper — the *character* of the distortion, not its amount, with a lowpass after so it reads "dirtier" not "brighter"), tilt → **space** (delay send). **Why this split is load-bearing:** an earlier arrangement had three of the four channels pushing brightness, and the result felt like *one axis operated four ways*. Brightness was removed as an axis for exactly that reason. Do not re-point two channels at the same perceptual dimension.
- **Volume is NOT one of them.** It belongs to its address — the chain's Volume entry (the playing hand's Horizontal by default; a finger or Fixed if the player moves it, VOL-2) — and never to the expression hand: two hands must not fight over one quantity.

### Expression hand — three invariants that are not preferences
1. **The sub-step integrator is mandatory.** `tickExpr` runs the whole dynamics at a fixed `EXPR_CFG.subDt` (~8 ms) no matter how long the frame was. Without it the `springF0=2.5 Hz` spring **self-oscillated at frame rates below ~13 fps** — which is the real desktop rate with synchronous MediaPipe on the main thread — producing a constant 5–8 Hz wobble that had nothing to do with the hand. That was the mystery wobble. The `dtMin`/`dtMax` clamp on the frame `dt` is a separate guard (a stalled frame would otherwise explode the integrators); **it does not give stability — `subDt` does.**
2. **The dead zone is load-bearing.** `smoothstep(v0,v1,x)` returns **exactly 0** below `v0`, and it is applied to the *smoothed* velocity. A resting hand jitters at ~0.05–0.15 palm-sizes/s; without the dead zone that noise crosses into the resonator and the instrument "plays itself". Same for `orDead` on tilt and `sprMin` on spread. A resting hand must give exactly zero.
3. **The only pitch it may touch is a live-only shimmer.** `exprVibPitch` sums into the same `.detune` as vibrato and humanisation, bounded by `EXPR_A.vibCents` (a couple of cents). It is **never recorded** — like the theremin Hz (hard rule #11). Nothing about the expression hand enters an event payload.

Ownership: the **last expression hand that moved** owns the instrument (`exprMoveT`), so two such hands don't fight; the dynamics are state of the INSTRUMENT, not of the hand, so energy continues across an owner change. On screen it is deliberately **not a dashboard**: one «ВЫР» bar (energy) plus the hand-dot hue/size (openness/energy); texture and space are left to be *heard*.

### The tutorial — six lessons as DATA, chained, driven by real actions
`tutor.js` runs lessons **inside the live app** (real camera, real sound, real grid — you learn by doing). `LESSONS` is data: `{id, titleKey, descKey, steps, next, setup?}`; a lesson with `steps:null` renders as «Скоро» and can't start. Steps are data too: `{key, gate?, enter?, done?, final?, reveal?, skipIfDone?}` — `enter(acc)` zeroes exactly the field this step measures (so the previous step's action can't pre-satisfy it), `done(acc)` is a **pure predicate**, and `gate()` drops steps that make no sense in the current scale (chord steps under `supportsChords`, the palette step under `typedChords`). Adding a lesson = adding a record; the engine is not touched.

The six, in `next`-chain order: **basics → chords → tunings → looper → handfn → split**. Progress is a quiet per-lesson ✓ in localStorage (`handsong.lesson.<id>`), never a gate — any lesson can be started in any order. A final step is a CHOICE card («Дальше: <lesson>» / «Готово — играть»), never an auto-jump; `Skip` returns to the list without the ✓.

**Events, one channel.** Everything arrives through `hooks.tutor(kind,payload)`, emitted at the sites of the real actions (every one marked `ЗАЦЕПКА ОБУЧЕНИЯ` in `gestures.js`/`ui.js`/`recorder.js`) — the event exists **iff** the action happened, so nothing is recomputed in parallel and nothing can drift. `apply(kind,p)` folds events into the accumulator generically. ⚠️ **The hooks teach the CURRENT gesture model — change a gesture and you must move its hook with it.**

**Setup must leave the app in a state where the lesson's own steps can complete, whatever the previous lesson did.** This is the rule the found bugs all violated, and each fix is now in `tutorReset`/`setup`:
- **Hand functions bled forward.** «Функции рук»/«Две роли» rewrite `handFn.ld`, and free play rewrites `ch`/`bs`. Basics would then find the left hand *not* on effects, and Chords/Looper would find the chord hand on `hold` instead of `latch` — the latch step could never fire. `tutorReset` now restores **all** of `ld`/`bs`/`ch` to the `state.handFn` defaults.
- **A jam bled onward.** A loop or jam from the Looper lesson kept playing into the next lesson of the chain. `tutorReset` calls `tutorClearLoop()` (the same `clearRec()`+`resetJamDisplay()` as ✕), and the `lpJam` step re-clears so the jam lands on an empty song and is accepted at any metre/scale.
- **The Looper lesson landed on a chordless scale.** Tunings deliberately leaves the player on Пелог (`noChords`); the Looper lesson's overdub step asks for the Chords role, which would have been silent. Its `setup` switches to **`MAJOR_IDX`** (found by `edo:12 && iv==='0,2,4,5,7,9,11'`, not hardcoded). Likewise Chords and Split start on **`CHROMATIC_IDX`** (found by `typedChords==='chrom12'`, the only scale with the full type palette), and Split's setup order matters — scale FIRST, then `tutorSplitInit()`, which falls back to a **bass** right half if the scale has no chords.

**The strip hides itself under a working finger, driven by FOCUS.** With a panel open the strip collapses to one line (`.mini`); while a finger actually works *inside* the panel it fades out entirely (`.hushed`, `pointer-events:none`) and returns ~1.8 s after the finger leaves. The trigger is **`focusin`/`focusout`/`change`, not `pointerdown`/`pointerup`** — a native `<select>` picker swallows `pointerup`, so the pointer-driven version brought the strip back on top of the still-open picker ("it won't hide"). Focus arrives reliably and *stays* while the picker is open, which is exactly the condition wanted. `pointerdown` inside a panel also hushes (scroll/label taps that take no focus).

### Localisation — English default + Russian, and one identifier hazard
`i18n.js` holds `LANGS=['en','ru']` (the mechanism is shaped for four — `es`/`de` are deliberately empty until someone can check the musical terminology; a wrong translation reads to a native speaker as a bug). **Interface strings** live in `DICTS` and come out through `t(key,params)`; the fallback chain is current-language → `en` → `params.def` → **the key itself**, so a missing translation is visible rather than silent. Static markup carries `data-i18n` / `data-i18n-title` and is refreshed by `applyI18n()`; anything JS builds (dropdown options, composed button labels) is redrawn from an `onLangChange` subscriber. The canvas needs nothing — `draw` calls `t()`/`L()` every frame.

**Musical data names are localised INLINE, not in the dictionaries**, and the three shapes encode the editorial decision:
| Shape | Means | Example |
|---|---|---|
| a bare string | international notation, identical in every language | `'SuperSaw'`, `'II–V–I'` |
| `{default, ru}` | a **proper noun** — transliterated, not translated | `{default:'Tabla', ru:'Табла'}` |
| a full `{en, ru, …}` object | a **translatable word** | `{en:'Bell', ru:'Колокол'}` |

`L(field)` resolves any of the three (`lang` → `default` → `en` → `ru` → first value), so a plain string passes straight through.

**THE IDENTIFIER HAZARD, fixed — do not reintroduce it.** A display name is not an identifier. Two places were using one and would have broken the moment the names became objects: `demo.js` matched its scenes to scales by **`s.name`** (now `SCENES[].idx`, a stable index into the append-only `SCALES`), and `ui.fillScales` bucketed the scale menu by the **displayed** `grp` label (now `grpKeyOf(s)` — `s.grpKey` if present, else the raw `grp` — with `L(grp)` used only for the caption, so one group can't split into four by language). **Nothing else may key on a display name.**

## Standing working rules (apply to every slice — prompts no longer repeat them)

- **What a new session reads.** Start with `HANDOFF.md` **Part I** (≈200 lines: state, open decisions, the work order, limits, lessons) and this file. Open `HANDOFF.md` Part II, `BACKLOG.md` or long code files **only for what the slice needs** — search by name (`grep`) rather than reading top to bottom. The project's current state, open decisions and work order live in HANDOFF Part I only; this file holds the code model and the rules.
- **Never** run the app, a dev server, a build, a browser, headless Chrome or tests, and **never** a git command; never commit. Verifying the app is the user's job, in the browser.
- **Node — STATIC CHECKS ONLY** (approved by the user): `node tools/check-static.mjs` (syntax of every module via `node --check`, every static import name against the target's exports read with comments STRIPPED, every name in an export list declared, every literal dynamic import target present, and — since the T4c-1 fix — no call to a `function name(…)` declared in or imported into the module passes MORE arguments than it has parameters; unused exports/imports are information) and `node --check` on changed files. ⛔ Never execute application code in node. **Every slice report states that the static checks passed** (or what failed).
- **Read `src/` before changing anything**; re-verify every line number — never rely on memory or on a previous session's numbers.
- **Code comments in Russian.** New user-facing strings need keys in BOTH `DICTS.en` and `DICTS.ru`, English first.
- ⛔ **Never insert a comment into the middle of an export list**, and re-read every export list you touch with comments in mind (a `//` mid-line once silently dropped names and broke a lazily loaded module — the checker now catches it).
- **If you change a function's signature or a stored field's meaning, find every reader** (positional callers included — hard rule #15). ⛳ **The probe module (`src/scaleprobe.js`) is a caller too** — T4c-1 dropped an argument from `chordNotesAt`, missed one probe call, and that row threw (the extra argument shifted every other one, so a register number arrived where the view was expected). **The slice report LISTS every positional caller of every changed function**, app and probe, each with the arguments it now passes. The static checker flags a call with MORE arguments than the declaration; it cannot see a call with the same or fewer arguments in a new meaning (a reorder, or a dropped argument that a later default silently fills), so the listing stays the real guard.
- **Stay inside the slice.** Defects found outside it are reported, not fixed.
- **Probes** (`src/scaleprobe.js`, console): every probe works with the song loaded and WITHOUT the editor or hands open, covers DERIVED paths (chase, ghost, selection, dissolve, highlights — not only stored events), and is accepted only at zero. Song checks prove nothing on a thin song: `await P.seed({replace:true})` builds a deterministic test song through the recorder's own funnels, and `P.all()` runs everything into one table and refuses to call a thin song a pass.
- **Report format:** documents changed; files changed with a one-line reason; console lines and their output at zero; the static-check result; anything left undone; the running "docs found stale" list. Never report a change as verified in the browser — say which steps the user must check.

## Conventions

- Terse, comment-heavy, single-letter helpers, compact lines. Match it.
- Add a feature in the module that owns it:
  - a **scale** = one entry in `SCALES`, **appended at the end** (index is `scaleIdx`; `state` and `sameDegrees` depend on it). Menu position is set by `trad`/`grp`, not array position — `fillScales` buckets by `grp` key.
  - a **cents (non-equal) scale** = same, plus a `cents:[...]` array (`length === iv.length`); keep a valid `edo`/`iv` as nominal structure. Home section: `easia`/`india` for world tunings, `europe` «Европа историческая» for the historical 12-note tunings, `exp` for Partch. It may be `noChords` (gamelan/pelog) OR carry `typedChords` with a **ratio** family set (Partch/mobile Natural — priced by the pure-ratio cents branch) OR `gridChords:true` + an integer-step set (Pythagorean/Natural-fixed/meantone/well temperaments — priced by the fixed-grid branch). A **historical fixed tuning** additionally gets **`fixedKey:true`** (tonic = key, an anchor note — C historically, real-note-name labels — see "fixedKey"); the C-anchored `cents:[...]` array is the tuning's recipe from C (`anchorOf`/`keyOf` move it when the scale is `tunable`).
  - a **non-octave scale** = a `period:<n>` (`3` tritave, `3/2` fifth…), `edo`/`iv` equal within that period, section `exp` «Эксперименты» (bounded by tuning). `periodOf` carries it through pitch/labels/register — never add a `2` literal. `noChords`, or a **ratio** family set priced by the period branch (BP `'bp'`). `rectGrid` (the layout DEFAULT) only if `(iv.length)%4===0` — the closed form is octave-only, so a non-octave scale gets no `+1`.
  - a **typed-chord family set** = one entry in `CHORD_FAM_SETS` keyed by a scale's `typedChords` value; **integer steps** for an edo/`gridChords` scale, **or plain-number ratios** for a cents/period ratio scale.
  - a **rhythm pattern** = one entry in `RHYTHMS`, **appended at the end** (`ui.js` holds positional indices `JR_BACK=0`/`JR_MAQSUM=1` — never insert in the middle). Declare `beats` and, if the beat is divided in three, `sub:3`; the grid must be exactly `beats*sub` cells or `gridOk` skips the pattern. Write it in **rows** (0 kick/1 snare/2 clap/3 hat), never tuned to one kit. Cell volumes are in the OLD drum scale like every existing pattern (`buildArrangement` converts them with `config.volFromOld('dr', …)`) — don't pre-convert them.
  - a **timbre/kit** = an entry in `LEAD_INSTR`/`CHORD_INSTR`/`BASS_INSTR`/`DRUM_KITS`. ⚠️ **The index IS the identity today** — it is what `a.inst`/`a.kit` store in every event — so an entry may only be APPENDED, never inserted or reordered, or every recorded track silently plays a different timbre. ⛔ **A SOLO timbre cannot even be appended:** the Karplus–Strong banks must sit at the TAIL of `LEAD_INSTR` (`LEAD_KS_FROM = LEAD_INSTR.length − KS_BANKS.length`, and `buildLeadBanks` builds by position), so a new solo timbre either lands inside the KS block or shifts it — and retargets every recorded KS note either way. The user has excluded that: stable timbre ids are a prerequisite for the first new solo timbre (HANDOFF, «ХРАНЕНИЕ ТЕМБРОВ»). Chords, bass and kits may append. The track editor's picker lists timbres only through `audio.timbresOf(role)`.
  - a **gesture/timing threshold** or palette geometry = `config.js`. **Expression-hand numbers are split by side on purpose:** feature→channel (dead zones, smoothing, spring) in `gestures.EXPR_CFG`, channel→depth/range in `audio.EXPR_A` — gestures imports audio, so the reverse would be a cycle.
  - a **hand function** = an entry in `state.handFn` defaults + `ui.HANDFN_OPTS` + a branch on `S.fn`/zone in `gestures.js` + a dictionary key.
  - a **lesson** = one record in `tutor.LESSONS` plus its step records and `tutor.<key>.prompt`/`.detail` dictionary keys; its `setup` must make its own steps completable from any previous lesson. Don't touch the engine.
  - a **user-facing string** = a key in `DICTS.en` **and** `DICTS.ru` (chrome), or an inline `L()`-shaped name next to the data (musical names).
  - a **behaviour gate** = a scale property + a predicate in `scales.js`, never a `tag`/index check.
  - a **path that creates or removes events** (the piano roll IS the third one, and it is written — `editInsertHit`/`editMoveHit`/`editDeleteHit`/`editMoveSeg`/`editResizeSeg`/`editDeleteSeg`) = stamp `tk`, keep `t` in absolute song beats, choose `a.v`/`a.k` that don't collide with what the track stores, remove with `compactEvents`, then call `schedInvalidate` exactly once — sorting first if a take is being recorded (see "Time, tracks and the recorder" and hard rules #27/#28).

## Hard rules — do not break these

1. **AudioContext is created only inside the `#startBtn` click handler.** ⚠️ **An `OfflineAudioContext` is NOT covered by this rule, and that is not a loophole — the rule exists for the autoplay policy, which governs contexts that reach the speakers.** An offline context plays nothing, has nothing to unblock, and is created later, on a deliberate action. Since slice F0 of the freeze arc, `initAudio(mkCtx)` takes an **optional** context factory (defaulted, so the live path is the same line it always was); only `src/render.js` passes it. ⛔ Do not "fix" that branch back — it reads like a breach and is not one.
2. **Never hardcode frequencies, note tables, or the octave `2`.** Pitch derives from `baseF()` and the current (or frozen) scale — `P^(iv/edo)` with `P=periodOf(s)`, or the `cents` overlay `2^(cents/1200)`. A literal `2` in a register/step/period path breaks the non-octave tunings (BP, Carlos) — use `periodOf`.
3. **Pool oscillators start once and never stop** (solo/chord/bass gated by GainNodes; per-hit drums/metronome/drone LFO are the exception). Solo voices and their banks are built **lazily** and then obey the same rule — that is precisely why a voice's banks are **cached and gated**, never torn down and rebuilt: a started oscillator lives until the context dies. ⚠️ **The offline engine copy (`src/render.js`) is a SECOND INSTANCE OF THIS RULE, not an exception to it:** it has its own oscillators, which live exactly as long as its own context, and inside that context the same discipline holds — started once, gated, never disassembled.
4. **The master limiter stays.**
5. **Lower layers never touch the DOM** — `audio.js`, `arrange.js`, `recorder.js` reach the UI only via `hooks`. `draw.js` is exempt.
6. **Live bindings — write state only through its setter**, never a module-level `const`. The looper re-reads `baseF()`/`CUR()`/the chord rule every step.
7. **Per-event scale freeze is the polymodality mechanism** (`sc`/`sev`/`a.ty`, and `cents` rides on the frozen `sc` — including for **chords**: a frozen Partch chord layer replays in just intonation via the `chordFreqs` cents branch on `ev.sc`). ⚠️ **`sc:CUR()` freezes a REFERENCE to the scale's VIEW, not an index and not a name.** ⛳ Since T2 of the universal tuning model `CUR()` returns, for EVERY scale, a VIEW — (tuning, mode, anchor) as one object memoised per (mode, anchor) by `scales.scaleView`: a copy of the scale's fields plus `mode` (the `SCALES` object), `tuningRec` and `anchor {policy:'tonic'|'C'|'choice', from}` — so every event freezes its tuning, mode and anchor. The same mode and anchor ALWAYS give the same object; editor grouping (`rollGroups`/`rollHit`), the editor's row/label caches, `rectLayout`'s memo and the chord-insert type lookup all rely on that identity. ⛔ A bare `SCALES` object must never become an event's `sc` (only `CUR()` or another event's `sc`), or one scale would split into two groups. ⚠️ **The chord type `a.ty` is usually a reference into `CHORD_FAM_SETS` too — but since U2 not always:** dissolving a chord (deleting one of its notes in the editor) writes ONE-NOTE types, fresh arrays `[iv]` that exist in no palette. Nothing may compare `a.ty` by reference or look it up in the palette: compare by value (`recorder.tyEq`), and price it only through `scales.chordNotes`, which reads the numbers. ⚠️ **Since P3 of the "tuned from" arc the frozen `sc` of a Pythagorean event is a VARIANT of the scale object (since T2 — the view, one per anchor)** (`scales.scaleView`: one memoised copy per anchor) — so the reference freezes the scale AND the note it is tuned from, and a scale's identity in an event is the pair (scale, tuned from). A saved file will have to write both (BACKLOG §1). In memory that is exactly right — replay survives array reordering, renaming and localisation. But **the reference itself cannot be serialised.** Since T0 every scale carries a stable string `id` and a `tuning` id (and `scales.viewIdOf` names a view as id + «tuned from»), so a saved file CAN write down which tuning and view a layer used — the ids are the serialisation boundary, not yet wired to any file format. Stable ids for USER-MADE tunings, and Scala readiness (exact ratios, degree names as data, import normalisation, a round-trip probe — HANDOFF/BACKLOG), remain prerequisites for saving and for the scale constructor. Don't design either feature around the object reference.
8. **The video draw and `detectForVideo` read the same camera frame** (`drawVideoBackground()` before detect, `drawOverlays()` after, one synchronous tick).
9. **There is ONE layout; never reintroduce a mode gate.** PC/`uiMode` are deleted. New behaviour keys off scale properties and `splitOn`, never a `uiMode`-style global branch. **Hit-test and render must derive geometry from the SAME frozen range** — the hand's `S.role`/`S.rx0`/`S.rx1` (frozen at capture) and the single-source helpers (`phoneHalves` for halves, `palSplitX` for the internal split, `rectBandY`/`rectRows` for bands). Two independent copies of a boundary will drift and the finger takes a different cell than it sees.
10. **The split's role pair stays two distinct roles.** `SPLIT_ROLES` is mutated only via `cycleHalf`, which skips the other half's role — keeping solo+solo, bass+bass (and chords+chords, drums+drums) unreachable. The reason is no longer "single-voice chains" (solo and bass can both be polyphonic now); it is that **every piece of per-ROLE state is single-valued**: one effect chain per role, one sticky register (`rectOctReg`), one voice mode, one latch (`'latch'`), and in the lead mode ONE voice (`monoOwner[role]`) — two halves of one role would share all of them, and in the lead mode would fight over the one voice. Don't add a path that sets both halves to the same role.
11. **Continuous-pitch overrides ride a live-only channel and are NEVER recorded.** The theremin Hz is the named option `live` of `ENG.leadOn` **and `ENG.bassOn`** (every ENG entry has the one shape `(a, ctx, {when, live, own})` since slice S2 — the old positional extras are gone because a time in seconds once could have landed in the Hz slot), passed only by the live `WleadOn`/`WbassOn`; replay never passes it and derives pitch from the frozen `deg/oct` (solo adds its recorded cents curve `a.bend`). Do not fold live Hz into the event payload — for solo or bass. ⚠️ **"Never recorded" is about the EVENT, and the capture is not an event.** Since O-2 the effect values a hand plays ARE written down — into the per-take automation lane beside `events` — and that is not a breach of this rule: the theremin's live Hz is still absent from every payload, while its audible result rides as the frozen step plus `a.bend`. What stays live-only under this rule is the same set as before: the continuous Hz, the per-attack humanisation (fresh at every attack, see the non-determinism limit), and the note layout.
12. **RAW vs REMAPPED coordinates stay separate; the detector always gets the full frame; the picture and the remap share ONE crop.** `detectForVideo` reads the uncropped `<video>`. Gesture math (pinch/hand-size/Z-reverb/FX-drag/thresholds) uses RAW `lm.x`/`lm.y`; on-screen position and hit-testing use `sx`/`sy`. The video is **cover-fitted** (`config.coverView` → `state.viewRect`, written each frame by `drawVideoBackground`) so it never stretches; the SAME `viewRect` is the `drawImage` source rect AND the `sx`/`sy` remap — never let them diverge (the drawn hand would land where the finger is not). Never clamp coordinates or rendering — only the resulting selection saturates. A new `1-x`, a second copy of the crop/remap, or feeding cropped pixels to the detector all break this.
13. **Mirroring has one source.** `camFacing`/`mirrored()`/`flipX` decide it; the video draw and every landmark→screen conversion read them. Never scatter a `1-x`.
14. **`clearJam` deletes only `ev.jam`-flagged events.** The flag is intrinsic to the event so player recordings (never flagged) are safe. Don't switch jam-clearing to layer numbers.
15. **Track events are scheduled AHEAD at explicit times; the `when` option stays.** `scheduleLayers` fires chord/bass/drum events at `loop.t0 + (ev.t + off)*spb` within `SCHED_AHEAD`, where `off` is 0 without repeat and, while the brace cycles, the whole-pass offset of the REGION BOUNDARY the window was split at; live calls default to `AC.currentTime`. Never collapse voice functions back to "fire now" — that reintroduces the main-thread-blocking drift the window fixes (see "Scheduler"). ⛳ **The time is ALWAYS the LAST argument, with no exception left:** every argument added to a voice function since — `deg`/`oct` (P1), `glide` (V1), `tie` (T3, moved before `when` in V2), `bri` — sits BEFORE `when` (e.g. `leadOn(owner,freq,vol,ins,deg,oct,glide,tie,when)`, `bassOn(owner,freq,vol,ins,deg,oct,glide,bri,when)`, `leadOff(owner,tie,when)`), and every positional caller that passes a time fills the new slots explicitly (`leadOff(k, undefined, at)`). Three slices (P1, V1, V2) each found a caller that would otherwise have put the TIME into the new slot and sounded the note at second 0 — check every positional caller, the render probe included, whenever a slot is added. An explicit `null` in the glide slot means "no glide of my own" (the default applies), never a zero time constant.
16. **`fixedKey` scales are tuned from an ANCHOR note, and the tonic is a KEY within that grid, not a multiplier.** The five historical temperaments (Werckmeister, Vallotti, Kirnberger, meantone, fixed Natural) are ALWAYS tuned from C, as historically — no selector, and the panel says so. **Pythagorean is no longer always anchored to C** (P3): it is `tunable`, and its anchor is its «tuned from» choice — following the tonic by default (then it IS the mobile path, and every key sounds alike), or a fixed note (the key colours of a historical harpsichord). Every `fixedKey` branch of `leadFreq`/`bassFreq`/`chordFreqs`/`centsOf`/`tonicFreq` reads `cFix(s)`+`fixedSlot` through `anchorOf`/`keyOf`, and `anchorOf` reads the anchor from the scale OBJECT (`s.tunedFrom` on the variant), never from live state — that is what freezes it in recorded events (#7). Labels use real note names. Don't route a C-tuned temperament through the mobile `baseF()·2^(cents)` path — it would erase the per-key character (C gentle, F# tense) that is the entire lesson; and never let `anchorOf` read `state.tunedFrom`, or moving the selector would silently retune every recorded Pythagorean track. `fixedKey` is a **separate** property from `gridChords`.
17. **The A4 reference has exactly ONE source.** `aRef` (state) feeds `a3()` → both `baseF()` and `cFix()` in scales. Never add a second copy or a per-family reference — mobile and fixed scales must move together, or a `415 vs 440` mismatch surfaces as a "detuned instrument".
18. **In split, hand functions are consulted PER HALF by that half's role; the old fx-hand hardcode is GONE.** `handFnOf(key, h.role)` decides `fx`/`note`/`hold`/`therm`; the default `handFn.ld.L='fx'` *derives* "effects on the left hand in the solo half". Do not reintroduce a hardcoded special case — one source of truth (`handFn`).
19. **Chord voices keep TWO filters; never merge `f` and `fb`.** `f` bakes the attack envelope (timbre, once at attack); `fb` carries continuous brightness (`bd`/`a.bri` expression, `setTargetAtTime` all note). On one node a brightness change would fight the scheduled attack ramp and permanently couple timbre to expression. Brightness lives per-voice (not a shared bus) so per-track isolation holds via the owner key (`'latch'` vs `'loop:'+layer[+':'+k]`) — the live hand can't repaint a replayed track. `a.bri` is recorded from the chord chain's `bright` parameter; there is no separate ЯРК bar any more. ⚠️ **Brightness stays BELOW the summing boundary and must not be "unified" with the serial chain** (O-1): it is `kind:'voice'` — no nodes at all — precisely because the value is read by each voice at its own attack, which is what keeps a replayed track's brightness its own. Everything ABOVE the boundary (reverb, delay, bus tremolo) processes the sum and has no per-note value at all. ⚠️ **This rule is about the CHORD voice.** Brightness is declared for every role, and solo, bass and drums implement it differently — a per-voice brightness stage beside the untouched output (`makeBriStage`) and a per-hit filter only when set (see "Brightness on every role"); none of that touches the chord voice's `f`/`fb`, and none of it is a licence to give chords a third brightness path.
20. **The live chord (`'latch'`) survives the REGION BOUNDARY; only the tracks' own voices are released there.** There is no loop wrap any more; the boundary exists only while the brace cycles. At each seam `liveWrapRelease` cuts the live SOLO voices and the live bass (a still-pinched hand re-attacks them next frame) and `releaseLoopLayersAt` releases the track owners (`'loop:'`/`'bassloop:'`/`'leadloop:'`). Never add `chordOff('latch')` there — `chordGlide` can't rebuild deleted voices, so it would cut a held/latched chord that belongs to the hand. ⚠️ Do not confuse this with the RECORDING: since the per-pass closing the recorder WRITES a `chOff` at the pass end and a fresh `chOn` at the pass start for a held chord (`recFoldRoll`). That is events only, never a call on the live voice.
21. **Looper-hand commands fire ONCE, from the pinch-capture block.** `fireLooperCmd` runs only on the `false→true` pinch edge (structural single-fire); held frames take a different branch. The pinched finger is frozen for `'loop'` (and `'hold'`) hands so drift can't fire a second command. Don't move command dispatch into a per-frame branch.
22. **The expression hand's liveness lives in the MIDDLE LAYER; keep the sub-step, the dead zones, and the four distinct axes.** `tickExpr` integrates at a fixed `subDt` (~8 ms) regardless of frame length — remove it and the spring self-oscillates below ~13 fps (the real desktop rate), which was the mystery 5–8 Hz wobble; the `dtMin`/`dtMax` frame clamp is a separate guard and does **not** replace it. `smoothstep` must return exactly 0 below the dead zone or a resting hand's detector noise plays the instrument. The four channels must stay on four **different** perceptual axes (energy→liveness, openness→wah, spread→distortion character, tilt→delay) — three of them once pushed brightness and it felt like one axis operated four ways. Everything reaches the nodes through `setTargetAtTime`, never direct assignment, and every node is identity at neutral. **Volume belongs to its ADDRESS (the chain's Volume entry — the playing hand's Horizontal by default, or a finger, or Fixed), never to the expression hand** (VOL-2; before, "volume stays with the note hand").
23. **The expression hand never writes to an event.** Its only pitch effect is `exprVibPitch`, a live-only shimmer of a couple of cents summed into `.detune` — same discipline as the theremin Hz (#11). No `a.expr`, ever. ⚠️ **CLARIFIED BY O-2, NOT WEAKENED:** its five OUTPUT scalars (`EXPR_CH` = `live`/`wah`/`text`/`space`/`engage`, snapshotted by `applyExpr` into `exprCur`) ARE captured — under `EXPR_FX='expr'` in the per-take automation LANE, which is not an event, carries no `a.`-anything and never reaches a payload. The rule's letter and its purpose both hold: nothing about the hand enters the event format, while a re-render can still reproduce what it did. Adding a sixth channel means adding it to `EXPR_CH` — never to an event.
24. **`hooks.tutor` is the tutorial's only input, emitted where the action really happens.** Never recompute a lesson's condition in parallel — the event must exist iff the action did. The hooks teach the CURRENT gesture model: change a gesture, move its hook with it. `done(acc)` predicates stay pure (`apply` does all mutation), and **every lesson's `setup` must leave the app able to complete its own steps whatever the previous lesson did** (scale, `handFn` for all four roles, the note layout, and a clean song — see "The tutorial").
25. **A display name is never an identifier.** Musical data names are localised inline (`L()`), so matching on `s.name` or bucketing by a shown `grp` label breaks by language. Use stable indices (`demo.SCENES[].idx`) or stable keys (`grpKeyOf`). This already bit twice; don't make it three.
26. **The note layout is a per-frame CHOICE, resolved once and applied to all three note-roles identically; labels follow the SCALE, not the layout.** Six parts, every one of them a real defect that was waiting to happen:
    - **One resolver, one arithmetic.** `scales.rectGrid()` is the only place the layout is decided (`rectEligible × state.rectPref`, scale property = the `'auto'` default), and **`rectLayout` is the only place the geometry is expressed** — `k`, `dup`, `octaves`, `hasReg`, band counts, all of it. Never re-derive it, never read `s.rectGrid` as if it were the layout, and keep `'auto'` the default — a boolean would carry one scale's layout onto the next. **No literal `4` on the rect path:** notes per rectangle is `k`, the band→rectangle offset is `regBands`, the register count is `REG_N`. A surviving `4` is silently wrong only at `k≠4` — the hardest kind to notice.
    - **The highlight needs the (degree, register) PAIR, never the degree alone, and it is a SET, never one note.** With several periods on screen one degree lives in several rectangles; the register travels beside the degree (`latchOct` / `curChordOct` / the voice's own `deg`/`oct`) and `rectSlotOf` (the inverse of `rectNoteAt`) finds the rectangle. A bare degree lights the lowest block — correct on exactly the scales that worked before, wrong on every multi-octave one. For the same reason the latch identity is (degree + **register** + type). **And since solo went polyphonic the highlight is a `Set`** — `drawGrid`/`drawRectGrid`/`drawThereminLines` all take one, a rectangle lights if *any* of its notes sound, and each sounding finger lights its own legend line (two hands in one rectangle light two). ⛔ Never collapse it back to a single value: it was a single value written in a loop over hands, so the last hand won and the other rectangle stayed dark.
    - **The playing tag lists EVERY note the hand sounds**, Hz and cents each, taken from `leadHold` (same source and same reason as the highlight) and composed with the chord readout's own degradation ladder (`fitLeadNotes` → `packSegs`: all with cents → cents on the first three → Hz only → `…`, never a number cut in half). **One tag per hand, at that hand** — each hand has its own position, volume and chord, and a single combined list would sit beside one hand while describing the other's notes. ⚠️ **With ONE note sounding the old two-line tag is used verbatim**; the multi-note form starts at two.
- **The solo highlight set comes from `audio.leadHold`, not from `HANDS`.** `leadHold` is the register the engine itself uses to decide what sounds, and each voice's `deg`/`oct` are written by `leadOn` — the same call that starts the note, with no second write path — so the picture cannot lag or contradict the sound (the discipline that fixed the chord Hz readout, which reads `chordHold` rather than recomputing). `HANDS` is *intent*: it would keep a rectangle lit after a voice was stolen. **Live hands only** (`'lead:'` prefix) — replayed layers (`'leadloop:…'`) deliberately do **not** light, or a busy loop would set the whole grid glowing and the highlight would stop meaning "what your hands are doing". **Bass follows the same law since V2**: its set comes from `audio.bassHold`, live keys only (`'bass'` in the lead mode, `'bass:…'` in the polyphonic mode; `'bassloop:…'` does not light), with `deg`/`oct` written by `bassOn`/`bassSet` (P1). It used to be read from `HANDS` as one value, and with two hands in the lead mode it could light the hand last in the walk rather than the one that owned the voice.
    - **The idle finger must be visible.** Where `k<4` the extra fingers play nothing (never a substitute note); the legend draws them as a dim `—`, and a pinched idle hand still gets a dim ring plus `tag.idleFinger`. Silence with no explanation reads as a bug, and at `k=2` half the hand is idle.
    - **The per-band register marker is load-bearing when `octaves>1`**, not decoration: four identical blocks otherwise give no way to know which octave you are aiming at. Derive it from `rectNoteAt` so it cannot disagree with the sound.
    - **`drawRole` must branch on `rectGrid()` for `ld`/`bs`/`ch` alike, NOT inside the `chTyped` branch.** `gestures`' `rectPlay` keys on the role, so a non-typed chord scale in rectangles would take input by rectangle and draw narrow rows — the finger grabbing a root it cannot see (#9). This was invisible only because every rect scale used to be `typedChords` or `noChords`. For the same reason, everything the palette guards (`gx0`, the `'oct'` band's `octRight`, the hint's `hx0`) is gated on **`typedChords()`**, never on `role==='ch'`.
    - **`draw.noteLbl` is the single label function for both layouts** (grid legend, theremin overlay, play tag, pre-pinch hint). Two functions could only agree while rectangles were confined to scales that all wanted ordinals; split again and the same note reads `C` in rows and `2` in rectangles. Its `edo ∉ {12,24}` clause is load-bearing for 19/31-TET.
    - **The register band exists iff `hasReg` (`octaves < REG_N`)** — one predicate, read by the `'oct'` capture, the draw offset and `thereminSpan`. Miss it in the capture and the bottom *note* rectangle of a 4-octave scale is swallowed as a register band and plays nothing.
    Also: the layout **never enters an event** — it is not frozen on `sc`, and a layer recorded in one layout replays identically in the other (#7/#11 discipline). Use `rectNotes()` (not `IVX().length`) wherever "the notes on the grid" is meant.
27. **A track's identity is its lane id, never its layer number, and `laneNew` is the only writer of `laneId`.** Layer numbers are reused (a new track takes `maxLayer()+1`, which after undo or delete is a number that already lived) and have holes (`clearJam` removes by flag). Everything a person attaches to a track — mute, solo, the arm, a pending delete, and anything later (names, colours, freeze) — must be keyed on the id. `laneNew` always issues a FRESH id and overwrites the number's old one, so correctness comes from the BIRTH of a track, not from cleanup after a dead one (`lanePrune` is hygiene): a skipped cleanup then leaks nothing onto the next track with that number. Keying on the number instead would make a new track silently inherit a dead one's mute — plausible, quiet, and slow to find. The layer number stays what it is: the address of the track's SOUND in the owner keys. Never write the lane id into an event.
28. **The scheduler cursors have ONE rebase point, `schedInvalidate`, and it assumes the array is sorted.** Every path that adds, removes or reorders events, or jumps the time base, calls it — never a scattered `curSched.i=0`. A forgotten call gives missed or doubled notes, not an error, and not immediately. It declares `events[0..length)` the sorted prefix, so a call made while a take is being recorded (whose events are appended unsorted) must sort first. Removal uses `compactEvents` — one in-place pass that keeps the `events` reference `draw` imports; never `splice` in a loop (quadratic on a long song) and never `events = …` (draw would keep the dead array).
29. **Every value that shapes the sound has ONE owner at a time, and is recorded BY DECLARATION.** Three clauses, one law — all three fail SILENTLY, which is why they are here and not in a comment:
    - **CAPTURE WALKS THE DECLARATIONS.** `fxCaptureWalk`/`fxCaptureChain` iterate the chain and then `inst.params`, the descriptors built from `FX_FACTORY`'s `params` spec. Declare a parameter and it is captured, replayed, drawn in the automation lane, labelled and given a default — **the day the effect is written, with nothing to remember**. ⛔ Never add a bespoke capture path for one effect, and never let a value that changes the sound live OUTSIDE the parameter model: it will simply not be recorded, nobody will notice, and a freeze will one day sound wrong for no visible reason. A value that genuinely has no descriptor must be declared as explicitly as the two that already are — the old scalars (one parameter, `FX_AMT`) and the expression hand (`EXPR_CH`). ⚠️ **"Captured" does not always mean "read":** for a PER-NOTE parameter (`fxIsPerNote` — glide, brightness, volume, the old solo scalars) the capture's lane points are still WRITTEN (declared means captured; they are the only record of hand movement BETWEEN notes), but nothing that sounds reads them — `fxLaneMerge` skips them, and the editor's lane shows and edits the NOTES' own values (`pnView`). Only network parameters, compositions and the expression channels are played back from the capture.
    - **THE SOUNDING VALUE HAS ONE OWNER AT A TIME:** the HAND while the transport is stopped, the RECORDING while it plays (`fxPlayDrive` is called from `tick` only when `!recording`). ⛔ Never make both live at once: capture and drive hang off the same heartbeat, so the capture would read back what playback just wrote and record its own output in a loop. There is deliberately no third state ("touched it, so I took it over") — editing recorded automation is the EDITOR's job, not a stray touch's. ⛳ **For PER-NOTE values (V4b) the question never arises:** a recorded note owns its own value inside its event and playback never drives the live instance for them (`fxLaneMerge` skips them), so the hand owns the live value ALL the time, before and during ▶, and each recorded note owns its own.
    - **THE AIM HAS EXACTLY ONE WRITER — THE HAND**, through the single door `gestures.fxParamsOf` (`FX_AIM`, `fxAimSet`/`fxAimGet`). The bars draw the AIM, not the sounding value, so the player can aim a new sound while the loop plays; a parameter the recording governs is MARKED (`fxIsDriven`), not silently hijacked. ⛔ Letting playback write the aim would make the bars lie about the only thing they exist to show — and it reads as a natural "fix", because it is exactly what the code did before O-3.1.
30. **A note's volume is never unset** (VOL-3). Every pitched or drum event carries `a.vol`, and nothing may remove it: an event without a volume gives the engine `undefined` — a NaN gain or accidental silence. The volume parameter declares its field `note:{key:'vol', required:true}`, and three guards in `recorder.js`, where the lane's per-note edits live, hold the law: `pnPlan` (the single producer of per-note edits since smooth automation; `pnMoves` before it) takes a required field's value left of the first point FROM that point and refuses an empty point list; `pnWith` never deletes one; and the lane's operations substitute a real value — deleting the FIRST point hands the lead to the NEXT point's value, the only point cannot be deleted, and moving the first point LATER is refused (the value to its left is its own, so the move would change nothing). The ramp events the editor generates copy `a.vol` from the note, so they carry one too. Volume cannot be removed from a track or reordered (`fxPerm`). ⚠️ This forbids the ABSENCE of a value, not silence: volume 0 is a legal value. Any new event writer (the planned latch follower VOL-6, pasting, generation) must write `a.vol`.

## How to verify a change

No tests. Verification is **manual, in the browser** — do not run the app, a server, headless Chrome, tests or git; that is the user's job. The only node allowed is the STATIC check (`node tools/check-static.mjs`, `node --check` on changed files — see "Standing working rules"). For the tuning model's probes the user runs `await P.seed({replace:true})` then `P.all()` in the console.
