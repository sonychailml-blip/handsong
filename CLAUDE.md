# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Air Synth 3 is a gesture-controlled synthesizer and interactive scales/tunings tutorial that runs entirely in the browser. It uses the webcam + MediaPipe hand tracking to play notes/chords/bass/drums/effects with pinch gestures, synthesizing all sound with the Web Audio API. On top of live play it has a **beat-clock looper** (record intent, overdub layers, undo per layer) and an **arrangement** system (harmony/rhythm/bass dropped in as frozen layers). The UI text and code comments are in **Russian** — keep new user-facing strings and comments in Russian to match.

**The app is split into ES modules under `src/`, loaded via `<script type="module" src="src/main.js">`.** There is no build system, no package.json, no dependencies to install, and no tests — the modules load directly in the browser. `index.html` holds only markup; `style.css` holds all CSS; the only external dependency is `@mediapipe/tasks-vision`, loaded from a CDN via an ES module `import` in `vision.js`.

**One control model (PC mode is gone).** The screen is a single vertical layout: **one role fills the whole screen** (`phoneInstr`, cycled by the role button). In **landscape** an optional **split** (`splitOn`) puts **two roles side by side** — the screen halves, each half is one instrument. **Role is decided by ZONE** (which half a hand pinches in — either hand plays whichever half it lands in), and **work inside a half is by POSITION** (the chord palette is position-only), with **one hand-keyed exception**: effects stay bound to the left hand, and only inside the solo half. There is no more `uiMode`, no `pc`/`phone` toggle, no `drawPC` — the old three-column PC layout and everything unique to it were deleted; the split covers PC's one real capability (two roles at once) and does strictly more.

## Running / developing

- Phone testing: `npx cloudflared tunnel --url http://localhost:5500` (fresh short-lived HTTPS URL; bust cache with `?v=N`).

## Architecture

The render loop lives in `main.js`. Each frame: draw the video → MediaPipe detects hands → `processHands()` updates the gesture state machine and drives audio → `drawOverlays()` renders. The recorder thins the ~60/sec engine calls into a few intent events per note.

### Screen model — one layout, optional split
- **Single role (default):** one role fills the screen (`phoneInstr` = `'ld'/'ch'/'bs'/'dr'`, cycled by the role button `instrBtn`). Role is bound to a hand: `handRole()` maps Right→notes, Left→fx (swapped by `swapHands`). The non-note hand only acts where a job exists — effects in solo, the chord-type palette in a typed-chord chord role.
- **Split (`splitOn`, landscape only):** the screen halves — **left half = `SPLIT_ROLES[0]`, right half = `SPLIT_ROLES[1]`** (each cycled by its own button, `instrBtnL`/`instrBtnR`). **ZONE = INSTRUMENT:** either hand plays whichever half it pinched in. Inside a half everything is by **POSITION** — the chord palette lost its hand-gate and is position-only (thumb+index left of the half's `palSplitX`) — with **one exception**: effects stay keyed to the **left hand** and only inside the **solo** half. Each half has its **own** octave/register rectangle writing ITS role's register (`setRectOctReg(S.role,…)`).
- **Frozen at capture:** at pinch the hand's role + X-range are frozen onto `S` (`S.role`/`S.rx0`/`S.rx1`) from the half `px` lands in; play and draw then read that frozen range, so hit-test and render never drift. **Single-source geometry:** halves from `phoneHalves(W)`, the internal palette split from `palSplitX(rx0,rx1)`, bands from `rectBandY`/`rectRows` — each computed **once** and shared by gestures and draw.
- **Skip-in-cycle invariant:** `cycleHalf` never sets a half to the role the other half holds, so the pair is **always two different roles** → duplicate halves are impossible and the mono-voice chains (**solo and bass are single-voice**) can never appear twice. Two solo (or two bass) halves would fight over one voice; the invariant makes that unreachable by construction.
- **Landscape gate:** `canSplit()=innerWidth>innerHeight`. `splitBtn` shows only in landscape; rotating to portrait with split on **auto-disables** it (`softAllOff`, nothing left ringing) and does not auto-re-enable.

### Gesture model
- **Pinch** = thumb (4) near a fingertip (8/12/16/20), normalized by hand size. The pinched finger (`S.oct`) selects the **octave register** (index=I … pinky=IV), switchable mid-pinch to glide — **except in the rect model** (below), where it selects the note-in-rectangle and the octave comes from the octave rectangle.
- **Y** = scale degree (`degHyst`); **X** = volume, mapped over the hand's frozen range — `[palSplitX(rx0,rx1), rx1]` in a typed-chord role, else `[rx0, rx1]`; **Z** = reverb send, solo only.

### Rect model — "4 notes per rectangle" (shipped: SOLO, BASS, CHORDS)
For scales with a **`rectGrid`** property (today: 19-TET, 31-TET, Partch, **Carlos gamma**), the phone note grid is not N narrow rows but **fat rectangles**: `rectRows()` note rectangles + **1 octave/register rectangle** at the bottom = `rectRowsFull()=rectRows()+1` bands. Band pixel geometry is single-sourced in `rectBandY` (config) and the count in `rectRows`/`rectRowsFull` (scales); gestures' hit-test (`degHyst` on `rectRowsFull()`) and draw partition H the same way, so finger and screen never drift. **Y selects the rectangle** (band); the pinched **finger I–IV = 1 of 4 notes/roots** inside it (`deg = (band−1)*4 + finger`, clamped). **`rectRows()` is now period-gated: `(iv.length + (periodOf===2?1:0))/4`** — an octave scale appends a top-tonic (`+1`) to close the period in the grid, but a **non-octave scale has no equivalence interval**, so its "note a period up" arrives via the register rectangle, not an extra row. So `rectGrid` is legal iff **`(iv.length + (periodOf===2?1:0)) % 4 === 0`** (19→20, 31→32, Partch→44, **gamma 20→20**; but not BP 13, alpha 9, beta 11).
- **Octave/register rectangle** (band 0, bottom): pinching it — by **position**, so ANY hand captures it (`'oct'` zone, overrides role; in chords it's SPLIT-gated to the right half so the palette hand isn't captured) — sets a **per-role sticky register** via `setRectOctReg()`: solo→`octReg`, bass→`bassOctReg`, chords→`chordOctReg`. This solved the old "finger-busy-so-octave-is-lost" blocker; the register survives the hand leaving the band/frame. The `'oct'` hand is silent (no note, no owner). The register shifts by the scale's **period** (via `leadFreq`'s `P^oct`) — an octave for octave scales, a **perfect fifth** for gamma; the band label reads `ОКТАВА` for `period===2`, else `regWord().toUpperCase()`.
- **Chords**: rect applies to the ROOT rows only, in the right part `[palSplitX,rx1]` of the role's range; the left palette is unchanged; the type still rides the sticky palette; the latch logic (same-off/re-attack/glide) is unchanged — only the root degree + octave source changed.
- Non-`rectGrid` scales keep the narrow-row model byte-for-byte.

### Theremin — continuous pitch (shipped: SOLO only)
A `theremin` toggle (the `〰` button next to the role, solo-only) makes solo pitch a **continuous function of y** (bends/vibrato) instead of quantizing to a step. `thereminSpan`/`thereminHz` (scales) map y→a fractional note position over the **same** partition draw uses, then interpolate **linear-in-cents** (`log2` of the two neighbours' `leadFreq`) — correct for unequal Partch/gamelan spacing. Each rectangle shows 4 fine note-lines (`drawThereminGrid`). It is **live-only**: the continuous Hz rides a **live-only 3rd arg of `ENG.leadOn`** (never recorded), while the looper still stores the nearest step (`S.deg`, event format unchanged) — glide-into-loop is a later task. The octave rectangle still sets the register.

### Typed chords — the palette
Scales with a `typedChords` property split the chord role: **left = a palette of chord types** (columns = families, rows = variants; counts from `chordFams()`/`types.length`, geometry in `palColX`/`palRowY`), **right = note rows**. The palette selects a cell by POSITION on a thumb+**index** pinch inside it (`S.oct===0 && S.x<palSplitX`); sticky, default first family/type. **Single-role:** the left (fx) hand is the palette hand; the right hand plays. **Split:** the palette is **position-only** — either hand picks a type by being left of the half's split with thumb+index; the other hand plays roots. Play: Y=root, X=volume, and the octave — **on non-rect typed scales (chrom12, BP, Pythagorean, both Naturals, meantone)** the finger picks it, **on the rect typed scales (19-TET/31-TET/Partch)** the finger picks the root-in-rectangle and the octave comes from the octave rectangle (`chordOctReg`). `ty` is a live reference into `CHORD_FAM_SETS`; latch identity = (degree + type). Two-axis hysteresis `cellHyst`.

`typedChords` keys → sets in `CHORD_FAM_SETS` (**8 keys**):
- `'chrom12'`, `'edo19'`, `'edo31'` — **integer steps** in that scale's own edo (priced by the integer `chordSteps` fallback).
- `'partch'` — 11-limit **ratios** (4 columns × 6: О otonal / У utonal / Диез 7-11 / Станд.); priced by the pure-ratio cents branch.
- `'bp'` — Bohlen–Pierce 3.5.7-subgroup **ratios** (15 chords: 3:5:7 major / 5:7:9 minor / characteristic); priced by the **period branch**.
- `'pyth'`, `'nat'` — the same 24-type vocabulary as chrom12 but as **pure ratios** (Pythagorean 3-limit / Natural 5-limit); priced by the pure-ratio cents branch (root × ratio, so every chord is pure from its own root).
- `'natfix'` — the same 24 types as **integer semitone offsets**, but used by the **fixed-grid** scales (Natural-fixed, meantone) whose `gridChords:true` reads each note out of the frozen cents grid → some chords pure, others wolf.

### Behaviour properties (prefer these over `tag`/index checks)
- `noChords` → chord role builds nothing (`supportsChords()` false). Maqams; the **gamelan** cents-scales and **pelog patets** (monophonic by choice); the **Carlos** scales (stage 1). Partch/Pythagorean/Natural are **not** `noChords` — they have typed chords.
- `typedChords: '<key>'` → palette mode; keys a set in `CHORD_FAM_SETS`. Keys: `'chrom12'`, `'edo19'`, `'edo31'`, `'partch'`, `'bp'`, `'pyth'`, `'nat'`, `'natfix'`.
- `cents: [...]` → non-equal tuning; pitch from `2^(cents[i]/1200)` instead of the equal step (see "Music theory & pitch").
- `period: <n>` → **interval of equivalence ≠ octave** (BP `3` = tritave, Carlos `3/2` = fifth). `periodOf()=s.period||2`. Absent ⇒ `2` ⇒ every octave scale byte-for-byte. Drives register/step (`P^oct`, `P^(step/edo)`), the `centsOf` period (`pc=1200*log2(P)`), `regWord`, `gridNoteLbl`, and the `rectRows` `+1` gate. **Never hardcode `2` on any pitch/label path** — use `periodOf`.
- `gridChords: true` → (cents scale only) typed chords read their notes **out of the fixed cents grid** by integer semitone offset (fixed-keyboard model), instead of pure ratios from the root. Selects the first `chordFreqs` branch. Today: Natural-fixed, meantone.
- `rectGrid: true` → the "4 notes per rectangle" layout for solo/bass/chords. Legal iff **`(iv.length + (periodOf===2?1:0)) % 4 === 0`** (19→20, 31→32, Partch 44, gamma 20). Drives `rectRows`/`rectRowsFull`.
- `supportsProgressions()` = 7 degrees. Note: a 7-note `noChords` scale (maqams, pelog) is still gated out of progressions because `refreshProgAvail` uses `supportsProgressions() && supportsChords()`. (Partch/12-note tunings/BP/Carlos aren't 7-note, so progressions stay gated regardless.)

### Music theory & pitch
`SCALES` is the source of truth: each has `edo`, `iv` (degrees in those steps), `tag`, `trad` (tradition, for the menu), optional `grp` (submenu), optional behaviour properties. **61 scales (indices 0..60).** Traditions (`TRADITIONS`, 6): Ладовая (`modal`), Арабская (`arab`, 24-TET maqamat), Микротональная (`micro`, 19/31-TET), Хроматика (`chrom`), Мировые строи (`world`, non-equal cents tunings: gamelan Слендро/Пелог + pelog patets + Partch), **Неоктавные (`nonoct`, period≠2: Bohlen–Pirce + Carlos α/β/γ)**. New menu shelf `grp:'Исторические темперации'` inside `modal` collects the historical 12-note tunings (Pythagorean, both Naturals, meantone).

**Tail index map (appended since the last docs pass):** 50 = Bohlen–Pierce · 51/52/53 = Carlos alpha/beta/gamma · 54/55/56 = Pelog patets Lima/Nem/Barang · 57 = Pythagorean · 58 = Natural (mobile/choir) · 59 = Natural (fixed/harpsichord) · 60 = quarter-comma meantone.

**Three ways to define pitch — equal steps, cents overlay, or non-octave period:**
- **Equal (default):** within-period ratio = `P^(iv[i]/edo)` where `P=periodOf(s)` (`2` unless `period` set). All EDO scales (12/19/24/31-TET) and the non-octave equal scales (BP `P=3`, Carlos `P=3/2`).
- **Cents overlay:** an optional `cents:[...]` array (`length === iv.length`) gives each degree's exact cents above the tonic — for **non-equal** tunings (gamelan, Partch, the historical temperaments). When present, `leadFreq`/`bassFreq`/`centsOf` use `2^(cents[i]/1200)` with the appended top = 1200¢. `edo`/`iv` stay as **nominal structure** (degree count, row layout, hysteresis). Cents scales are octave (`period` absent).
- **Non-octave period:** `period:<n>` replaces the hardcoded `2` in register (`P^oct`), equal step (`P^(step/edo)`), and the cents period (`pc=1200*log2(P)`). Register shifts by the period (BP tritave, Carlos fifth), not the octave. `period` and `cents` are mutually exclusive in practice (BP/Carlos are equal; the temperaments are cents+octave).

**Chord pricing — `chordFreqs` has four branches, checked in this exact gate order** (order decides which scale gets which — do not reorder):
1. **`s.cents && ty && s.gridChords`** → **fixed-grid**: `ty` is integer semitone offsets; each note = grid pitch `корень+off` read from `s.cents` (octave carry for off≥12). Natural-fixed, meantone. Produces the pure/wolf spread of a fixed keyboard.
2. **`s.cents && ty`** → **pure-ratio cents**: `ty` is ratios; note = `baseF()/2·2^(o)·2^(rootCents/1200)·ratio` — root from the cents overlay, each interval a pure ratio. Partch, Pythagorean, Natural-mobile. Every chord pure from its own root.
3. **`periodOf(s)!==2 && ty`** → **period-equal**: `ty` is ratios; root by `P^(iv/edo)` (period register `P^o`), note = root·ratio. Bohlen–Pierce.
4. **fallback** → `chordSteps()`: integer path. Typed `ty` adds its step array to the root; else 7-note diatonic/ethnic/maqam stack thirds, pentatonic/blues/chromatic power chords, pure-EDO (`tag:'edo'`) by interval ratios. chrom12/edo19/edo31 and every non-typed scale. **Byte-for-byte unchanged** — a scale reaches here only when the three gates above all fail.
- `CHORD_FAM_SETS` `iv` are **integer steps** for `chrom12`/`edo19`/`edo31`/`natfix`, and **plain-number ratios** for `partch`/`bp`/`pyth`/`nat`. Never give a step-set to a scale with a different `edo`, and never give a ratio-set to a non-cents/non-period scale.

### Audio engine (`initAudio`) — five chains into one master
`master → limiter → destination`. Shared `ConvolverNode` reverb (only the solo send is Z-controlled). Chains: (1) solo — banks → drive → envelope → volume → tremolo → delay/reverb; (2) chord pool (`CHORD_POOL_N` always-on 2-osc voices, gain-gated); (3) bass pool (`BASS_POOL_N` mono, timbre baked on attack); (4) drums (synth per hit, kit from `a.kit`); (5) drone (detuned saw pair, LFO-swept LP, follows the tonic). Plus the metronome.

### Looper & polymodality
An event is `{t, layer, fn, a, sc, sev}`: `t` in beats, pitch as degree+octave, frozen scale `sc`, `sev`, plus `a.ty`/`a.inst`/`a.kit`. Frequency is derived at play time via `leadFreq/chordFreqs/bassFreq(..., frozenSc)`, so the loop re-tunes to the live tonic while each layer keeps its frozen scale (**and its `cents` tuning**, for free). Replay via `ENG` isn't re-recorded. This is polymodality — don't "simplify" replay to the current scale.

## Conventions

- Terse, comment-heavy, single-letter helpers, compact lines. Match it.
- Add a feature in the module that owns it:
  - a **scale** = one entry in `SCALES`, **appended at the end** (index is `scaleIdx`; `state` and `sameDegrees` depend on it). Menu position is set by `trad`/`grp`, not array position — `fillScales` buckets by `grp` key.
  - a **cents (non-equal) scale** = same, plus a `cents:[...]` array (`length === iv.length`); keep a valid `edo`/`iv` as nominal structure. Home tradition: `world` (or `modal`/`Исторические темперации` for the historical 12-note tunings). It may be `noChords` (gamelan/pelog) OR carry `typedChords` with a **ratio** family set (Partch/Pythagorean/Natural — priced by the pure-ratio cents branch) OR `gridChords:true` + an integer-step set (Natural-fixed/meantone — priced by the fixed-grid branch).
  - a **non-octave scale** = a `period:<n>` (`3` tritave, `3/2` fifth…), `edo`/`iv` equal within that period, tradition `nonoct`. `periodOf` carries it through pitch/labels/register — never add a `2` literal. `noChords`, or a **ratio** family set priced by the period branch (BP `'bp'`). `rectGrid` only if `(iv.length)%4===0` (period≠2 drops the `+1`).
  - a **typed-chord family set** = one entry in `CHORD_FAM_SETS` keyed by a scale's `typedChords` value; **integer steps** for an edo/`gridChords` scale, **or plain-number ratios** for a cents/period ratio scale.
  - a **timbre/kit** = an entry in `LEAD_INSTR`/`CHORD_INSTR`/`BASS_INSTR`/`DRUM_KITS`.
  - a **gesture/timing threshold** or palette geometry = `config.js`.
  - a **behaviour gate** = a scale property + a predicate in `scales.js`, never a `tag`/index check.

## Hard rules — do not break these

1. **AudioContext is created only inside the `#startBtn` click handler.**
2. **Never hardcode frequencies, note tables, or the octave `2`.** Pitch derives from `baseF()` and the current (or frozen) scale — `P^(iv/edo)` with `P=periodOf(s)`, or the `cents` overlay `2^(cents/1200)`. A literal `2` in a register/step/period path breaks the non-octave tunings (BP, Carlos) — use `periodOf`.
3. **Pool oscillators start once and never stop** (chord/bass gated by GainNodes; per-hit drums/metronome/drone LFO are the exception).
4. **The master limiter stays.**
5. **Lower layers never touch the DOM** — `audio.js`, `arrange.js`, `recorder.js` reach the UI only via `hooks`. `draw.js` is exempt.
6. **Live bindings — write state only through its setter**, never a module-level `const`. The looper re-reads `baseF()`/`CUR()`/`chordSteps()` every step.
7. **Per-event scale freeze is the polymodality mechanism** (`sc`/`sev`/`a.ty`, and `cents` rides on the frozen `sc` — including for **chords**: a frozen Partch chord layer replays in just intonation via the `chordFreqs` cents branch on `ev.sc`).
8. **The video draw and `detectForVideo` read the same camera frame** (`drawVideoBackground()` before detect, `drawOverlays()` after, one synchronous tick).
9. **There is ONE layout; never reintroduce a mode gate.** PC/`uiMode` are deleted. New behaviour keys off scale properties and `splitOn`, never a `uiMode`-style global branch. **Hit-test and render must derive geometry from the SAME frozen range** — the hand's `S.role`/`S.rx0`/`S.rx1` (frozen at capture) and the single-source helpers (`phoneHalves` for halves, `palSplitX` for the internal split, `rectBandY`/`rectRows` for bands). Two independent copies of a boundary will drift and the finger takes a different cell than it sees.
10. **The split's role pair stays two distinct roles, at most one mono role.** `SPLIT_ROLES` is mutated only via `cycleHalf`, which skips the other half's role — keeping solo+solo and bass+bass (the single-voice chains) unreachable. Don't add a path that sets both halves to the same role.
11. **Continuous-pitch overrides ride a live-only channel and are NEVER recorded.** The theremin Hz is a 3rd arg of `ENG.leadOn` passed only by the live `WleadOn`; replay derives pitch from the frozen `deg/oct`. Do not fold live Hz into the event payload.

## How to verify a change

No tests. Verification is **manual, in the browser** — do not run node, a server, headless Chrome, or any automated test/git command; that is the user's job.

1. Serve, "▶ Запустить", allow camera. The app **starts in single-role phone** (SOLO full-width, one role button, no mode button anywhere).
2. Solo/chords/bass/drums roles play; looper records/overdubs/undoes; arrangement drops in.
3. Typed chords (Хроматика, 31-TET, 19-TET): left index pinch selects a palette cell; right hand plays; 19-TET pure minor beats less than 12-TET minor; 31-TET `дом7` = 4:5:6:7.
4. Cents scales (Мировые строи → Слендро/Пелог): sound UNEVEN (gamelan), octave a clean 2:1, play-tag cents read the real values; gamelan chords show the no-chords hint.
5. Menu: each tradition's `grp` subgroups render once, in order (Ладовая has Диатоника/Лады(моды)/Этнические/Пентатоника-блюз/Симметричные/Экзотические/Мировые пентатоники/Японские; Арабская has one Макамы group). Мировые строи lists Слендро/Пелог/Партч.
6. **Split (landscape, `◨`):** the button appears only in landscape; enabling it halves the screen (left/right roles from `SPLIT_ROLES`) with a mid divider. Either hand plays whichever half it pinches; a chord latched in one half keeps ringing while the other half plays solo (two roles sounding at once). Each half sets its **own** register in its own octave band. The two role buttons each cycle соло/аккорды/бас/ударные **skipping the other half's role** (never two-the-same, never two solo / two bass). A **bass** or **drums** half renders and plays inside its half only (drum rows span the half, not the screen). With no solo half the FX bars vanish and `〰` hides. Rotating to **portrait** auto-disables split (nothing left ringing) and hides `◨`.
7. Rect model (19-TET/31-TET/Partch, solo/bass/chords): fat rectangles + a bottom «ОКТАВА» band; Y picks the rectangle, finger I–IV picks 1 of 4 notes/roots; pinching the octave band sets a **per-role** sticky register (solo/bass/chords don't share it). Chords: left palette unchanged, rect roots in the right part.
8. Partch (Мировые строи): 11-limit JI; solo/bass glide as 11 rectangles; chord role shows the О/У/Диез/Станд. palette; an О7 is a beat-free 4:5:6:7; a recorded Partch chord layer replays in JI.
9. Theremin (`〰`, solo only): appears next to Соло (single-role) or when a split half is solo; ON glides pitch continuously across the fine note-lines; the looper still records the nearest step; OFF and other roles unchanged.
10. Non-octave (Неоктавные): Bohlen–Pierce solo/bass play in a tritave (register a `3:1` apart), labels read `Т,2,3…` and the register word is `тритава`; BP chords show the 3:5:7/5:7:9/characteristic palette (a 3:5:7 is beat-free). Carlos α/β/γ divide the fifth (register a `3:2` apart, register word `рег.`); **gamma is rect** (5 fat rectangles + register band), alpha/beta are the narrow grid; all three are `noChords`.
11. Historical temperaments (Ладовая → Исторические темперации): Pythagorean chords have a sharp third (81/64); Natural-mobile chords are pure from every root; Natural-fixed and meantone read chords from the fixed grid → some pure, some wolf (meantone concentrates the wolf into one fifth). A/B the same chord across the shelf to hear the trade-off. Cents scales show ordinal `Т,2,3…` row labels, not note names.

Never report a change as done without stating which steps you could not verify.
